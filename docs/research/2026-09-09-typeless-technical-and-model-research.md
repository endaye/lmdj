# Typeless 技术架构与模型研究

> 研究日期：2026-09-09。对象：`www.typeless.com` 的商业语音输入应用。
> 文档性质：公开资料研究与工程推断；不是产品立项、模型选型或接入承诺。
> 未安装客户端、抓包、逆向或运行对照实验；没有实测准确率、延迟、成本和离线结论。
> 检索最新 `origin/main` 的 `docs/` 未发现 Typeless 专题；已有 Needle 类文本指令模型研究，见第 7 节。

## 1. 核心判断

Typeless 值得研究的重点是把语音变成可直接使用的文字，并送回当前工作位置的完整交互链，而不是一个已经公开、可以照搬的模型。

公开资料能确认：云端转写；使用第三方 LLM，官方举例 OpenAI；桌面端通过系统权限录音和插入文字。**具体 ASR 模型、LLM 型号、参数量、权重、微调和路由策略均未在本次查阅的官方资料中披露。** 因此不能写成“Whisper + GPT-4o”，也不能认定它完全自研或在端侧推理。[数据控制](https://www.typeless.com/data-controls)、[权限说明](https://www.typeless.com/help/faqs)

本文用三种证据标签：**官方声明**只代表厂商公开描述；**工程推断**是可解释功能的设计假设；**未知**表示现有证据不足。官方营销效果不等于独立测量结果。

## 2. 产品能力与技术问题

| 官方公开能力 | 对工程的启示（推断，不是实现披露） |
| --- | --- |
| 去口头语、去重复、理解说话途中改口、组织列表 | 输出目标是意图保持的编辑稿；只优化逐字转写不足以描述质量 |
| 个性化风格、个人词典 | 可由词汇偏置、配置或提示词实现，不能据此推断逐用户训练 |
| 多语言与混合语言输入 | 应分别验证语言切换、专名和领域词，而非只看单语平均准确率 |
| 翻译 | 转写错误可能继续传到翻译，输出流畅也可能掩盖原意错误 |

这些能力来自[官方首页](https://www.typeless.com/)，均未在本研究中实测。

另一个入口 Ask anything 支持选中文字后语音改写、解释、摘要与搜索，结果进入文本区域或弹出面板；官方明确要求网络连接。它提示产品不只包含听写，还需要区分“输入内容”和“操作内容”的模式。[Ask anything](https://www.typeless.com/ask-anything)

## 3. 可确认边界与推测处理链

### 3.1 已确认的系统边界

- **客户端权限：** 官方 macOS 安装说明要求麦克风和 Accessibility；后者用于将结果插入当前文本输入框。这不能证明 Windows、iOS、Android 采用相同底层接口。[安装说明](https://www.typeless.com/help/installation-and-setup)
- **云端计算：** 音频及有限上下文参与云端处理，上下文包括应用信息和其中相关文字。[数据控制](https://www.typeless.com/data-controls)
- **结果落点：** 选中文字的编辑和开放问答有不同呈现位置；跨应用交互属于客户端的重要职责。[Ask anything](https://www.typeless.com/ask-anything)

### 3.2 参考分解，不是 Typeless 内部架构图

```text
用户触发录音 + 当前输入位置
  → 音频采集 / 结束判断                         [具体实现未知]
  → 云端语音识别与语言理解                     [云处理确认；模型未知]
  → 结合词典、上下文进行编辑 / 翻译 / 指令理解  [逻辑分工推断]
  → 返回文字或问答结果
  → 客户端核对目标位置并呈现或插入              [核对机制未知]
```

可用两种架构解释这些功能：

| 假设 | 优势 | 代价与可验证问题 |
| --- | --- | --- |
| ASR → 文本 LLM → 输出策略 | 可分别测转写和改写、替换供应商、保留中间结果 | 多阶段延迟和误差传递；要检查改写是否删除否定或数字 |
| 音频语言模型直接生成成稿，辅以工具或规则 | 可能减少阶段切换，并利用语音信息 | 转写与改写更难归因；需验证忠实性和失败时的可恢复性 |

还有混合路由的可能。公开资料不能确定是哪一种，更不能把逻辑处理步骤当成独立微服务。

**未确认的技术栈：** Swift、Electron、Tauri、Flutter、React Native 等客户端框架；音频编码与采样率；VAD；WebSocket/HTTP；流式还是分段识别；云服务商、GPU、批处理和缓存方式。跨平台发行不能反推出共享 UI 框架，实时宣传不能证明流式协议。

### 3.3 比模型名称更容易决定体验的工程问题

以下为本研究的设计分析：

1. **结束判断：** 停顿不等于说完，提前结束会截断后半句，等待过久又破坏输入节奏。
2. **改口解析：** “设成一百二十，不，一百二十八”要保留最终值；创作口述中的重复可能本来就应保留。
3. **目标稳定性：** 网络请求期间用户切换窗口、移动光标，旧结果不能插入新位置；应绑定输入会话和目标身份，失效时提供可恢复的结果。
4. **取消与重试：** 取消后到达的迟到结果不能继续写入；重试不能重复插入。
5. **上下文边界：** 只读取任务必要文本；选中文本中的指令应作为内容处理，不能自动升级为系统操作权限。

这些是复现同类体验需要验证的缺陷类别，不表示已经观察到 Typeless 存在这些问题。

## 5. 数据流与隐私的技术含义

官方将零留存与云端处理同时描述，并表示第三方 AI 提供商有零留存约定。[数据控制](https://www.typeless.com/data-controls) 本文没有审计其服务端、合同或日志，因此这是厂商承诺。

[隐私政策](https://www.typeless.com/privacy)（页面标注更新于 2026-08-25）说明：普通音频和上下文在处理后丢弃；开启 History cloud sync 后会保存历史文本用于同步，关闭会删除云端历史；主动反馈和明确同意分享的纠错有额外处理条款。账户和计费信息也有自己的保存规则。

技术上需要分清三个维度：**数据在哪里计算、保存多久、是否用于训练**。本地历史不能推出离线可用，零留存不能推出没有数据离开设备，不用于训练也不能推出没有推理处理。开启同步后的历史文本和原始音频也不是同一种数据。

本次打开[子处理者页面](https://www.typeless.com/subprocessors)失败，未取得可核实清单；不猜测完整供应商、地域或基础设施。若后续评估接入，仍需核查同步默认值、反馈范围和各功能的数据路径。

## 6. 如何评估同类技术，而不是凭成稿“很聪明”选模型

以下是后续实验建议，**没有执行，也没有形成模型选型决定**。

先用有授权的自有录音与人工标注，建立覆盖中英混说、音乐术语、数字、否定、途中改口、长停顿、背景音乐和无语音输入的数据集。标注同时保留逐字稿与最终意图，避免把正确去口头语算作 ASR 错误。

| 层次 | 建议测量 | 要回答的问题 |
| --- | --- | --- |
| 识别 | 中文 CER、英文 WER、专名/数字召回 | 听错发生在哪里？拿不到中间转写时不能声称测到了纯 ASR |
| 编辑 | 数字/否定/实体保持率、改口成功率、无依据新增率 | 是否只是更流畅，却改变原意？ |
| 交互 | 停止说话至完整可用结果的 p50/p95，输入目标正确率 | 时间是否包含上传、推理和插入？ |
| 可靠性 | 断网、取消、超时重试、焦点变化、迟到结果 | 是否丢失文字、重复或写错位置？ |
| 资源 | 每音频分钟成本、内存、功耗、上下行字节 | 每种设备和网络条件是否可承受？ |

对照应至少包含“只转写”“转写 + 保守规则”“转写 + 文本模型”，必要时再加入音频语言模型。固定相同音频、提示词、输出要求和硬件，并记录精确模型版本；本地模型还记录权重哈希、量化和运行时。按照缺陷分别评价，不能用更漂亮的语句掩盖数字或否定错误。

延迟分析可以用以下分解作为测量起点：

```text
停止说话后等待 ≈ 结束判定 + 剩余上传 + 识别尾部 + 编辑 + 返回/插入
```

这是串行近似；流式或阶段重叠时应按实际关键路径计时，不能把重叠阶段简单相加。费用也需包含识别、文本推理、网络和重试，不能由订阅价格倒推出模型推理成本。

## 7. 与 LMDJ 的关系

已有[Needle 类端侧结构化指令模型研究](2026-09-01-needle-class-on-device-command-models-for-lmdj.md)聚焦文本到 IntentDraft。Typeless 研究补充的是它上游的语音与交互问题，不把旧文中的候选模型自动变成当前选型。

可供未来设计讨论的路径：

```text
语音 → 带来源的转写 → 受限 IntentDraft
     → 校验 / 预览 / 按风险确认 → Host 补齐权威字段 → Application Facade
```

依照[仓库架构约束](../../AGENTS.md)，模型输出不能直接写 Project Truth；Provider 选择属于 Workspace/Host 设置，失败留在 Attempt，模型推理不能进入实时音频执行路径。此处只是沿用边界，不新增接口。

LMDJ 比通用写作更需要**忠实性**：例如“把 Pad 3 的音量降低 3 dB，不是静音”不能被编辑器缩写成另一个操作。“改成 128”还必须由当前目标和状态消歧，不能让模型猜项目路径、对象 ID 或修订号。

值得借鉴的是快速触发、词典、显式区分听写/指令、可恢复的结果和清楚的处理状态。不能直接迁移的是自由改写后的自动执行，也不能用跨应用文字插入替代 Application Facade。背景音乐中的误唤醒和录入音乐而非人声，还需单独验证。

本研究不引入 Typeless SDK/API 依赖：本次资料不足以确定有可供 LMDJ 使用的稳定开发者接口。当前可交付的是研究依据；任何语音功能、模型实验或 Provider 实现仍需要单独确定范围。
