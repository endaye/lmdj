## Findings carried into the revision

1. MINOR is incompatible with replacement of the public pure virtual run ABI;
   corrected proposal is MAJOR, with fresh exact dependency allocation required.
2. Mandatory WAV input `schema_id/schema_version` were unspecified; no input
   profile may be silently invented by K1.
3. Source const views can retain mutable aliases; owned immutable staging,
   aggregate budgeting and handle retention accounting need explicit rules.
4. Current sink captures stack references; run-end validity alone does not make
   saved callbacks safe. Thread/lifetime semantics require C-Q4 approval.
5. Existing SDK accepts only Provider `PROVIDER_FAILED` outcomes; approved WAV
   domain errors need a deliberate boundary change and negative tests.
6. Current output publish and terminal writes are separate. Consumer validation
   must precede visibility; crash/terminal commit-marker semantics require C-Q5.
7. `platforms` and `max_output_bytes` are C++ descriptor fields outside the
   capability.v2 JSON shape. Do not force them into the closed schema.
8. Duplicate input hashes are currently rejected across ports; preserve that
   rule unless a separate change is approved. Preserve input occurrence order.
9. #471's proposed Job/Candidate changes are not part of #467 byte access;
   avoid silently combining their API/version allocations.
