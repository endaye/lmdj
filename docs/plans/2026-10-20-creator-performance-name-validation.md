## Behavior

Share the existing1–64 Unicode code-point predicate inside the Host. The field
keeps the entered text and the UI's existing trimmed Save value, reports an
invalid value accessibly, and disables only Save for a fresh invalid name.
Export/Discard remain available. A legal64 supplementary-plane name remains
intact; do not slice, normalize, or apply a UTF-16 maximum.

The controller refuses a fresh invalid name before finalization or any
mutation/inspection/bind. Keep the stopped capture/WAV owner and permit an
explicit corrected Save or Discard. Previously admitted UNKNOWN or committed
Save keeps its existing pending name, inspection, bind-retry and retirement
path even if a caller supplies a different invalid name. No error-code-based
outcome inference is introduced.

The existing UNKNOWN input remains editable although the controller already
ignores a replacement name. To keep this new field validation from blocking
the original retry, project that existing pending name as transient Host state:
show it read-only while UNKNOWN is unresolved, and let Save retry the original
identity without validating a replacement field. Set it only on actual
ambiguous admission, never on local refusal or PROJECT_BUSY; clear it when the
recording becomes idle or a new recording starts. It is not Save confirmation,
does not settle UNKNOWN, and changes no publisher/WAV lifetime or persistence.
