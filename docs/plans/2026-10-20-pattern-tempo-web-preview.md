## Public wire and typed SDK, frozen before product edits

The four B2-reserved operations remain `.set`, `.cancel`, `.commit`, `.status`
under `pattern.tempo.preview`. Add `.begin` to prepare without audio or durable
effects: callers obtain a Core-issued turn ticket before the first audio effect.
This makes a first set's unknown response reconcilable by its already-known
ticket. Retrying an old zero-ID start must never create another audible turn.
One B2 source binding can serve sequential turns, but each Web turn receives
a new nonzero monotone token scoped to this Control/RuntimeSession lifetime.
Exhaustion refuses; no wrap/reset within that lifetime. A token addresses one
turn only, including after return-to-base/cancel/commit.

All payloads are exact-key objects, no sidecar. UUIDs use existing validation;
revision uses the existing nonnegative safe-integer domain. Tokens, Core IDs,
generation, epochs, frame and tick numerators are canonical decimal strings
without Number conversion; nonzero except explicitly zero initial preview ID.

| Operation | Exact payload | SDK method |
| --- | --- | --- |
| `pattern.tempo.preview.begin` | `{project_id, pattern_id, expected_revision}` | `beginPatternTempoPreview({projectId,patternId,expectedRevision})` |
| `pattern.tempo.preview.set` | `{ticket,bpm}`; integer40..240 | `setPatternTempoPreview({ticket,bpm})` |
| `pattern.tempo.preview.cancel` | `{ticket}` | `cancelPatternTempoPreview(ticket)` |
| `pattern.tempo.preview.commit` | `{ticket,command_id}`; exact UUID retained for unknown retry | `commitPatternTempoPreview({ticket,commandId})` |
| `pattern.tempo.preview.status` | `{ticket}` | `inspectPatternTempoPreview(ticket)` |

Every ticket has exactly `{preview_token, project_id, pattern_id, source_id,
expected_revision}`. `source_id` is the original actually applied Native
publication generation retained when begin issued the ticket; it is not the
Application's internal binding ID. It stays frozen across this turn's owned
same-BPM revision adoption. Every subsequent operation compares the complete frozen
ticket before any I/O/publication, not only its token. A repeated matching
begin while ready returns that ready ticket; an unsettled turn refuses begin.
An old ticket cannot operate on a later turn, even when Truth never changed.
Set after a terminal turn refuses; begin is required for a new turn. Cancel
before the first set is terminal without an audio or storage effect.

Every response is the ordinary success envelope containing exactly:

```text
{ticket, preview_id, phase, committed_bpm, preview_bpm,
 project_revision, source_revision, publication_generation,
 command_id, committed_revision, applied, error}
```

`phase` is `ready|source_pending|preview_pending|preview_refused|previewing|cancelling|
cancelled|commit_unknown|committed_pending|committed|source_lost`.
Initial prepared turn has preview_id `"0"` and no command/receipt. It stays
zero through a Host-owned `source_pending`, its cancellation or pre-preview
refusal. Once Facade actually admits preview, the nonzero ID and status come
from the B2 owner. Command/committed revision and error are
nullable. Error uses the existing redacted error shape and an explicitly
allowlisted tempo refusal reason, never storage paths/provider text.
For a first commit error, only a fresh B2 observation proving no frozen command
may add `details.tempo_commit_refused: true`. This producer receipt lets SDK
release its attempted command identity after known refusal. Bridge timeout or
generic error codes are never that receipt; previously unknown commands retain
identity even after another error. If B2 instead retains a command/receipt,
surface its actual status and failure, preserving UNKNOWN or known persistence.

`applied` is null or exactly `{start_epoch,pattern_generation,applied_frame,
anchor:{frame,tick_numerator,bpm},playing}` from Native's observation. An
awaited publication generation and a real applied predecessor stay distinct;
no clock is predicted or rounded. SDK strictly validates all keys, target and
ticket identity, integer strings, nullable receipts/errors and actual clock
relationships, then returns immutable camelCase DTOs. It preserves issued
commit identity and observable UNKNOWN after observer errors/timeouts; no new
random command ID or automatic duplicate authoring retry. A fresh ticket
cannot silently adopt a different owner after timeout/disposal.
