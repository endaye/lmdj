# 已确认：Creator 使用本设备工程会话内的统一创作 Undo/Redo

- 日期：2026-09-30
- 解决的问题：[#1655](https://github.com/endaye/lmdj/issues/1655)。
- 状态：产品与架构语义已确认；运行时与控件由 [P0.1 #1659](https://github.com/endaye/lmdj/issues/1659) 实现，本决策不表示功能已交付。
- 依据：[Creator workflow baseline](2026-09-29-creator-user-workflow-baseline.md) 第 6、8、14 项，以及 [Creator 用户操作流程](../../design/2026-09-29-creator-user-workflow-design.md)。
- 替代范围：[Stage 8 S8-D4](../../design/2026-08-08-lmdj-stage8-sample-editor-design.md) 的“不提供通用 Undo/Redo”不再限制后续 Creator；Stage 8 当时的实现记录及其余决策保持原样。Reset Pad 作为普通 Authoring Command 纳入历史；本决策不改变它既有的确认交互。

## 1. 结论与原因

Creator 为本设备当前打开的工程会话提供统一、线性的 Undo/Redo。
一次用户创作动作对应一条历史，撤销恢复该动作之前的创作内容，重做恢复该动作之后的内容；
两者都产生新的 Project Truth revision，不回退 revision 数字。

这个边界让删除、录音提交、参数编辑和 Sequence 编辑拥有同一种“返回上一步”，
同时把会话历史与工程持久化、崩溃恢复、未来协作的版本历史分开。
用户无需因切换 Sample、Sequence 或 Perform 页面而切换历史。
这是 LMDJ 确认的首版范围，不声称 Koala 有相同的历史持久化或内部实现。

## 2. 历史作用域与生命周期

- 历史由工程身份、设备上的当前打开会话及写入所有权约束；不共享给其他设备、其他标签页或其他工程。
- 页面、选中 Pad、选中 Pattern 的变化不切换历史栈。保存、自动保存与普通页面导航保留历史。
- 关闭、刷新、重开、切换工程、工程被外部替换或写入所有权丢失时结束当前历史。第二个标签页接管后从空历史开始，原标签页不能继续撤销。
- 切走浏览器标签页、锁屏或音频中断本身不清空仍存活且持有所有权的会话历史；若发生重载或接管，适用上一条。录音中断与恢复仍走既有流程。
- 工程内容按既有机制持久化；Undo/Redo 栈不写入 Project Truth、工程导出或跨设备同步数据。重新打开保留已提交内容，但不恢复旧历史。
- 新建、打开、复制工程及自动初始化不作为用户创作撤销项，打开完成的工程构成历史起点。异步初始化写入必须与历史顺序隔离：不能把用户编辑之后到达的系统写入误记为用户动作或被 Undo 覆盖；若它替换当前工程基线，应结束当前历史并告知原因。这里不改变默认声音逐 Pad 下载的工作流。
- 成功且确实改变内容的新用户创作动作清空 Redo。失败、拒绝、取消、无实际变化及同一命令的重复请求不增加历史、不清空 Redo。
- Undo/Redo 自身移动历史位置，不作为新的普通动作压栈；空栈时不可执行。

## 3. 可撤销操作集合

统一纳入用户成功提交的 Project Truth 创作修改。下表中的未来能力在各自实现时接入同一历史；列入集合不表示本 Task 或 P0.1 同时实现这些能力。

| 类别 | 历史内容与边界 |
| --- | --- |
| Pad 指派、替换、清空 | 恢复动作涉及的完整绑定与创作参数；清空与撤销均保留引用 Pad Slot 的 Pattern 事件。 |
| Pad 参数修改与 Reset Pad | 恢复实际修改前后的完整创作值，包括用户未显式触碰但命令同时改变的字段。 |
| 声音导入、录音提交、Sound Set 安装 | 成功提交后纳入；一个用户动作涉及的 Asset、Lineage、Pad 绑定及参数整体恢复，不留下半次安装或半个录音提交。 |
| Chop、Split Stems 等处理结果采纳 | 采纳成功产生一条历史，多 Pad 结果原子撤销；计算和候选预览不入栈。 |
| Pattern 创建、槽位指派／清空／移动及事件编辑 | 记录涉及的对象、顺序、身份及槽位关系；事件继续只引用 Pad Slot。 |
| Sequence 录制结算、BPM／Quantize／Swing 等工程参数 | 已提交的创作值纳入；录制中的拒绝规则保持有效。 |
| Performance 等其他用户提交的工程创作对象 | 与其他创作动作共用历史；演奏中的瞬态状态不因名称相同而纳入。 |
| 后续 Pad choke 参数、复制／合并／交换与网格编辑 | 每次用户动作原子纳入，不另建页面或 Pad 私有历史。 |

以下操作不进入该历史：播放、停止、试听、导航、选择、实时 FX 手势、音频激活、设备或 Provider 设置、保存、导出与分享；以及下载进度、Provider Attempt、候选预览、未提交的录音与 Crop 缓冲、恢复进度。
若上述流程最终提交了新的创作对象，仅该成功提交进入历史。

删除下载中、处理中或失败的 Pad 时，取消任务本身不可撤销。若该动作还清除了已有的 Project Truth 内容，Undo 只恢复这部分创作内容；若仅取消任务且 Truth 不变，则无撤销项。
取消后到达的旧任务结果不得重新写回 Pad。Undo 不重启请求、不恢复 Attempt 状态，也不冒充“恢复下载”。

## 4. 一次用户动作与事务边界

- 一次参数拖动从手势开始前的值到结束后的值构成一条历史；不能按 pointer move 或内部提交次数拆分。无其他动作插入时，拖回原值不留空历史项。
- 一次批量网格编辑、多 Pad 采纳、Sound Set 安装、Pad 复制／合并／交换均为一个原子动作，不能要求用户逐个恢复中间写入。
- 一次 Sample／长按录音成功提交是一条历史。权限拒绝、静音拒绝、取消或尚未提交的裁剪不是录音撤销项。
- Sequence 以 Record-off、Stop 或实际目标切换形成的录制结算段为单位；内部增量提交不是用户可见的多个 Undo。被拒绝的切换不创建结算段。本规则不增加现有 transport 尚不支持的切换能力。
- 手势合并只能覆盖同一动作的连续修改，不能跨越其他已提交动作；异步结果按成功提交顺序进入历史，不能插回任务发起时的位置。
- 未结算录音、进行中的历史事务或待恢复事务期间，Facade 拒绝 Undo/Redo，Host 禁用控件并给出用户可理解的原因。Undo 不隐式停止录音、结算、丢弃候选或选择恢复方案。
- 用户先完成正常停止、结算或恢复，之后再执行 Undo。恢复确认原命令已提交时不重复记账；在新打开的会话恢复既有提交也不复活旧会话历史。用户在新会话明确采纳尚未提交的恢复候选，则该新提交正常入栈。

## 5. Project Truth、Facade 与资源边界

### 5.1 内容恢复与 revision

历史记录用户动作对应的变更前后创作内容，按事务应用，并校验工程、会话、写入所有权及当前 revision。
例如 `r10 / A → 编辑 → r11 / B → Undo → r12 / A → Redo → r13 / B`。
这里 A/B 表示创作内容；新 revision、命令收据与事务身份不能从旧记录回写。
原有 Asset、Pattern 等创作对象身份及产物来源证据应恢复，不因 Redo 重新生成声音或伪造来源。

因此 #1659 中“exact prior Project Truth revision”的验收含义由本决策明确为：
**精确恢复对应创作内容，但提交新的递增 revision**，而非把整个工程退回旧版本号。
事务被拒绝或确定失败时，Truth 与历史位置均不变；提交结果未知时先走既有 receipt／恢复流程，不能盲目重复提交或提前移动历史位置。

### 5.2 所有权与接口能力

Application Facade/Core 拥有历史与原子提交语义；Host 仅请求 Undo/Redo，读取可用状态、下一动作名称和禁用原因。
Host 不解析 Project bundle，也不保存一份工程快照自行覆盖 Core。
内部采用按用户动作记录变更前后内容的历史事务；允许不可变内容共享等存储优化，但不能把整份旧工程无条件覆盖作为未来协作撤销方案。

Undo/Redo 经过既有 Authoring、持久化与 Runtime 派生发布路径。
Runtime Snapshot 仍是不可变派生状态，不成为历史中的 Project Truth；播放期间的命令准入、生效时机与并发边界不因本决策改变。
本 Task 不新增公共 API 或 Contract 字段；#1659 负责接口签名、事务分组实现、存储结构及有限容量预算，并在其计划中说明历史淘汰与资源释放策略。

### 5.3 Artifact、Provider 与清理

Redo 复用原 Asset／Artifact 和完整来源证据，不重新录音、下载或计算，不依赖 Provider 再现同一结果。
Undo 和 Redo 历史仍引用的素材都必须保持可读；不能因 Pad 被清空而立即删除仍被历史引用的字节。
只有历史淘汰、Redo 分支丢弃或会话结束后，才可释放对应的历史保留引用；释放引用不等于授权物理删除，仍须满足工程及其他资源持有者的保留规则。
素材缺失等资源错误不得造成部分恢复或先移动历史位置。
本决策给出 GC 必须遵守的历史保留约束，不接管物理 GC、同步格式或存储系统的实现。

## 6. 协作及保留的问题

沿用 workflow baseline 第 14 项：未来撤销只能影响自己本设备的操作，不能覆盖他人或其他设备的修改。
首版是单写入会话历史，不提供跨设备撤销、历史持久化、协作变换或自动 rebase；收到外部工程替换或失去所有权时结束本会话历史，明确提示不可继续撤销的原因。
未来协作的选择性撤销与合并算法需独立决策，本次不改变“远端修改下一小节生效”的待实现边界。

[#536](https://github.com/endaye/lmdj/issues/536) 及其[问题文件](../questions/ai-change-confirm-or-undo.md)继续保留。
可撤销不等于授权 AI 直接改工程；本决策不选择“确认在前”还是“撤销在后”。
已经按当时授权流程采纳的创作修改，应完整进入统一历史。

## 7. 后续实现的验收场景

以下为 #1659 及依赖任务的验收规格，不是本次已经执行的运行时测试。
每个箭头后应立即读取对应状态，再执行下一步；不以最终截图替代中间转换证据。

| 场景 | 必须观察的结果 |
| --- | --- |
| 编辑 → Undo → Redo | 每步核对完整受影响内容与未受影响内容；值为 A/B/A/B，revision 严格递增，对象身份及来源证据正确。 |
| Undo → 新创作提交 | 提交成功后 Redo 为空；对照失败、拒绝、取消、无变化及重复请求均保留原 Redo 与历史位置。 |
| 删除有声音 Pad → Undo → Redo → 指派新声音 | 删除后 Pad 静音且事件保留；Undo 后绑定及参数恢复；Redo 后再空；新指派后原事件播放新声音。 |
| 删除下载／处理中的 Pad → 旧任务迟到 | 取消成功后无旧结果写回；只有实际 Truth 修改有撤销项，Undo 不启动任务。 |
| 录音或处理结果提交 → Undo → Redo | 提交后核对 Asset／Artifact 身份、摘要、字节长度与来源；Undo 后目标恢复；Redo 后复用同一产物，外部执行次数不增加。 |
| 参数拖动／批量编辑／多 Pad 采纳 | 一次 Undo 恢复整个动作，一次 Redo 恢复完整结果，无部分写入；无变化手势不留空项。 |
| Sequence 录制 → 内部提交 → Record-off／Stop／有效切换 → Undo | 未结算期间显示禁用原因；实际结算后一次 Undo 恢复该段之前内容，其他段不变；拒绝切换不制造历史。 |
| 未结算或恢复中 → 请求 Undo → 完成结算／恢复 → Undo | 前次请求被拒绝且无副作用；完成后按确定的已提交内容撤销，不重复提交或丢弃录音。 |
| 提交失败／结果未知 → 对账或恢复 | 确定失败时 Truth 与历史均不动；未知结果先对账，同一命令最多记录一次；资源错误无部分恢复。 |
| 切页／保存 → Undo → 保存 → 重开 | 切页和保存后仍可撤销；重开后持久化内容为 Undo 后内容，历史为空。 |
| 接管／外部替换 → 原会话 Undo | 原会话不可写且历史失效；新会话空栈，任何一方都不能撤销另一会话的动作。 |
| 历史引用素材 → Pad 清空 → Undo／Redo | 历史保留期间字节可读；淘汰后仅释放历史引用，不误删仍被工程引用的资源。 |

Core 的内容／revision／原子性、Facade 的会话／恢复／资源边界与 Creator 的控件／手势分别由相应最低层测试覆盖。
浏览器自动化与真实设备上的录音、生命周期和听感证据分别记录；未执行的路径不得写成已验收。
