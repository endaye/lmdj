# 决策文件目录

自 2026-08-18 起，每条已确认决策是本目录下的一个独立文件。2026-08-16 及更早
的历史决策存档在 [../decision-log.md](../decision-log.md)，保持原样、不再追加。

并行分支各自新建自己的决策文件，不共享任何追加点；这是
[C2](../../quality/2026-08-17-machine-task-todo.md) 确立的结构，不要退回
到往单一文件追加。

## 约定

- 命名：`YYYY-MM-DD-<slug>.md`。日期是决策确认日；slug 是小写 kebab-case
  的主题名。同一天多条决策就是多个文件。
- 一个文件一条决策。同一次评审产出的一批相关决策可以合并为一个文件
  （先例：Stage 8 的 S8-D1–D13）。
- 不维护逐条索引：文件名按日期排序即时间线，目录列表即索引。
- 若决策解决了某个开放问题，在同一个 Task 里删除
  [`../questions/`](../questions/) 下对应的问题文件，并在决策条目里注明
  它解决的问题。
- 勘误或推翻既有决策：新建新日期的决策文件并链接被替代的条目，不回改
  旧文件（存档文件同样不回改）。

## 条目模板

````markdown
# 已确认：<一句话结论>

- 日期：YYYY-MM-DD
- 结论：……
- 原因：……
- 影响：……
````

沿用存档的写作口径：只记录已经确认的结论；未确认的内容先进
[`../open-questions.md`](../open-questions.md) 约定的问题目录。
