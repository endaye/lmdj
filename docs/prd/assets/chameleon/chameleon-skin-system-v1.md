# Chameleon 可换皮肤贴图规范 v1

状态：`approved-for-modeling`

适用对象：[Chameleon 3D 造型三视图 v1](chameleon-3d-turnaround-v1.md)

本规范固定“一个基础网格、多套贴图皮肤”的资产边界。它不代表 3D 模型、
Web 运行时、动画系统或 AI 状态映射已经实现。

## 1. 核心不变量

- 所有皮肤共用同一份基础网格、骨骼、动画、UV0 和材质槽位；
- 换皮肤不得改变头冠、眼球转塔、背脊、四肢、对趾脚掌和卷尾的廓形；
- 鳞片、条纹、颜色分区和微表面只由贴图表达，不能通过换网格实现；
- 左右眼保持独立对象和独立旋转能力，但共享同一套眼部材质约定；
- 皮肤外观与 AI 处理状态分离：皮肤定义常态表面，状态只读取预留遮罩并由
  运行时参数驱动；
- 任何状态色、闪烁或流动动画都不能被烘焙成某一套皮肤的唯一版本。

## 2. 基础网格和材质槽位

建议最多使用三个材质槽，控制 Web 渲染 draw call：

| 槽位 | 覆盖范围 | 说明 |
| --- | --- | --- |
| `Body` | 头冠、躯干、背脊、四肢、脚掌、尾巴 | 皮肤变化的主要表面 |
| `Eyes` | 左右眼球转塔、眼白、虹膜、瞳孔 | 左右眼可独立旋转，材质结构一致 |
| `Mouth` | 口腔内部和舌头（如建模） | 可选；未制作口腔时不创建空槽 |

模型导出时不得因某套皮肤增加新的材质槽、子网格或骨骼。

## 3. UV 契约

- `UV0` 是所有皮肤的稳定主 UV，范围为 `0..1`；
- 身体、左右眼和口腔使用不重叠的 UV 岛，不能镜像眼部或身体主花纹；
- 接缝优先放在腹部内侧、四肢内侧和尾巴下侧，避免穿过眼圈、头冠和背脊；
- 2K 源贴图的 UV 岛之间至少保留 `16 px` padding；
- 尾巴从根部到尖端保持连续方向，方便制作沿尾巴流动的状态遮罩；
- 重新拓扑、LOD 和蒙皮版本必须保持 UV0 的视觉对应；如确需破坏兼容性，
  必须提升皮肤契约主版本。

## 4. 贴图通道

### 必需通道

| 文件后缀 | 色彩空间 | 通道语义 | 用途 |
| --- | --- | --- | --- |
| `_basecolor` | sRGB | RGB = 基础颜色，A = 透明度保留为 1 | 颜色、条纹和大尺度花纹 |
| `_normal` | Linear | OpenGL tangent-space normal | 鳞片和非廓形微表面 |
| `_orm` | Linear | R = AO，G = Roughness，B = Metallic | glTF 2.0 PBR 打包通道 |

变色龙皮肤默认 `Metallic = 0`。金属、玻璃或机械皮肤如果改变角色材质语义，
需要单独评审，不能仅靠把 `_orm.B` 改为 1 即视为合格皮肤。

### 可选通道

| 文件后缀 | 色彩空间 | 通道语义 | 用途 |
| --- | --- | --- | --- |
| `_emissive` | sRGB | RGB = 发光颜色 | 皮肤自身恒定发光细节 |
| `_state-mask` | Linear | R/G/B/A = 四个可独立驱动区域 | AI 状态反馈的运行时遮罩 |
| `_detail-normal` | Linear | 高频切线空间法线 | 多套皮肤可共享的细鳞片层 |

`_state-mask` 只定义区域，不定义状态。建议初始区域为：

- R：眼圈与眼球转塔；
- G：背脊；
- B：身体侧带；
- A：尾巴流动路径。

Listening、Analysis、Generation、Waiting、Failure 和 Completion 等具体状态
如何映射颜色、强度、速度与动作，必须在独立角色状态设计获得批准后定义。

## 5. 分辨率和运行时格式

| 阶段 | Body | Eyes / Mouth | 格式 |
| --- | --- | --- | --- |
| 源文件 | 2048×2048 | 1024×1024 | 无损 PNG、TIFF 或创作软件原文件 |
| Web 桌面 | 2048×2048 | 1024×1024 | KTX2/BasisU 优先 |
| Web 移动 | 1024×1024 | 512×512 | KTX2/BasisU 优先 |
| 缩略图 | 256×256 | 不单独加载 | WebP/PNG |

最终 Web 预算需要在选定 3D runtime 和目标设备后以实测为准。当前数值是资产
制作上限，不是已验证的产品性能承诺。

## 6. 皮肤包命名和清单

建议目录：

```text
skins/<skin_id>/
  manifest.json
  <skin_id>_body_basecolor.*
  <skin_id>_body_normal.*
  <skin_id>_body_orm.*
  <skin_id>_body_state-mask.*
  <skin_id>_eyes_basecolor.*
  <skin_id>_eyes_normal.*
  <skin_id>_eyes_orm.*
```

`skin_id` 使用小写 kebab-case，发布后不可复用。清单至少记录：

- `schema_version`；
- `skin_id` 和展示名称；
- 兼容的基础网格版本；
- 每个材质槽的贴图 URI；
- 每个源文件的 SHA-256；
- 作者、许可和来源；
- 是否包含 emissive、state mask 和共享 detail normal。

正式运行时清单和 JSON Schema 应在 3D runtime 选型后进入 owned product
boundary；本规范不在当前阶段伪造一个尚无消费者的运行时 contract。

## 7. 验收门槛

每套皮肤必须通过：

1. 不替换网格、骨骼或动画即可完成热切换；
2. 纯黑廓形与基础模型完全一致；
3. 中性灰材质下仍由几何识别为变色龙；
4. 正面、侧面、背面无明显 UV 拉伸、接缝断裂或左右错位；
5. Base Color / Emissive 按 sRGB 读取，Normal / ORM / Mask 按 Linear 读取；
6. 眼球独立旋转时不暴露接缝或错误纹理方向；
7. 2K、1K 和 256 缩略图三档均可生成且来源可追溯；
8. 缺失可选贴图时使用明确默认值，不静默加载其他皮肤文件；
9. glTF/GLB 导出通过所选验证器，贴图清单 hash 与包内容一致；
10. 状态遮罩关闭时，皮肤回到稳定的常态外观。

## 8. 明确延后

- 3D runtime、渲染库和 Web 组件；
- 基础网格拓扑、LOD 数量、骨骼和动画约束；
- AI 功能状态到颜色、表情和动作的完整映射；
- 第一批皮肤的主题、数量、版权和商业化方式；
- GPU 纹理内存、draw call 和首屏加载的最终性能预算。
