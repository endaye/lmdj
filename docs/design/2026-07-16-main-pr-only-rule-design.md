# Main 分支 PR-only 规则设计

## 目标

让 `main` 始终保持可部署，并把“所有正常开发通过 Pull Request 进入 `main`”从部署设计中的约定提升为仓库级执行规则。

## 规则范围

规则同步写入 `AGENTS.md` 与 `CLAUDE.md`，约束在本仓库工作的代理和协作者。GitHub 的 `main` 分支保护继续作为远端强制门禁；仓库规则不替代分支保护。

## 日常开发规则

1. 不得直接在本地 `main` 上创建、修改或提交项目文件。
2. 开始任何改动前，先同步最新 `main`，再创建短期分支；Codex 分支使用 `codex/` 前缀。需要隔离时使用独立 worktree。
3. 所有改动必须在短期分支上完成验证并 push，通过 Pull Request、必需 CI 和 review gate 后，以 squash merge 进入 `main`。
4. PR 合并后删除短期分支。`main` 只用于同步、只读检查、创建分支以及部署已合并提交。
5. 如果准备修改时仍位于 `main`，必须先创建或切换到短期分支，不能先修改再迁移。

## 紧急例外

管理员仅在事故恢复或分支保护本身阻断修复时可以绕过 PR。绕过必须是最小改动，并在事后补充 PR、issue 或事故记录，说明原因、变更内容和验证结果。日常赶时间不构成紧急例外。

## 验收标准

- `AGENTS.md` 与 `CLAUDE.md` 包含语义一致的 PR-only 规则；
- 规则与现有单服务器分支及部署设计一致；
- 规则明确本地操作、PR 合并路径和紧急例外；
- 规则修改自身也通过短期分支和 PR 合入 `main`。
