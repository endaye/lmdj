# Tool-generated artifact bytes exhaust the review input limits on every Build allocation PR, so the review input must exclude generated path classes while recording the exclusion.

## Why

The production review collector bounds its input (`MAX_FILES = 50`,
`MAX_INPUT_BYTES` in `scripts/ci/pr_agent_review.py`), but a Build allocation
PR carries ~56 generated files on its own and an immutable Portal snapshot adds
~70 more, so every such PR exceeds the file limit before any human-written
change is counted (#1364 was refused with "changed Git inventory exceeds the
file limit" at 126 files). The defect is procedural, not visible in any one
source file: the review-scope design never distinguished human-written content
from deterministic renderings, and the Build-allocation change shape guarantees
the collision. Frozen snapshots, rendered assembly, generated identity, and the
assembly lock are already verified by deterministic gates (`scripts/docs-site.sh
check`, `tests/build/version_test.py`, `scripts/version.py verify`,
`tests/conformance/version_lock_test.py`); model-reviewing their bytes adds no
assurance and only spends the bounded budgets.

## How to apply

When a change touches review-input collection or the generated-artifact set,
keep the two in sync: the generated path classes live in
`GENERATED_DIRECTORY_PREFIXES` / `GENERATED_FILES` in
`scripts/ci/pr_agent_input.py`, and the exclusion must stay *recorded* — the
input document's `excluded_generated` field names every withheld path so the
exclusion itself is auditable rather than silent. Never resolve a review-input
limit refusal by raising the limit to fit generated bytes; exclude the
gate-verified class or split the reviewable change set. A change whose entire
inventory is excluded is no longer a dead end when every excluded path is
Portal-class (`apps/architecture-portal/versioned_*` and
`apps/architecture-portal/static/versions/`): `build_input` then raises
`GeneratedOnlyInput` carrying a `lmdj.pr-agent-input-generated-only.v1`
receipt, the publisher posts a `lmdj-review-generated-v1` marker, and
`scripts/ci/review_wait.py` admits it only when the Architecture Portal lane
is green on the same head — any other generated-only combination keeps the
explicit refusal. The regression tests in
`tests/build/ci_pr_agent_input_test.py`
(`test_generated_artifacts_are_excluded_from_limits_but_recorded`,
`test_all_generated_portal_inventory_yields_a_receipt`, and the
`MAX_FILES` refusal test) enforce both directions: generated paths never reach
the diff or the file budget, and the refusal semantics for genuinely
oversized reviewable inventories are unchanged.
