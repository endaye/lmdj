# An instrument that cannot detect presence cannot establish absence; a report needs validation at its claimed implementation site.

## Why

An empty search can mean either absence or a representation the search cannot
see. A member-name grep misses positional aggregate initialization; a name
pattern misses aliases, generated registrations and table-driven dispatch. A
wrong-tree search can be correct for the measured revision and false for the
revision under review. A clean harness or corpus can likewise exclude the
failure class by construction.

The recorded Web Host example followed generated identity JSON through CMake
extraction and compile defines to the last positional `ApplicationConfig`
member. The Host injected Sound Set limits even though the member name never
appeared at its assignment. A name-only search produced the same empty result
for both wired and unwired code.

The converse recurred in a Project Bundle report (#980): it claimed a
`project.import.chunk` operation and ID-addressed `project.inspect`, while the
Host dispatched `project.import.index` and `project.import.entry`, and inspect
accepted an empty payload for the retained session. Its filesystem claims also
ignored the Host's OPFS path mapping. During that investigation, an unrelated
name search missed the Creator's `onImport` → `importProjectJourney` wiring.
Both conclusions were accepted before checking whether their evidence could
express the question.

## How to apply

Before accepting a report as a premise or opening a workstream, follow
[issue-list §2, Validate evidence](../skills/issue-list/SKILL.md#2-validate-evidence-before-accepting-a-report-or-opening-a-workstream).
It owns per-operation dispatch/handler/payload checks, the known-present control
and bounded authoritative-site inspection for each absence, and the resulting
verified/contradicted/unverified disposition at an exact revision. Retain
positional, generated and table wiring in that inspection.
