## 1. 目的与非职责
事务式保存/加载 Project Truth、导入/导出 portable Project Bundle，并维护 Sequence journal overlay、flush receipt 与 recovery artifact；不 Cook、渲染或拥有 Host UI。
## 2. 当前实现状态
Project I/O `1.0.0` 的 Store、Sequence Journal、streaming Bundle parser/packer、v1/v2 读取与 v3-only 写出、Workspace Cache 和 crash-safe publication 已实现。flush 以 manifest replacement 为 commit point，并把 command/session/flush identity 与 committed revision 写入可幂等重放的 receipt。
## 3. 所有权与依赖
依赖 Foundation 与 Authoring Domain；平台适配不能改变领域语义。
## 4. 架构与数据流
Facade 提交 Project、Bundle stream、bounded Sample bytes 或 Sequence flush；Project I/O 在 writer lease 下验证 journal overlay，原子发布 Project v3 revision，再完成 receipt。Store 只暴露已提交 Project Truth；未提交 overlay、owner-loss recovery artifact、waveform cache 与不可变 Runtime Snapshot 生命周期彼此独立。
## 5. API 与 Artifact 边界
只持久化 Project Truth 与原始 WAV Artifact；`lmdj.project-bundle.v1` 只定义 transfer envelope；Workspace waveform cache 可丢弃重建，Runtime Snapshot 明确禁止持久化为创作真相。
## 6. 状态、错误与生命周期
故障矩阵验证验证、取消、超时与发布中断恢复；typed error 区分输入、平台、busy 与提交失败。
## 7. 产品使用方
Application Facade 使用；Host 不直接解析 bundle。
## 8. 测试与证据
Project store、v1/v2→v3 migration、atomic Sample transaction、Sequence journal/receipt/recovery、Bundle 1.0/1.1 round trip/publication、fault matrix、distinct-platform publication ownership、Native link-count 与 Web/native storage platform contract 测试。
## 9. 限制与下一门禁
云同步和协同冲突策略未批准，不能从本地存储能力推断。
## 10. 版本身份
版本和依赖由 `module.json`/Assembly Lock 派生。
