## 权威内容

当前 Bundle Contract 是 portable Project transfer envelope：canonical index 固定 Project ID、Project Contract、entry path/offset/bytes/SHA-256、总字节数和整个 Bundle digest；当前版本只允许无压缩 payload。`project_contract` 枚举覆盖仓库定义的 Project Contract（v1 至 v5）。writer 发出 Project Truth **head checkpoint** 的 Contract 级别而不是初始 checkpoint 的；reader 继续接收旧 envelope。导入侧从载入的 Project 重算期望 digest，loader 把 v1 与 v2 归并为 v3，因此声明 v1 或 v2 的容器仍有既存导入限制，不能把枚举可接受性当作完整旧版本迁移证据。
## 与 Project Truth 的关系

Bundle 只负责传输，不是新的创作真相。成功导入后，已验证的 Project 是权威 Project Truth；Runtime Snapshot、Provider/Attempt、Workspace/Host setting 与设备状态不进入 Bundle。

## 安全与发布

解析器对 header、索引、路径、大小、重叠、顺序、重复、hash 与 Project identity fail closed。导入先完整验证并 staged，随后由 Project I/O journal 原子发布；失败、取消或超时不得留下可打开的半成品 Project。

## 使用方与证据

Application Facade 暴露 streaming import/export；Creator Host 只传递字节和展示 typed result。Schema、parser、round trip、故障注入、取消与 OPFS publication tests 固定该边界。`conformance.project_bundle` 另把 Bundle 枚举与仓库内定义的 Project Contract 清单绑定，`e2e.project_bundle_writer_level` 则打包真实 CLI Host 创建的 Project，因此下一次 Project Contract 级别移动会先让套件变红。

## Slice lineage Project transport

The envelope now admits the successor Project Contract alongside v1-v4.
Native, Python and browser readers retain prior envelope versions and accept
the current writer's v5 Project bytes, including closed Slice lineage. Import
validates Project Truth and retains the original lineage; it does not resolve
Workspace CandidateSets or execute Provider attempts. The envelope version and
current Contract identities remain generated from the active manifests.
