## 目标边界

Main thread 只负责 manifest/hash 装载门、Window 能力、用户手势、DOM/MIDI 输入、生命周期观察、有界 transport 与终止清理；Dedicated Worker 独立证明 OPFS、SyncAccessHandle 与 writable replacement 能力，Project、OPFS、Facade、解码与混音仍由 Control/Core 边界负责。Pointer、Keyboard、MIDI 汇入唯一 `trigger(flatSlot, velocity)` 路由。

## 分发与身份门禁

`scripts/web-runtime-host.sh build` 原子生成 `build/web/host/dist`：全部分发资产使用内容哈希文件名，canonical `host-manifest.json` 以私有 ownership contract 绑定当前 Product Build、Host `1.1.2`、私有协议 `1`、固定 512 MiB heap、四项资源上限、固定 Emscripten 身份，以及九项生产资产的精确路径、role、正字节数和 SHA-256；第九项是可见 Load 流程使用的诊断 Project 资产。Browser Main 在装载 runtime 资产前校验完整形状与 canonical bytes；Control 在创建 proxy queue、OPFS、Facade 或 audio adapter 前独立校验同一有界 manifest。缺失、畸形、超限、任何字段或 inventory 漂移、hash/identity 不匹配、重复或迟到初始化均 fail closed 为 `HOST_PROTOCOL_MISMATCH`；即使真实 bridge 已发布，迟到/重复初始化也会关闭入口并 once-only seal Control runtime。

proof-only server 只暴露指定 dist，设置精确 COOP/COEP/CORP/CSP 与 WASM MIME；仅 index/manifest 使用 `no-store`，内容哈希资产使用 immutable cache。它不是生产发布服务。

## 生命周期门禁

普通 Trigger 与全部 `take.begin` 只在 `running` 接收。诊断 Project 的每个 awaited Host request 返回后都重新核对 page-lifetime admission；pagehide 后不得继续 import、assignment、final inspect 或 publication。修复结束后必须再次 `project.inspect`，且 final revision、诊断 Asset 与全部 64 个 Pad assignment 都匹配，才可请求 Snapshot publication。`HOST_RESTART_REQUIRED` 即使晚于 invalidation 返回也保持 sticky，`HOST_PROTOCOL_MISMATCH` 同样 fail closed；两者都只触发一次终止清理，页面重建前 direct/queued Load 不得重试。

中断同步关闭 runtime admission、清除 pressed state，并按 epoch 只发一次 Control suspend/seal。恢复必须同时具备 Context `running`、正整数 current/ack generation 相等，以及一个真实用户 recovery probe 的唯一 `voice_started`；visibility 或 pageshow 本身不能完成恢复。

## 自动化证据

`scripts/web-runtime-host.sh proof` 覆盖两次 clean build 的逐字节可复现性、deterministic inventory、proof-server headers/cache/no-follow ownership、双重 manifest gate，以及 Chromium packaged Main→Control→Facade/OPFS→Wasm AudioWorklet 全旅程。当前本地候选先证明可见顺序 `Load diagnostic project -> ready -> Activate audio -> running -> trigger`：首次准备只执行一次 create、一次 import、64 次 Pad assignment 并得到 revision `65`；Pointer 与 Keyboard 各产生一个精确 outcome；reload 后复用同一浏览器本地 descriptor、零重复 mutation、revision 不变且再次进入 `running`。reload 后的 `project.open` 使用 60 秒有界 writer-handoff 预算；超过预算仍以 `HOST_TIMEOUT` fail closed，浏览器 Proof 仅在 Host 与诊断错误码同时精确等于该值时允许一次整页恢复，其他错误与重复超时继续失败。terminal failure 会先封闭新请求，再给 responsive Control Worker 5 秒有界 grace 完成 OPFS writer release；超过 grace 才强制终止 Worker。随后继续证明 500 个 admission sequence 与 500 个 `voice_started` outcome 精确对应、20+1 Take 边界、重启重开、失败与 lifecycle 路径。WebKit 只在 mandatory primitive 可用时执行完整 smoke；缺少能力时必须输出结构化 limitation。`1.0.15.2` 当前只有本地 Proof 证据；[PR #91](https://github.com/endaye/lmdj/pull/91) 的远端 CI 与合并证据仅属于历史 `1.0.14.0`，不升级为本候选的 PR、CI 或 merge 结论。
