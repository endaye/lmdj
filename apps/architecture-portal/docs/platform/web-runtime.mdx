## 当前 Lab
Web Runtime Lab 验证静态服务、WASM Core Probe、AudioWorklet 和物理证据准备器；它不在 Product Assembly。
## 正式 Host 分发
正式 Web Runtime Host `1.0.0` 已进入 Product Build `1.0.14.0` Assembly。它具备固定 Emscripten 身份的双 clean-build 字节可复现门、内容哈希资产、带 ownership contract 的 canonical manifest、Browser Main 与 Control 双重身份门禁、Dedicated Worker realm 的 OPFS capability proof，以及只服务已完整验证 dist 的 proof-only CSP server。manifest 绑定当前 Product Build、协议 `1`、固定 512 MiB heap、资源上限和八项生产资产的精确 inventory；AudioWorklet 的 Emscripten 固定自引用也精确绑定同一 manifest 已验证的内容哈希 runtime。
## 线程模型
主线程处理 UI/control，AudioWorklet 处理实时音频；消息与 buffer 边界必须保持有界。
## 验收阈值
Task 10 自动化证明 deterministic/atomic package、无旧进程冒充的 proof server readiness、隔离 headers/cache、无 shim 的 packaged Host 启动，以及 manifest 失败或迟到初始化时零新增 OPFS mutation。Task 11 的 packaged Chromium 全旅程现进一步证明：真实 Facade/OPFS Project create/import/assign/Snapshot，500 个 admission sequence 与 500 个 `voice_started` outcome 精确一一对应且零容量损失，20+1 Trigger 的 Take 提交后精确保留 20 个 event，page/Worker restart 后重开同一 Project，并覆盖 Snapshot 拒绝保留旧 generation、显式 suspend、单 probe recovery、writer lease contention、protocol mismatch、`HOST_TIMEOUT` 后 lease 释放与 clean close。

Playwright WebKit 仅是 capability/protocol/OPFS/restart/lifecycle smoke；当前 runner 以 `UNSUPPORTED_WEB_RUNTIME` 明确记录缺少 `opfsSyncAccessHandle` 与 `opfsWritableReplace`，不能冒充完整 WebKit 产品验收。五项物理门仍是 `deferred / unverified`：macOS Safari Pointer、macOS Chrome Pointer、macOS Chrome Physical MIDI、iPadOS Safari Touch、iPadOS Safari Touch lifecycle；延迟、underrun 与真实设备体验仍由独立 evaluator 判定。
## 非能力
当前不承诺离线安装、Creator Web/PWA 交付、跨物理设备一致体验或 `beta`/`stable` 质量；proof-only server 不属于生产部署面。
## 下一门禁
Formal Host 的 Assembly 身份与自动化 Proof 已建立；下一产品门禁是补齐五项物理 dossier、远端 CI 与相应 Channel 的独立授权。自动化仍不替代物理证据。
