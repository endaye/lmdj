## 当前 Lab
Web Runtime Lab 验证静态服务、WASM Core Probe、AudioWorklet 和物理证据准备器；它不在 Product Assembly。
## 正式 Host 分发
正式 Web Runtime Host `1.1.2` 已进入当前本地候选 Product Build `1.0.15.2` Assembly。它具备固定 Emscripten 身份的双 clean-build 字节可复现门、内容哈希资产、带 ownership contract 的 canonical manifest、Browser Main 与 Control 双重身份门禁、Dedicated Worker realm 的 OPFS capability proof，以及只服务已完整验证 dist 的 proof-only CSP server。manifest 绑定当前 Product Build、协议 `1`、固定 512 MiB heap、资源上限和九项生产资产的精确 inventory；AudioWorklet 的 Emscripten 固定自引用也精确绑定同一 manifest 已验证的内容哈希 runtime。
## 线程模型
主线程处理 UI/control，AudioWorklet 处理实时音频；消息与 buffer 边界必须保持有界。
## 验收阈值
Task 10 自动化证明 deterministic/atomic package、无旧进程冒充的 proof server readiness、隔离 headers/cache、无 shim 的 packaged Host 启动，以及 manifest 失败或迟到初始化时零新增 OPFS mutation。Task 11 的 packaged Chromium 全旅程现进一步证明：真实 Facade/OPFS Project create/import/assign/Snapshot，500 个 admission sequence 与 500 个 `voice_started` outcome 精确一一对应且零容量损失，20+1 Trigger 的 Take 提交后精确保留 20 个 event，page/Worker restart 后重开同一 Project，并覆盖 Snapshot 拒绝保留旧 generation、显式 suspend、单 probe recovery、writer lease contention、protocol mismatch、`HOST_TIMEOUT` 后 lease 释放与 clean close。

Task 13 A 进一步固定 Project mutation deadline：唯一绝对 cutoff 在同步 JavaScript-to-Wasm envelope/sidecar copy 之前开始，native steady deadline 不会因 copy、queue handoff 或主线程 timer 阻塞而后移；source-shell controller 只把 operation deadline 交给权威 transport，不再另起竞争 timer，1,000 ms recovery-outcome watchdog 与 runtime-terminator deadline 则保持独立；publication 仍 open 时 cancellation 可赢并返回 `HOST_TIMEOUT`；publication claim 先赢时，claim 是取消截止点，越过 caller deadline 后仍返回真实 committed success 或 aborted error。claimed settlement 的生产 watchdog 精确为 1,000 ms；超时返回带 `terminal_state: restart-required`、`mutation_outcome: unknown` 的 `HOST_RESTART_REQUIRED`，Host 保持 failed/sealed，并在重开时接受 old-or-new authoritative truth、清理 manifest 未引用文件后允许 inspect/retry。terminal BroadcastChannel 只负责唤醒，Control 的 native authorize/complete 与 Browser Main 的一次性 consume 让 forged/replayed ACK 和 duplicate release 无法制造 completion，真实 completion 也只能消费一次；packaged `CONFORMANCE=OFF` regression 同时覆盖 responsive native completion、无 native completion 时不可跳过的 100 ms force-terminate fallback、deadline-after-claim cancel telemetry 与 once-only terminal delivery。这些自动化证据不改变五项物理门状态。

当前本地候选把真实人工前置序列固定为 `Load diagnostic project -> ready -> Activate audio -> running -> trigger`。Chromium 自动化证明首次准备为一次 create、一次 import、64 次 assignment、revision `65`，Pointer/Keyboard 各有一个精确 `voice_started` outcome；reload 后同一 browser-local descriptor 被重开，零重复 mutation、revision 不变并可再次激活。descriptor UUID 不进入 DOM diagnostics。该证据不等于声学延迟、物理 MIDI、Safari/iPad Touch 或主观音质验收。

## 公共静态托管边界

已实现的发布 tooling 从 canonical origin 获取 remote signed tag 与受保护 `main`，要求 tag
commit 是该 `main` 的 ancestor；Release inventory 精确为 ZIP、checksum、受信 Product key
的 detached armored checksum signature，并在解析 checksum 前验证 signature。它会发现并
验证真实 prior Product/Host 身份，在 prior immutable 与 production 上先跑完整
HTTP/Chromium，再创建 immutable draft；只有 draft smoke 通过才发布同一 ready Deploy ID。
发布后失败或信号中断会 reconcile alias，必要时恢复 exact prior；首次无 prior 时采用官方
reversible site disable。生成站点只给 manifest 中九个精确 hash asset 加 immutable header，
未知 asset/source map 继续 `no-store`；成功/恢复分别保存 deployment evidence v2/recovery
evidence v1。

该流程尚未在远端发生。本地已存在 signed annotated tag `lmdj-v1.0.15.2`，Good signature
primary fingerprint 为 `2B5EE362F058800036AD4FB5116ECE156F954D29`，target 为
`72ae40074620cc5681c462ba04a31a666449734f`；该 target 已是 `origin/main` 上 PR #98 的 merge
commit。尚未 push、review、CI、merge 的限定只适用于本 Task 的 deployment-tooling branch；
本地 tag 尚未 push，未做远端验证，因此仍不声称有本候选的 remote verified tag、Release、
`lmdj-runtime` project、workflow run、Deploy ID、immutable URL、production alias 或
deployment evidence。Portal 只报告 tooling 已实现和公共部署 absent，直到真实 evidence
record 被审查并提交。

proof-only server 仅对本地 Proof 服务 `dist` 与安全 headers；它不是生产服务。生产由
Netlify 静态托管同一份已验证的 release `dist`，不运行该 Python server。`lmdj-canary`
属于未来 Creator，排除在此 Runtime Host project/URL/alias 之外；完整操作与 pre-deploy
记录分别见仓库文件 `docs/deploy/web-runtime-host.md` 和
`docs/quality/2026-08-08-web-runtime-public-deployment-acceptance.md`。

Playwright WebKit 仅是 capability/protocol/OPFS/restart/lifecycle smoke；当前 runner 以 `UNSUPPORTED_WEB_RUNTIME` 明确记录缺少 `opfsSyncAccessHandle` 与 `opfsWritableReplace`，不能冒充完整 WebKit 产品验收。五项物理门仍是 `deferred / unverified`：macOS Safari Pointer、macOS Chrome Pointer、macOS Chrome Physical MIDI、iPadOS Safari Touch、iPadOS Safari Touch lifecycle；延迟、underrun 与真实设备体验仍由独立 evaluator 判定。
## 非能力
当前不承诺离线安装、Creator Web/PWA 交付、跨物理设备一致体验或 `beta`/`stable` 质量；proof-only server 不属于生产部署面。
