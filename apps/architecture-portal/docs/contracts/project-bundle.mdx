## 权威内容

`lmdj.project-bundle.v1 · 1.2.0` 是 portable Project transfer envelope：canonical index 固定 Project ID、Project Contract、entry path/offset/bytes/SHA-256、总字节数和整个 Bundle digest；当前版本只允许无压缩 payload。`1.2.0` 把 `project_contract` 枚举扩到仓库定义的全部四个 Project Contract 级别（v1 至 `lmdj.project.v4`），是向后兼容的追加：自 Project I/O 无条件写出 `lmdj.project.v4` 起，缺少 v4 意味着本 Build 创建的任何 Project 都不能打包，这正是该版本存在的理由。writer 发出 Project Truth **head checkpoint** 的 Contract 级别而不是初始 checkpoint 的——一个在首次持久化时被提升的旧 Project，打包出的 index 必须与 Project I/O 导入侧重算的 digest 一致；reader 为迁移继续接收 `1.0.0` 与 `1.1.0` envelope。这一点有一个当前限度：导入侧从载入的 Project 重算期望 digest，而 Project I/O 的 loader 把 v1 与 v2 都归并为 `lmdj.project.v3`，因此只有声明 `lmdj.project.v3` 或 `lmdj.project.v4` 的旧容器能通过；声明 v1 或 v2 的容器仍然导入失败，这是先于本 Build 就存在的缺口。

## 与 Project Truth 的关系

Bundle 只负责传输，不是新的创作真相。成功导入后，Project v4 是权威 Project Truth；Runtime Snapshot、Provider/Attempt、Workspace/Host setting 与设备状态不进入 Bundle。

## 安全与发布

解析器对 header、索引、路径、大小、重叠、顺序、重复、hash 与 Project identity fail closed。导入先完整验证并 staged，随后由 Project I/O journal 原子发布；失败、取消或超时不得留下可打开的半成品 Project。

## 使用方与证据

Application Facade 暴露 streaming import/export；Creator Host 只传递字节和展示 typed result。Schema、parser、round trip、故障注入、取消与 OPFS publication tests 固定该边界。`conformance.project_bundle` 另把 Bundle 枚举与仓库内定义的 Project Contract 清单绑定，`e2e.project_bundle_writer_level` 则打包真实 CLI Host 创建的 Project，因此下一次 Project Contract 级别移动会先让套件变红。
