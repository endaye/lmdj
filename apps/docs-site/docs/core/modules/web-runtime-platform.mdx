## 1. 目的与非职责
为浏览器 Host 提供共享 Runtime Session、输入 adapter、Control bridge、manifest gate 与 Web Audio 接线；不拥有 Creator UI、诊断 UI、Project Truth 或产品专属身份。
## 2. 当前实现状态
Creator Web 与诊断 Web Runtime Host 共用 Platform 和同一 Wasm Runtime。Platform 除 Sample surface 外，还桥接 revision-bound `sample.quota`、Sequence begin/event/flush/stop/next-Bar switch/status/settings/recovery，以及 Stage 10 的 Pattern Slot assign/clear/move 与整套 Performance 操作；当前 source 在 accepted event 后读取 Facade typed overlay projection，发布 committed snapshot + overlay；active-session BPM 更新保留同一 overlay/boundary，owner-loss seal 与 flush/Stop 发布 clean committed view，Stop publication failure 可由 exact replay 恢复。若 owner-loss clean publication 自身失败，Host 使用已安装 quiescence contract 停止并清空 Runtime Pattern 后才释放 owner。pointer、keyboard、MIDI admission 统一使用 Audio Runtime frame clock 与单调 `input_sequence`，JavaScript 不计算 musical time。本版新增 Platform 自有的 master tap 与录制通道。`web/performance_master_tap_worklet.js` 是注册为 `lmdj-perform-master-tap` 的 AudioWorklet processor：它把 master bus 直通到监听 gain，同时按 4800 帧成批向控制侧投递。监听 gain 由 Session 持有，最后连接物理输出；`monitorVolume`/`setMonitorVolume` 使用 0–100 的线性百分比，激活前即设置初值，运行中以 20 ms ramp 平滑变化。`monitorDestination` 让 Host 的非录制声音接入同一监听路径。tap 初始化失败或 processorerror 后，Core 输出仍恢复到同一 gain；重复恢复不叠加连接，跨 context 目的地拒绝。gain 不改变上游录制批次，也不写入 Project 或 Undo history；终止时断开并拒绝修改。`web/performance_master_capture.mjs` 是唯一消费者，对每条消息做精确键校验：批次为 `{type:"batch", channels:[Float32Array, Float32Array], generation, sequence}`，两个声道等长且不超过 `MAX_BATCH_FRAMES = 4800`，`sequence` 必须严格递增一格；停止确认为 `{type:"stopped", finalSequence, generation}`，失败为 `{type:"failed", reason:"post-message-failed", droppedFrames, generation}`；停止确认的等待上限是 `STOP_ACK_TIMEOUT_MS = 30000`，超时按失败结算。generation 不匹配的消息一律丢弃，Host 无法用陈旧 generation 复活已结束的录制。

本版落地 D04 实时控制的 Web producer（W1）：Platform 注册 `performance.live.status`（query）与 `performance.live.control`（command）两个新 operation，`protocol.mjs`（JS 注册表）、`src/bridge.cpp`（桥 supported_operation）与 `src/control_runtime.cpp`（native 校验器）三处同改；headered 录制由 `performance.record.begin` 的可选 `control_epoch` 键选择，`record.event`/`launch-request` 相应携带 `control_epoch` 加规范十进制字符串的 `expected_recording_sequence`——opaque 序号逐字符校验，绝不经过 JS Number；slot 恒为 0..63 安全整数，不存在 32 位 mask 换算。新事件 kind（`filter_parameter`/`filter_release`/`pad_mute`/`pad_solo`/`clear_pad_gates` 及带绑定对的 fx_move/fx_release）只在两键同时存在时按闭合集合校验。Runtime Session 的 Runtime action 通道从无限 Promise tail 改为有界窗口：至多 1 inflight + 1 普通 waiting，至多 64 个 open Pad gesture 各保留 1 条 matching release 位置，另有 1 个 cleanup token；普通输入超额明确拒绝、不合并已接收控制值、不丢 matching release，cleanup/关闭对从未到达 Core 的 waiting 输入显式 reject。Session 跟踪 `controlEpoch` 与 expected 序号窗口，replayed receipt 不推进计数。capture 握手新增应用层 `started` ACK：start 消息携带 `{generation, binding:{control_epoch, session_id, begin_command_id}}`，worklet 实际应用后在下个 process 前回同形状 `started`；controller 在发送前占有唯一 pending start，promise 仅在 owner/generation/binding 严格匹配的 ACK 后 resolve，错 binding/额外字段/重复 started/提前 batch 都是协议失败并走有界 stop 清理，旧 generation 的迟到 ACK 永不复用；headered begin 的 SDK promise 在 Core fence ready 与 capture ACK 双 ready 前保持 pending，暂存的录制输入零投递。

`sample.update_pad` 与 `sample.preview.set` 的 `playback` 接受 `lmdj.project.v5` `5.1.0` 的六个可选回放对齐键：`protocol.mjs` 与 C++ control runtime 都按“五个必填键加可选键”的封闭集合校验，未知键与越界值返回 `HOST_PROTOCOL_MISMATCH`，形状合法但越过源末尾的循环点由 Facade 以 `INVALID_ARGUMENT` 拒绝。Runtime Session 的 `wirePlayback` 把 camelCase 字段映射为线上键并只发出非缺省键，`normalizePlayback` 把回读补全为带缺省值的完整对象。试听不再在 Platform 内自行换算帧，而是调用 Facade 的 `resolve_sample_preview_playback`，所以试听与 Cook 播放同一结果。C++、`protocol.test.mjs` 与 `runtime_session.test.mjs` 以同一个 `tests/fixtures/contracts/pad-playback-full.json` 断言这一形状，防止各副本单独漂移；`control_runtime_test.cpp` 另证明试听的 `pitch_cents` 确实到达 voice（升八度的 200 帧 one-shot 在 120 帧内结束）。`5.2.0` 的 `attack_ms`、`release_ms`、`tone` 与 `eq` 以同样方式经过两层：越界值与畸形频段在固定线上返回 `HOST_PROTOCOL_MISMATCH`；Runtime Session 的 playback 对象始终带 `attackMs`、`releaseMs`、`tone` 与 `eq: {low, mid, high}`（旁通的频段为 `null`），线上只发出非缺省键与出现的频段。共享 fixture 新增 `tone` 变体，三处副本都以它往返。
## 3. 所有权与依赖
只依赖 Application Facade 与 Audio Runtime；当前身份由 Build Identity 派生。Bundle reader 接受 Project v5 transfer，旧 v1/v2/v3/v4 输入继续由 Core 迁移。Product CMake 注入 Product Build、Platform 版本、完整资源上限及精确 Host allowlist。
## 4. 架构与数据流
Creator/Diagnostic Host → Runtime Session → Application Facade；Project/Sample/Sequence actions 共享有界 Host lane，Runtime Session 的 `createProject` 在串行 Project action 上发出 `project.create`，先校验调用方给出的 Project/Pattern 身份、BPM 与 Bar 数，再只接受指名同一身份、revision 0 的结果；`duplicateProject({sourceProjectId, projectId})` 在同一串行 lane 上发出 `project.duplicate`，发送前拒绝非法或相同的身份，只接受指名新身份、revision 0 的 Local Project summary；Host 只复制、不替换当前打开的 Project、writer lease 或 Runtime，调用方另行 `openProject` 打开副本。Host 在 running、有 active Sequence 或未完成 Sample import 时以 `HOST_STATE_INVALID` 拒绝，另一标签页持有源 Project 时返回 `PROJECT_BUSY`，目标身份已被使用时返回 `DUPLICATE_ID`；源 Project 有未完成录制（含崩溃 owner 留下的 active Journal）时返回 `HOST_STATE_INVALID` 与 “source Project has an unfinished recording”，而不是被通用 sanitizer 还原成请求无效。发布前 deadline 已过则不发布任何副本，由 bridge 报告 `HOST_TIMEOUT`。Pointer、Keyboard、MIDI 汇入同一 frame-stamped admission。Control bridge 把 typed overlay projection 合成 immutable Prepared Pattern，AudioWorklet 在下一 Bar 消费并发布 Voice/Bar state；Project Truth 仍只在 flush/Stop commit 后变化。全局 Pattern transport 的 live overlay 发布由 Facade 协调器在控制节拍上驱动：Platform 实现 `publish_overlay` 能力（prepare 走 Runtime Snapshot），service tick 持续服务开着的录音，同 Pattern 的排队发布在落地前 coalesce，Record-off 可撤回尚未被 audio claim 的 overlay 后提交；已 claim 的 publication 保留原 busy/边界结算——无 beat restart。
## 5. API 与 Contract 边界
Platform 校验 canonical distribution manifest，但该同构建协议不是公开跨版本 Contract。`1.0.44.0` 的 manifest gate 要求恰好十三项 resource limit：`decoded_float_pcm_bytes_per_bank` 67108864、`decoded_float_pcm_bytes_total` 134217728、`decoded_float_pcm_bytes_resident` 268435456、`imported_wav_bytes` 68157440、`ingest_channels` 2、`ingest_decoded_frames` 43200000、`ingest_source_bytes` 104857600、`perform_recording_frames` 86400000、`perform_recording_queue_batches` 32，以及本 Build 新增的四项 Sound Set Set Store 上限 `maximum_soundset_manifest_bytes` 1048576、`maximum_soundset_blob_bytes` 68157440、`maximum_soundset_unique_bytes` 268435456 与 `maximum_soundset_staging_bytes` 536870912；键集是精确匹配，多一项默认值即拒绝，每一项都必须是正的安全整数并逐值比对。这正是 Platform 本次取 MAJOR 的依据：一份在 `1.0.43.0` 下合法的分发清单，在本 Build 的 gate 下被拒绝。四项上限是 Host 容量事实，经 `ApplicationConfig` 到达 Core；浏览器侧 Catalog 对象的暂存缓冲是另一回事，不在 manifest 内。资产清单同样精确：声明 `compatible_hosts` 的 Creator 分发必须恰好携带一个 `perform_master_tap_worklet` 角色的资产，诊断 Host 分发必须为零；重复路径、缺失或错误的角色计数、非法 digest 与资产路径，都是 fail-closed 的 inventory 缺陷而不是可容忍的默认值；resource limit、Emscripten 身份与 host allowlist 也逐项精确比对。更早的不可变分发包保留各自的精确身份，不被回溯要求携带 Stage 10 字段。Project Bundle 与 WAV sidecar 只通过 Facade 的 bounded streaming API 进入 Core，Browser 不解析 Project/WAV。
Creator 资产集合由实际 Host manifest 与生成的 `expected_assets` 选择。
Native gate 对进入离线主版本范围的 Creator 清单要求恰好一个 `offline_worker`；
此前的 Creator 清单与诊断 Host 清单要求零个。缺失、多余或重复均拒绝 ready
与 Runtime 创建，已发布清单保留其原有集合。
OPFS 的素材持久化不等同于离线启动。

## 6. 状态、错误与并发
Manifest mismatch、生命周期失效和 terminal failure 均 fail closed；Main、Control、Worker 与 AudioWorklet 的职责和消息上限固定。Runtime Session 另行发布 master capture 状态，状态字为 `unconfigured` → `configured` → `ready`，失败时进入带 typed error 的 `unavailable`；只有 `ready` 才允许开始一次录制，同一时刻不允许并发录制。状态经 `subscribePerformanceMasterCaptureStatus` 订阅、`performanceMasterCaptureStatus()` 读取，观察者抛错不影响录制生命周期归属；Host 不得从 `AudioContext` 状态、计时器或页面可见性推断 capture readiness。会话另以 `sampleAudioClock()` 提供纯 JS 的音频时钟采样——`{contextTimeSeconds, callbackHeartbeat, engineEpochHeartbeat}`，其中纪元心跳在每次 `audio.activate`（含中断恢复）解决后重采；同一引擎纪元内引擎帧与 AudioContext 时钟以 48 000 fps 一比一前进，一次采样即锚定之后全部换算，常数误差不超过约两个渲染量子，音频不在 running 时以 `HOST_STATE_INVALID` 拒绝。Control bridge 在控制线程上严格逐个 dispatch 请求：Facade 经 Asyncify 等待 OPFS 期间到达的请求按 FIFO 等待，待前一次 dispatch 完整返回（含 rewind）后才重新代理，因此同一线程不会重入 Asyncify；该保证对直接提交到 transport 的调用方同样成立，而 OPFS 存储层在检测到重入时 fail closed 而非破坏内存。Control 侧将 generation quota rejection 与 publication residency rejection 分开：前者保留 Bank/Project 类型和安全筛选后的账本 payload，后者继续使用 transient Web Runtime resource failure，且任一拒绝都保留当前 live generation。启动时先以 release ordering 发布 ControlBridge，再发布 audio adapter；pre-JS 的 audio readiness 因而同时构成 ControlBridge publication barrier。`recovery_probe_ready` 仅在 Runtime 为 `recovering`、当前 epoch 的 probe window 已 armed 且没有已保留 Probe 时为真；Probe 被保留或 window 关闭后立即回到 false，Host 不得从 timer、Context 状态或页面可见性推断 readiness。

`performance.live.control` 与 `performance.live.status` 的 Bridge 默认预算均为一秒，
从原始提交时刻计时，等待 Control dispatch 的队列时间也消耗该预算；显式 caller
cutoff 只能收紧它。Bridge 交给 Control 的是同一 absolute effective deadline，
不会在 dequeue 时重新获得完整窗口。`audio.activate` 的一秒 Control 预算和现有
输出设备启动阶段保持各自的起算边界；测试 helper 也使用原来的一秒激活预算。

Runtime Session 启动只运行一次真实 Control Worker/OPFS capability probe，默认等待预算为 15 秒。明确缺少 Worker/Blob、Worker 返回 negative 或 Worker error 继续 fail closed 为 `UNSUPPORTED_WEB_RUNTIME`；纯调度预算耗尽精确进入 `HOST_TIMEOUT`，不能伪造 `opfs`、`opfsSyncAccessHandle` 或 `opfsWritableReplace` 缺失。message、error 与 timeout 三条 settlement 路径都由同一 `finally` terminate Worker 并 revoke Blob URL。显式暂停期间 Project 操作保持禁用，Host suspend 响应与浏览器 Context suspend 严格串行。
## 7. 产品使用方
Creator Web 与诊断 Web Runtime Host 共用此 Platform；实际身份由 Build Identity 派生。历史 Platform `4.0.0` 把 `MAX_ASSET_BYTES` 保持为 1 MiB sidecar/chunk 边界，并以 `MAX_SAMPLE_IMPORT_BYTES` 接受 manifest 锁定的完整选区 WAV 总量；协议创建失败不再被误当成 quota/snapshot truth。Sequence UI 只展示 Facade 返回的 authority state；pending switch 在 Bar acknowledgement 前保持旧 Pattern，recovery artifact、长素材解码缓冲与 CaptureBuffer 都不冒充 Project Truth。master tap 采集到的 PCM 批次同样只是瞬态 Host 资源：Runtime Session 的 capture 配置由 manifest 锁定的 `perform_recording_frames` 与 `perform_recording_queue_batches` 派生，两者缺失或不是正整数时状态停留在 `unconfigured`；这些批次在被 Facade 提交为 Artifact 之前都不是创作真相。

## 9. 限制与下一门禁

Native manifest 回归直接采用当前生成的 `expected_assets`，不增删其角色，完成
初始化后检查 ready 与 Runtime 创建。对须含 worker 的清单验证缺失或重复均拒绝；
对不声明 worker 的清单验证额外 worker 拒绝 ready 与 Runtime 创建。
这些 Native 下层断言不替代浏览器启动、真实设备或离线更新验收。

全局 Pattern transport 的 T0 conformance 使用 Facade 独立执行线程：真实 OPFS
immutable write 在写入后、flush 前暂停时，同一 Control lane 仍完成既有 Bank
准备、live press/voice receipt、release 与状态查询；释放后检查完整落盘字节，
原线程销毁 writer lease，再由新执行线程重新获取并读取。测试暂停钩子和导出仅存在于
`LMDJ_WEB_AUDIO_CONFORMANCE` 构建。生产 ControlBridge 的串行 dispatch 和 OPFS
Asyncify 重入拒绝保持不变。

T3 起 Platform 向 opted-in session 提供公开的全局 Pattern transport 面：
`pattern.transport.request` 与 `pattern.transport.inspect` 两个操作经既有 serializer
与 bridge allowlist 进出，session 在 `createRuntimeSession` 以 `patternTransport: true`
显式 opt-in，并在 `project.open`/`project.create` 的 quiescent 点用 `pattern_transport: true`
标记完成协商；未协商的 session 请求一律 `HOST_STATE_INVALID`，legacy
`sequence.record.begin` 语义不变。request 绑定 session/project/command/epoch/intent，
返回 pending ticket（`submit` 为 `accepted`/`replayed`，附完整 status），dispatch tail
立即释放。每个 status 都带 `runtime_frame`，即 Host 读取 status 时 Engine 已渲染的帧数；
Session 把它规范化为 `runtimeFrame`，并以自身的 `performance.now()` 时钟记下收到的时刻
`observedAtMilliseconds`。Host 由此可以从任意时刻的观测推算播放位置，不必假定 transport
刚从 `origin_frame` 开始；continuation 由 bridge 的 service cadence 以短的 epoch-checked 步骤重入，
不在 tail 内等待 audio receipt 或长 IO。engine 的 Pattern 事件调度只在协商启用后
由 transport 门控，legacy 路径逐位不变。已 engaged 的 session 拒绝冲突的 legacy 直接写入
（`sequence.record.begin`、录音中的 `sequence.settings.update`），保证单一 journal owner。
live Pad press/release 在 enqueue 接受后的既有位置注入 admission 候选：watermark 从
coordinator 打开的窗口下界单调分配，release 复用其归属 press 的 watermark 作为
correlation；journaling 响应不早于 durable append，unknown enqueue 绝不自动重试。
录音的 preparation、audio receipt、journal settlement 与 committed Pattern publication
是四个分别持有的 completion（`publication_pending` 单独可见）。显式 Suspend、Project
替换与 Close 进入同一 shutdown barrier：acknowledged Pattern Stop → admission closure →
journal settlement 或 recoverable refusal → input release → 生命周期 effect；receipt 不到达的
unknown closure 使 Suspend fail closed，且未决 admission 原样保留，不允许 clean
replacement 声明。跨身份 `snapshot.reload`（或停止态 Pattern 切换）与 engagement 协调：
播放中拒绝（transport session 拥有 Pattern 选择）；其余情况先按需进 shutdown barrier
再注销 engagement，下一次 request 以当前 Pattern 重新 engaged；Engine stop 会抹除
transport generation 与未决 reservation，因此 Suspend 结算后 engagement 注销、每次
activation 在 quiescent 点重新武装端口，同 generation 内 epoch 单调递增、重新武装后从
1 重启（status 携带 runtime_generation 供页面识别）。同身份重发布保留 engagement；
其产生的 pending publication 应用前（Bar 边界）的 Record 得到可重试的
HOST_STATE_INVALID 拒绝，在 facade 写任何 journal 之前返回，绝不留下不可复用的
preparation。Host 端口还向 Facade 报告引擎当前 Pattern（`current_pattern()` 直通
Engine 的 `current_pattern_id()`）：playing 状态下已在 Bar 边界应用的 switch 使
engagement 的 vendored 绑定变陈旧时，下一次 Record 由 Facade 协调器先重锚绑定再开
journal（#1403），事件直接提交到引擎当前 Pattern，不再以确定性 fence 错配停驻
error phase；录制中（journal 活跃）永不重锚，跨 switch 结清仍由 close 机制拥有。

上述 T0/T3 历史证据只覆盖其原生 Host/bridge、Node Runtime Session 与真实 Chromium

### S6 Web 物理 writer 与 terminal receipt（修复源码）

Control 与真实 durable I/O child 使用同一 storage platform 的已取得 writer；本地授权
与物理持有分别记账。child 销毁 lease 只移除本 realm 的 exact token 并退还实际 pin，
不代理到正在等待 child join 的 Control。物理 owner 的 pending drain 保留 handle 和
独立的共享内存引用；总 pin 未实际退还、cleanup debt 未清或另一 realm 仍持有物理
writer 时，不能声明全部释放。

authenticated terminal channel 的 native authorization 是一次性的。Worker 记住实际
授权，`releaseAllWriters()` 的 false、异常或非严格 true 都保留 Worker／channel 并等待
真实 drain；临时 pending 不调用负 completion。严格 true 后仍需 native completion 的
实际正回执，才发布 terminal release receipt 并关闭。重复同 token 不启动第二个循环。
这不把 caller timeout、空 Control map 或 retained C++ lease 改写成物理释放。

原完整 Web 失败证据保留；这份修复源码和 Node VM 检查不证明 Wasm／OPFS、完整
Creator、真实 PCM 或物理／听感验收已通过。普通 storage close 的既有异常传播边界
也保留为真实失败，不在析构中吞错后声称 Host 已关闭。

## Authoring history control

`history.inspect`, `history.undo` and `history.redo` address only the open Project.
The JS session validates status and serializes restore requests with other Project

## Retained Asset assignment

`RuntimeSession.assignPad({commandId, expectedRevision, slot, assetId})` assigns
an Asset already retained by the open Project to an explicit flat Pad slot
`0..63` (A01–D16). It captures the complete caller-supplied identity before
waiting on the existing Project action and Host request queues. The Host wire
remains `pad.assign` with `{command_id, expected_revision, slot: {bank, pad},
asset_id}`, no sidecar and no caller path. The native route retains its existing
nullable Asset compatibility; the SDK's retained-Asset method requires a UUID.

Facade owns membership, revision, recording-owner admission and durable command
deduplication. Assignment keeps the source Pad and immutable materials. A different
Asset resets the destination's playback; the same Asset retains it. Destination
colour follows the existing Domain rule. A refused command stops no voice or
preview and publishes no snapshot. Confirmation before replacing an occupied Pad
and cancellation of an unsubmitted selection belong to the Creator consumer.

After a known commit, Control stops the destination's live voice and clears its
preview, prepares current Project Truth and publishes its Bank through exact
generation acknowledgement. If queued Host controls temporarily prevent Bank
admission, the existing publication boundary waits within the original absolute
request deadline and retries only that same unconsumed prepared Bank. It does not
cook again or resend the authoring command. Other publication refusals return their
existing typed failure. Bank admission and the exact new-generation acknowledgement
remain separate; admission timeout cannot stand in for a missing acknowledgement.
During replay the destination control preserves replay
and Pattern voices. The response retains `slot`, `asset_id`, `committed_revision`,
`replayed` and `project_revision`, and adds `runtime_revision`, `runtime_published`
and an optional typed `snapshot_error`. A publication failure after persistence
therefore remains a known commit; it cannot be presented as a cancelled assignment
with unchanged Truth. The original request deadline and running timeout safety
rules remain in force.

For Assign, successful publication has no `snapshot_error`; failed publication
requires a valid typed error. The SDK rejects a failed receipt with a missing or
malformed error. Existing Sample operations retain their separate no-prepare rules.

Bridge returns the real response before `snapshot.published` or
`snapshot.rejected`. An exact command replay after a later edit publishes the
current revision, preserving the old committed identity without undoing that edit.
The typed SDK validates target, Asset and publication authority, including after
queue delays, and rejects a closed or failed owner. A lost receipt is not retried:
inspection reveals current Truth, while an explicit caller retry must retain every
field of the original identity. The source Task plan
`docs/plans/2026-10-11-d03-assign-producer.md` tracks producer verification and
the separate Creator picker, browser and listening obligations.

## Pad deletion and cancellation

`RuntimeSession.deletePad({slot, expectedRevision})` cancels queued and active
imports for that slot before entering the shared Project action queue. A cancelled
Blob read no longer holds that queue; its eventual bytes are discarded. Control
stops the Pad and clears preview, delegates `pad.delete` to the Facade, removes
cancelled import handles and publishes the new Bank through exact-generation
acknowledgement. Responses retain the committed revision separately from Runtime
publication failure. Other Pad imports and their revision guards remain intact.

`RuntimeSession.editPatternEvents({patternId, expectedRevision, remove, put})`
sends flat-slot keys and events as `pattern.events.edit` through the shared
Project action queue.

Control refuses the edit before commit, with Truth unchanged and the edit
retryable, while:

- the Pattern transport records (`sequence_session_active`);
- a Pattern transport command is in flight (`pattern_transport_busy`);
- a scheduled Pattern publication has not yet applied at its boundary
  (`pattern_publication_pending`), and the edit would swap the playing Pattern
  in place, or the scheduled view is of the edited, not current, Pattern. A BPM
  change, an Undo, a Pad edit or a reload can schedule one. A stopped edit of
  the current Pattern is admitted: its immediate publication supersedes or
  follows the scheduled one.

Otherwise it delegates to the Facade. When the edited Pattern is the Runtime's
current one, Control then republishes only the Pattern view, without a Bank:

- **Stopped:** the view is replaced immediately (`publication: "published"`),
  so the next Play is not refused for a pending publication.
- **Playing:** the view is swapped in place with
  `publish_pattern_view_preserving_phase` (`"live"`). This keeps the origin and
  any sounding voices, so playback neither restarts nor waits for a bar, and new
  notes ahead of the playhead sound in the current loop.

Each swap takes a fresh engine Pattern slot, and a retiring view keeps its slot
while its voices sound. When every slot is held, the edit stays committed and
the swap is deferred (`"deferred"`). The service cadence reclaims slots and
swaps the view in place, prepared from Truth, as soon as one frees; a later edit
or any other Pattern publication supersedes the deferral. It waits while a
transport command is in flight or a recording is open, because a recording
admits no outside publication; the recording's own publications are prepared
from Truth and carry the edit, and once the recording closes the deferral
resumes. An audio interruption, which retires the transport engagement, does not
drop it. Nothing reports the deferral after the response.

Without the Pattern transport opt-in, legacy scheduling plays the Pattern
whenever audio runs, and Control has no transport state to tell it so. The edit
then takes the immediate path, which restarts the Pattern from its first bar,
and a full slot set is reported as a failed swap, since no service cadence
retries it. Creator always opts in.

An edit of another Pattern publishes nothing (`"none"`); that Pattern is
prepared from Truth when it is selected. A failed swap after commit returns the
committed revision with `"failed"` and `snapshot_error`. Because a grid edit
changes no Bank, a Runtime that was current before the edit, so that a
Bank-bound `sample.preview.set` is admitted, stays current after a successful
or deferred swap or an edit of another Pattern. A `sequence.settings.update`
(BPM, swing or quantize) changes no Bank either, and keeps a current Runtime
current the same way (#1805).

## Pattern length and copy

`RuntimeSession.resizePattern({patternId, bars, expectedRevision})`,
`doubleUpPattern({patternId, expectedRevision})` and
`copyPattern({sourcePatternId, patternId, expectedRevision})` send
`pattern.resize`, `pattern.double` and `pattern.copy` through the shared
Project action queue (#1823). Each call mints its own `command_id`.

The decision makes all three unavailable while playing, so Control refuses them
before commit with `HOST_STATE_INVALID`, with Truth unchanged, while:

- the Pattern transport records (`sequence_session_active`);
- a Pattern transport command is in flight (`pattern_transport_busy`);
- the Pattern transport plays (`pattern_transport_playing`). Unlike
  `pattern.create`, which only Creator disables while playing, the Host itself
  enforces this boundary.

A resize or double-up of another Pattern is refused while a scheduled view of
that Pattern has not yet applied (`pattern_publication_pending`), as for a grid
edit.

Otherwise Control delegates to the Facade. A resize or double-up of the
Runtime's current Pattern then republishes its Pattern view immediately, as a
stopped `pattern.events.edit` does (`publication: "published"`, `"deferred"`
or `"failed"` with `snapshot_error`), so the next Play loops at the new length.
A copy, or a resize or double-up of another Pattern, publishes nothing
(`"none"`). None of them changes a Bank, so a current Runtime stays current.

## Pad colour

`RuntimeSession.setPadColour({slot, colour, expectedRevision})` sends a flat
slot as `pad.colour.set` through the shared Project action queue; `colour` is a
palette index, or null to restore the category default. Each Pad of
`inspectProject()` carries the Core-resolved `category`, `colour_override` and
`colour` unchanged; the Session never derives a colour.

A colour changes no audio. Control admits it while the Pattern transport plays
and refuses it before commit, with Truth unchanged, while the transport records
(`sequence_session_active`) or a transport command is in flight
(`pattern_transport_busy`), as for a grid edit. It prepares and publishes
nothing: the playing view keeps its origin and generation, and a Runtime that
was current before the commit stays current after it. The result is
`{committed_revision, project_revision, replayed, publication: "none"}`.

## Performance replay authoring

Edits during a Performance replay follow the
[2026-10-02 decision](https://github.com/endaye/lmdj/blob/main/docs/prd/decisions/2026-10-02-performance-replay-authoring.md)
and its [2026-10-03 erratum](https://github.com/endaye/lmdj/blob/main/docs/prd/decisions/2026-10-03-performance-replay-authoring-erratum.md)
(#1789). Control tracks a replay this Host began from the
`performance.replay.begin`, `stop` and `status` results it forwards. Each
service cadence queries its status once; any state other than `playing`, or a
failed query, ends it. Project create/open first stops the replay through its
own Facade stop operation on the old Project, then replaces the session. The
new Project publishes its own view; reopening the old Project does not resume
the stopped replay.

While the replay plays, edits commit to Truth as usual, but no Pattern view is
published over the replay's:

- `pattern.events.edit` of the current Pattern returns `publication: "deferred"`;
- `pattern.resize` or `pattern.double` of the current Pattern also returns
  `publication: "deferred"`, and `pattern.copy` publishes nothing; the
  [2026-10-08 decision](https://github.com/endaye/lmdj/blob/main/docs/prd/decisions/2026-10-08-replay-pattern-structure.md)
  admits all three during a replay;
- a BPM or Swing change returns `pattern_publication: null`;
- Undo/Redo, a Pad edit's re-preparation and a reload publish the Bank only;
- a slot-full deferral from before the replay does not swap its view in.

Replay hits and the Pattern voices a replay launches carry their own material
and never read the engine Bank, so the Bank still publishes and live presses and
previews hear Truth at once. A Pad edit stops the Pad with `stop_slot_live`,
which ends only that Pad's live voices; the replay's voices keep sounding.

Once the replay ends, the service cadence restores the Host's selected Pattern
from Truth: at the next bar while the transport plays, as a Pattern switch does,
otherwise immediately. The restore waits while a transport command is in flight,
a recording is open, the transport reports an error or a publication is pending.
It is prepared from Truth, so it carries any deferred grid edit. While the
transport plays, a restore that finds every slot held waits until reclaim frees
one, and does not prepare again in the meantime. Any other refused or failed
restore clears `runtime_revision`.

Under the [#1801 decision](https://github.com/endaye/lmdj/blob/main/docs/prd/decisions/2026-10-07-performance-replay-command-handoff.md),
Play/Stop and Record first stop a playing replay, wait for its neutral-reset
confirmation, and restore the selected Pattern from current Truth before the
transport command runs. This restore applies immediately even when the replay
launched a different Pattern. The original request deadline covers the complete handoff; a failed
or timed-out stop prevents the command. Quiescent Engine Stop has already
cleared FX, so replay Stop can complete with audio suspended before Project
replacement. Replay and transport do not play side by side.


### S6 本地物理手势身份（修复源码，执行验收未完成）

已有 `trigger(slot, velocity, source, gestureKey?)` 和
`release(slot, source, gestureKey?)` 可携带同一个本地对象引用。该引用不检查内容、
不复制、不进入 Native wire 或持久化 Truth；只有已协商 input profile 才提供原
physical hold 的精确匹配。省略参数保留原调用兼容性，未协商 legacy Host 不获得
这项匹配保证。活跃或仍欠原 caller consume 的 key 不能复用；key／slot／source
不匹配不派发输入，也不会退回到最新同槽位输入。

未知 press admission 仍保留原身份并独立 inspect。SDK 在等待实际 sequence 之前
保留一个私有 Release intent，keyup／cancel／旧调用／safety 共享它和第一次 deadline；
intent 不代表 Native accepted、consume 或物理 ACK。已派发未知结果不重放；
真实已知 admission 拒绝后才允许后续新尝试。原一秒预算不因重复观察而重置。
真实 Release 消费与 press caller 消费分别欠账，只有真实消费／完整独立 retirement
回执可以各自结清。

Creator 的物理 key 生命周期独立于 Voice、视觉 token 和 loop latch。实际调用
trigger 后，即使已经 keyup，也立即按原 key 提交 Release，不等待 durable completion。
one-shot 自然结束或 loop-toggle 保持播放都不能抹去物理义务；Native 继续决定
这些模式的声音行为。未真正调用 trigger 的动作不制造 Release，dispose／adverse
cleanup 仍提交已调用输入的物理释放。false 不是消费 ACK，未知错误保留真实 SDK
owner。该修复保留原五秒开录与 300 秒 stress 预算及所有生产验收旅程。

本段描述待验收修复源码，SDK／Creator 单元回归不等于 Native／Bridge／OPFS／
全 Creator／听感通过。版本影响为未交付 S6 既有 Web Runtime Platform MINOR 债务，
不分配 Product Build 或改变 Native／持久化 Contract。

正常 close／suspend 已等待原 owner 时，丢失 admission 随后确认的匹配 profile
Release 只在 lifecycle 实际 handoff 后使用真实本地 retained press 续接，不排在等待它的 Host 请求后。原 runtime
短 admission 串行性与实际 handoff 一秒 deadline 不变；新输入与无关请求仍排原队列。


### S6 协商 profile 的恢复探针期限（修复源码，执行验收未完成）

恢复探针只绑定真实 Press。SDK 在等待 admission 前保留原 recovery epoch、
前台 epoch 和原调用开始时间；Release 不获得 probe 身份。只有仍有效的同一
probe 可以完成恢复或触发 SDK 失败。原一秒 deadline 到期会产生实际
`HOST_TIMEOUT`／`restart-required`，普通 running Pad 超时仍只拒绝原 caller、
继续保留真实 debt，不采用这项 probe 失败语义。

真实消费回复到达后，SDK 在成功通知和 running 转换前再次检查原期限；即使
timer 尚未执行，迟到回复也不能恢复旧会话。已失效 probe 的真实消费仍结清
原 ticket／physical debt，却不能覆盖新的恢复 epoch 或发布旧恢复成功。真实
voice-capacity 失败保留原错误码和失败 outcome。前台失效后迟到的 accepted
admission 仍保留原 owner，并提交真实 correlated Release，不制造取消或 ACK。

本段是独立恢复修复源码说明，不代表 packaged replacement 或完整 Creator
验收通过。版本影响为未交付 S6 的 Web Runtime Platform PATCH 正确性债务；
公开 API、Native wire、持久化 Contract 和 Product Build 均未改变。


### S6 普通 Record 准备期间的失败（修复源码）

失败后的真实 Native stop 不解除仍在 worker 中的原 prepare/preflight。普通
Record 在已知准备完成后得到真实 `not_running` 时，Facade 保留原 command、epoch
和失败，并经同一 worker 的真实 `owner_lost` 读取/持久化结算后继续 shutdown。
没有已开始录音的 S/F 或 opening 成功收据；未知结果与拒绝仍保留责任。

Host 继续要求实际 callback-last-use、Native stopped、executor owner 释放及
原 Bridge response/consumer release。独立 writer acquisition、完整 Truth/Artifact
reopen 和浏览器 OPFS 回执不能从逻辑 idle、计时器或单个 stopped 值推断。
该私有结算不新增 wire/DTO/vtable 或 Product 身份；源码与当前运行验收分开记录。


### S6 重复 close 的真实清理等待（修复源码）

### S6 replacement 的正向清理屏障

Session 的本地消费 API `waitForTerminalCleanup(): Promise<boolean>` 观察
同一实例已经发起的真实 terminal cleanup，不发起第二次 Stop 或 terminator。
只有原 caller/input 消费、Native full-owner 释放、真实后台关闭及 SDK 节点与
监听器清理全部完成才返回 true；未知工作继续等待，失败不授予替换资格。
清理尚未发起或已拒绝时返回 false，不因观察而启动清理；绑定完成 Promise
先于可能重入的 terminator、按键状态与诊断回调。原 close 的 false/fatal 结果与最早错误仍保留，
缺少 getter、transport sealed 或自定义 terminator 已 resolve 都不是释放回执。

部分加载失败只清理原调用通过私有 Module 配置登记的本地 Host；变化的全局
Host 不证明归属。实际 pre-js 在发布前通知原配置，SDK 核对同一 Module。默认
packaged loader 在首次 await 前串行保留同一窗口的 Module 注入，重叠加载
拒绝，直到原调用真实结束才释放保留；这仍不是物理 owner 的释放回执。

此新增 API 另欠下一协调结算的 Web Runtime Platform MINOR；Creator 消费
修复欠 PATCH。本段不分配身份，当前 packaged recovery、完整 Creator 与
真实 OPFS/PCM/物理验收仍需各自原始旅程证据。
