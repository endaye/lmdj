## 1. 目的与非职责
把 Project Truth 和 Artifact 确定性派生为 Runtime Snapshot；不保存 Project 或执行实时输出。
## 2. 当前实现状态
Project Cooker 可从 Project v5 tick-native Pattern、Pad playback 与 PCM16 Artifact 确定性生成 Runtime Snapshot；WAV inspect/decode、真实 peak waveform、44.1→48 kHz resample 与确定性矩阵已实现。本版新增一条纯附加的 Performance replay 投影：`cook_performance_replay(project, performance_id, resolve)` 返回不可变的 `PerformanceReplayProjection`，字段恰为 `performance_id`、`resolved_revision`、`bpm`、`quantize_enabled`、`swing_percent`、`pads[64]`（resolved Pad）、`patterns[16]`（每个 Pattern Slot 一份 Runtime Snapshot）、`boundaries`（`offset_tick` + `PerformanceEvent`）、`event_count` 与 `initial_live_state`（`5.4.1` headered profile 的录音起点，缺席即旧 profile）。header 随投影原样携带：零事件的 Performance 同样恢复起点，且它不随首事件 tick 归一化移动。headered profile 的 boundary 按 `(tick, input_sequence)` 展开，旧 profile 的排序不变。既有 Cook surface 的形状与语义不变。
## 3. 所有权与依赖
依赖 Foundation 与 Authoring Domain，不依赖 Host 或 Product Assembly。
## 4. 架构与数据流
resolved playback 同时填充 voice DSP 块：循环点与 crossfade 以与 trim 起点相同的向下取整换算到 48 kHz，舍入溢出被夹回解析后的循环之内，reverse 与 ping-pong 成为标志，pitch 与 pan 原样携带；trim 末端开放时，crossfade 被限制为以源末帧结束的循环的一半。#1667 的 attack/release 毫秒乘 48 成为输出帧（one_shot 从不播放 release，其 release 解析为 0），tone 在 ±2 死区内解析为 0，EQ 保持 Project Truth 的单位，并以存在位与 cut 位标记各段。

不带 voice DSP 构建时（`LMDJ_VOICE_DSP=0`，即 Cardputer），块为空。Cooker 恰好接受解析为中性块的设置，其余以 `Pad playback voice settings are not supported by this build` 拒绝；无效设置仍先报告为无效。`project_cooker_test` 与 `audio.voice_dsp_disabled` 共用同一张中性表，保证两种构建对同一 Pad 的判断一致。Runtime Content v1 encoder 的 `voice_dsp` 拒绝同样覆盖包络、tone 与 EQ。

验证 Slot/Asset/playback 引用和 source-frame admission，读取不可变 WAV Artifact，生成多层 peak envelope 与 48 kHz PCM，输出不可变 prepared snapshot。replay 投影走同一条确定性路径：以 Project Truth 中的 Performance 与 `pattern_slots` 为输入，逐 Pad Slot 解析 playback、逐 Pattern Slot 生成 Runtime Snapshot，并把 Performance event 展开为带 `offset_tick` 的 boundary 序列。
## 5. API 与 Artifact 边界
Artifact 输入显式传入；inspect/waveform 不修改 Project，Cook 输出 resolved playback、Runtime Snapshot 或 privacy-safe typed error。

`WavMetadataInspector(total_byte_length)` 通过 `feed(span)` 按顺序消费连续窗口，
`finish()` 仅在完整输入和合法末端边界后返回现有 `WavMetadata`：sample rate、channels
与 data chunk 的 source frames。它只保留16字节头部缓冲和固定数量状态，不保留输入
view、PCM 或未知 chunk 的 payload；成功解析不分配 heap。空窗口无副作用，错误和
提前 finish 均为 sticky failure，额外输入也拒绝。现有 `inspect_wav(span)` 使用同一
检查器，元数据检查不再为整段 PCM 分配内存；`decode_wav` 的解码行为保留。

格式仍为严格 RIFF/WAVE：精确 RIFF 长度、chunk extent 和奇数 padding、唯一16字节
PCM fmt 与唯一非空 data、PCM16 mono/stereo、44.1/48kHz、准确 byte rate 与完整 frame
alignment。支持 data 在 fmt 之前和未知 chunk。元数据不来自总文件字节、event cursor
或未读完的头部提示。此 API 仅解释完整输入的格式；Artifact 摘要、owner 和 revision
须由 Project I/O 扫描的最终回执证明。保存完整性和演出 elapsed 仍是独立事实。

当前 source 追加 `encode_runtime_content` / `decode_runtime_content`，处理
`contracts/runtime-content/README.md` 所定义的确定性 little-endian 派生内容。编码保留单个 Pattern、
Pad playback 和未压缩 PCM16；按包含格式描述的 sample body 完整身份去重。解码先验证
完整内容身份、精确版本/能力、表顺序与引用、全部 sample body、playback 和调用方限额，
再构造自有 PCM 的不可变 Snapshot。`RuntimeContentLimits` 的零值是零额度，不是无限。
这不是 Project parser、实时回调 API 或设备的 Engine/FX/DMA 总内存预算。

`inspect_runtime_content` 与 decode 共享完整校验器，在分配 PCM 或 count-sized 表前
返回 encoded/unique PCM/per-Pad float 字节、最大 float 临时样本及 Pad/event/sample
数量。`runtime_content_types.hpp` 单独提供纯值身份/额度/footprint，窄 Facade 公共
头不必暴露 Runtime Snapshot。inspection 不跳过摘要、规范顺序、能力或引用检查；
输入在调用期间必须保持有效且不可变。摘要 hex 转换使用一次固定大小 string 分配，
分配异常直接传播到失败边界，不通过可能吞掉异常的流返回截断身份。
这些兼容追加不改变 wire Contract 版本，完整 Engine/准备/平台资源 admission 属于
Runtime Facade，真实设备内存仍须测量。
## 6. 状态、错误与生命周期
相同输入必须产生相同结果；快照与 Project 生命周期分离。`PerformanceReplayProjection` 同样只是派生状态：它由 Cook 现算、随消费者生命周期释放，绝不是 Project Truth，也绝不被持久化或回写创作真相。
## 7. 产品使用方
Audio Runtime 与 Application Facade 消费 Cook 结果。
## 8. 测试与证据
`project_cooker_test.cpp`、`sample_analysis_test.cpp` 和 `determinism_matrix_test.cpp` 覆盖格式、边界、waveform cache identity、resample 与相同输入相同输出；`performance_replay_projection_test.cpp` 覆盖 replay 投影的字段解析、Pattern Slot 解析与 boundary 展开，并覆盖 `5.4.1` header：零事件存活、独立于首事件 tick、revision 与素材身份固定。`wav_selection_test.cpp` 覆盖选区语义。
## 9. 限制与下一门禁
`wav_metadata_inspector_test.cpp` 覆盖任意 split、单字节复用窗口、严格格式错误、
截断/额外输入、sticky failure 和30分钟静音的固定窗口零 PCM 分配；保留原 decoder
作为格式比较，并用独立字面 rate/channels/frames 约束共同计算错误。真实 C++/Wasm/
OPFS 组合覆盖多窗口静音、odd JUNK、已校验但不支持的编码和末字节摘要错误，各自
关闭页面并重开两次。Facade/SDK/Host 的异步查询、取消与 owner retirement、Take
时长展示仍待；该检查器不应作为长时间同步 Control 查询接入。

`runtime_content_test.cpp` 和独立 `runtime_content_contract_test.py` 覆盖固定字节、
跨实现读取、exact/+1 限额、异常字段与分配失败。新 Contract 尚未选择到 desktop
Assembly；新增兼容 API 的 MINOR 分配与消费者 lock 留给 B2 Assembly 集成。

增量 Cook 和分布式 Cook 不属于当前能力。replay 投影只提供确定性派生素材，不承担实时调度、听感或物理演奏验收。

## Bounded Slice materialization

`select_pcm16_wav` materializes a nonempty half-open interval from a source bounded
to 16 MiB. It validates PCM16 mono/stereo at 44.1 or 48 kHz and emits an independent
WAV preserving channel samples and source frame rate. The existing stereo-only
selection API retains its original restriction. Runtime preparation can subsequently
resample using the existing rules; materialization itself does not resample or write
Project state. The WAV selection unit test covers both profile rates/channel counts,
exact PCM intervals, the byte bound and malformed/range refusal.


## Empty Pad events

A valid Pattern event targeting an empty Pad remains in Project Truth but is
omitted from the derived audible events. Reassigning that Pad makes the existing
rhythm resolve against the new binding. An assigned Pad with a missing Asset,
corrupt bytes or invalid playback still fails Cook; silence is specific to an
unassigned Slot, not a fallback for damaged references.
