## 1. 目的与非职责
维护 Project Truth、序列与命令语义；不执行存储、Cook、音频或 Provider 调用。
## 2. 当前实现状态
Authoring Domain 以当前 Project Contract 为领域真相：每个 Pad 的完整 playback value、PPQ 960 tick-native Pattern event、BPM/Quantize/Swing，以及 assign/update/reset/replace/create-pattern 命令语义继续有效；v1/v2/v3/v4 只作为迁移输入。v4 额外定义两块权威结构。其一是 `pattern_slots`：恰好 16 项的定长数组，每项是 Pattern UUID 或 `null`，构成可发射（launchable）的 Pattern 地址空间；`AssignPatternSlot`/`ClearPatternSlot`/`MovePatternSlot` 是其命令语义，同一 Pattern 不得同时占用两个 Slot，Slot 也不得引用不存在的 Pattern。其二是 `performances`：每个 Performance 由 `performance_id`、`name`（1..64 字符）、`created_bpm`（40..240）、`recording_revision`（>= 0）、`recording_artifact`（artifact_ref 或 `null`）与 `events` 组成。`performance_event` 是恰好七种的封闭 union：`pad_hit`（`slot` 0..63、`onset_tick`、`duration_tick` >= 1、`velocity` 1..127）、`pattern_launch`（`pattern_slot` 0..15、`effective_tick`）、`fx_engage` 与 `fx_move`（`fx` 0..7、`value` 0..1000、`tick`）、`fx_release`（`fx`、`tick`）、`hold_on`、`hold_off`。v4 同时承载 Asset Lineage：`asset_lineage` 的 `source` 与 `derivation` 各是一组由常量 `kind` 判别的封闭并集，`source` 记录 source Artifact 或安装来源的 Sound Set 槽位，`derivation` 记录带帧范围的 resample 或空负载的 `soundset_install`。新的 `CapabilityAdoptionLineageDerivation` 是第三个封闭派生变体：能力、Provider、可空 model、原始参数摘要、Attempt、源 Asset、输出 Artifact 和 `SliceIntervalRecipe` 都是必需 evidence。它只搭配 asset_artifact source，并验证 Slice 身份、摘要、UUID、非空区间和已批准帧率；不依赖 SDK 对象或存储路径。`create_project` 产出当前 v5 Contract；命令不能降低现有 Contract。
## 3. 所有权与依赖
Core/产品共同维护语义，仅依赖 Foundation。
## 4. 架构与数据流
Pad playback 另有六个可选的 `lmdj.project.v5` `5.1.0` 字段：reverse、pitch_cents（−2400..+2400）、pan（−100..+100）、loop_mode（forward / ping_pong）、loop_start_frame 与 loop_crossfade_frames，缺省值即此前的行为。范围、循环点位于 trim 内、ping-pong 不带 crossfade、forward crossfade 不超过循环的一半，统一由导出的 `is_valid_playback` 校验，命令处理与撤销增量的内容校验共用它；trim 末端开放时，crossfade 上限由知道源长度的 Cooker 判定。`5.2.0` 再加四个可选字段：attack_ms（0..2000）、release_ms（0..4000）、tone（−100..+100）与 eq。eq 的 low、mid、high 三段都可缺席，缺席即旁通：low 为 `{kind: shelf | cut, freq_hz 20..2000, gain_millidb −18000..+18000}`，mid 为 `{freq_hz 100..10000, gain_millidb −18000..+18000, q_milli 100..10000}`，high 与 low 同形、freq_hz 为 1000..20000。缺省值即此前的行为，同样由 `is_valid_playback` 校验。

命令进入 Handler，经 `expected_revision` 验证后产生新的权威创作状态；playback 属于 Pad Slot，Pattern event 只引用 Pad Slot。整数 quantizer 是唯一量化与 Swing 权威。Performance event 沿用同一间接层：`pad_hit` 只引用 Pad Slot，`pattern_launch` 只引用 Pattern Slot 序号，两者都不直接引用 Asset；tick 仍是 PPQ 960 tick-native，不引入墙钟时间。Performance 的 canonical 事件顺序由领域自身定义，Host 不得自行重排。
## 5. API 与 Contract 边界
领域对象遵循 当前 Project Contract，不接受 Host 私有 JSON 形状；v4 顶层必需键为 `contract, project_id, revision, bpm, sequence_settings, banks, assets, patterns, pattern_slots, performances`。v1/v2/v3/v4 只是只读迁移输入，migration 不重新解释已退休字段，也不为旧 Contract 追加 Performance 或 Pattern Slot 语义。
## 6. 状态、错误与生命周期
Project Truth 可演进但不包含 Runtime Snapshot、Provider 选择或 Attempt failure。Performance 与 Pattern Slot 属于创作真相；Performance 的 replay 投影、实时 FX 状态与录音会话进度都是派生或瞬态状态，不回写领域模型。
## 7. 产品使用方
Project I/O、Project Cooker 和 Application Facade 使用领域模型。
## 8. 测试与证据
`project_test.cpp`、`command_handler_test.cpp`、`model_sequence_test.cpp` 覆盖 playback defaults、四模式、边界、冲突与 revision，`command_handler_test.cpp` 另覆盖 Pad 颜色命令、各换素材命令对覆盖色的保留与清除、颜色解析优先级与标签→类别映射；`performance_test.cpp` 同时验证 Slice lineage 完整 round-trip、显式 null model、每层缺失/额外字段和无效证据，并覆盖七种 event 的边界与封闭性、Pattern Slot 校验与 Performance 字段约束，`migration_v4_test.cpp` 覆盖 v1/v2/v3 → v4 迁移。
## 9. 限制与下一门禁
通用 Undo/Redo、协同编辑、Time-stretch 与 Artifact GC 不在当前实现声明内。领域层只定义 Performance 的结构与取值域，不声明任何听感、设备或物理演奏验收。
## 10. 版本身份
版本和依赖由模块清单及 Assembly Lock 生成。

## Candidate adoption command

`AdoptCandidates` is a named atomic command and `apply` overload; the existing
`Command` variant is unchanged. Its Project ID, expected revision, source Asset
ID and full ArtifactRef bind every assignment. Validation rejects empty or duplicate
Pad targets, reused Asset IDs, invalid lineage, and mixed analysis identities before
copying state. All assignments create independent Assets, reset target playback,
retain source Assets and increment one revision in the current Project Contract.
Source lineage retains the analysis revision. This command has no public receipt
replay semantics; a stale revision remains a conflict.

## Session authoring deltas

`AuthoringDelta` records typed before/after values for Pad slots, Assets and lineage,
Patterns, Pattern Slots, Performances, BPM, Quantize and Swing. Applying a delta
checks its prior values and the resulting domain invariants atomically. Undo uses
the inverse; Redo uses the same original delta. Both generate a new increasing
revision and preserve Project identity and Contract. Composition folds internal
recording commits into one user action. Domain owns no history stack or audio bytes.
`domain.authoring_delta` verifies round trips, changed-value conflicts, composition,
object coverage and refusal without partial mutation.


## Pad deletion

`DeletePad` clears one Pad binding and restores default playback through the same
checked command semantics as `AssignPad` with a null Asset. Patterns continue to
reference the same Pad Slot; Assets and Artifact identities are retained. Invalid
slots, stale revisions and command collisions keep their existing refusal rules.

## Pattern event editing

`EditPatternEvents {pattern_id, remove, put}` is the Sequence grid's atomic edit
(#1671). One checked command removes every keyed event, then inserts or replaces
each `put` event by key, and canonicalises the Pattern. The key is
`(bank, pad, onset_tick)` (SR-D26).

- A move is a removal plus a put at the new key.
- A length or velocity change is a put at the same key.
- Notes at different onsets may overlap.

It refuses, without changing Truth:

- an unknown Pattern (`pattern_not_found`);
- a removed key that does not exist (`pattern_event_missing`);
- a key repeated within `remove` or within `put` (`pattern_edit_duplicate_key`);
- an empty edit (`pattern_edit_empty`);
- an event outside the Pattern or across its loop seam;
- an edit whose result equals the current Pattern (`pattern_edit_unchanged`), so
  a no-op never becomes a revision.

## Pattern length and copy

Three checked commands change a Pattern's length or copy it (#1823), as the
[2026-10-08 decision](https://github.com/endaye/lmdj/blob/main/docs/prd/decisions/2026-10-08-pattern-length-and-copy.md)
records. Lengths stay 1, 2, 4 or 8 bars, so `lmdj.project.v5` is unchanged.

- `ResizePattern {pattern_id, bars}` sets the length to `L = bars × 3840`
  ticks. Lengthening keeps every event, so the added bars are empty.
  Shortening removes each event with `onset_tick ≥ L` and truncates the rest to
  `duration_tick ≤ L − onset_tick`, so no note crosses the loop seam.
- `DoubleUpPattern {pattern_id}` doubles the length and repeats each event at
  `onset_tick` plus the old length.
- `CopyPattern {source_pattern_id, pattern_id}` adds `pattern_id` with the
  source's length and events. When the source holds Pattern slot `s`, the same
  commit assigns the copy to the lowest empty slot after `s`. When no later
  slot is empty, or the source holds no slot, the copy holds none.

Each follows `apply_checked`: a replayed `command_id` returns its receipt and a
stale revision conflicts. The receipt event carries the resulting `bars`, or
the copy's `pattern_slot` (`null` when it holds none). They refuse, without
changing Truth:

- an unknown Pattern or source (`not_found`, `pattern_not_found`);
- a length other than 1, 2, 4 or 8, or an id that is not a lowercase UUID;
- a resize to the current length (`pattern_length_unchanged`), so a no-op
  never becomes a revision;
- a double-up at 8 bars (`pattern_length_maximum`);
- a copy id that already exists (`duplicate_id`).

## Pad colour

Each Pad has one effective colour, an index into a fixed five-colour palette
whose order is persisted and never changes: 0 DRUMS `#F3B580`, 1 BASS `#DFF779`,
2 MELODIC `#B49DE8`, 3 VOCAL `#94D2DC`, 4 TEXTURE `#E6ED98`.

- `Asset.category` is an optional `drums | bass | melodic | vocal | texture`
  that describes the sound. Absent means unclassified.
- `PadSlot.colour` is the user's optional override as a palette index. It
  exists only while the Pad holds an Asset.
- `effective_pad_colour` is the one rule: the override, else the index of the
  Pad's Asset category, else `null` (neutral). Hosts never recompute it.

Sound Set roles map by meaning: `kick`, `snare`, `clap`, `hat_closed`,
`hat_open`, `perc` and `cymbal` to drums; `bass` to bass; `melody` and `chord`
to melodic; `vocal` to vocal; `fx` to texture. `other` stays unclassified.
`map_soundset` carries each slot role's category on its proposal so the
installed Asset records it. Stem labels map `drums`, `bass` and `vocals` to
drums, bass and vocal; `other` stays unclassified. Imported, recorded,
resampled and Slice-adopted Assets are unclassified, and existing Assets are
never backfilled.

`SetPadColour {slot, colour}` is a checked command with its own `apply`
overload. A `null` colour removes the override, so the Pad follows its
category again. It refuses, without changing Truth:

- an empty Pad (`pad_empty`);
- an index outside the palette (`pad_colour_out_of_range`);
- the current value (`pad_colour_unchanged`), so a no-op never becomes a
  revision.

The override follows the Pad across asset changes. `AssignPad` to another
Asset, `ImportAssignSample`, each Pad an `InstallSoundSet` writes and
`AdoptCandidates` keep it. `AssignPad` to `null` and `DeletePad` clear it. A
Sound Set `keep` leaves an occupied Pad untouched, override included. Reading
and writing both fields in Project files and history belongs to Project I/O.
