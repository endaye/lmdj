## 1. 目的与非职责
准备样本、调度 Pattern/Pad 事件并离线或实时渲染；不修改 Project Truth。
## 2. 当前实现状态
Audio Runtime `3.1.0` 已实现 Prepared Sample Bank、per-Pad playback、四种触发模式、Voice state、Realtime Engine、Offline Renderer，以及整数 BPM transport anchor、Bar-boundary notification 和 Pattern origin。Prepared PCM 不再设置单 Pad 帧数上限：64 个 Pad Slot 各自持有独立的可变长 `std::vector<float>`，每个 16-Pad user Bank 使用独立字节账本，同时受 generation 总账本约束；无需 PCM arena 或 offset table。resident bytes 由 publication owner 另行核算。当前 source 以 32 位 atomic slot-token mailbox 线性化 immutable Pattern publication：control 只取代尚未被 callback claim 的同 Project/Pattern/next-Bar view；不同 Pattern 默认拒绝，只有同时匹配 pending generation、源 Pattern 与 activation frame 的 Sequence switch/Stop authority 才可替换或取消。已 claim 的 view 保留原 boundary，较新的 view 从 claimed activation/BPM Bar length 重算到下一 Bar；slot token 的 bit 31 表示 claimed，完整 64 位 generation 保存在不可变槽内；保留原有 2^63 耗尽边界并 fail closed，不循环复用外部身份。实时线程只消费不可变 Runtime Snapshot 与固定队列，不执行 quantization、Project mutation 或 journal I/O。本版新增固定八段 master FX 链：`kFxChainOrder` 的顺序恒为 filter → delay → reverb → stutter → gate → reverse → crush → cutter，每段状态是 `{value, engaged, frozen}`，链级另有一个 HOLD 位冻结全链当前形态。所有 FX 取值共享 0..1000 的整数值域（`kMasterFxValueMaximum = 1000`）。`MasterFxChain` 暴露 `prepare / reset / set_bpm(bpm) / apply_gesture(FxGesture) / process(left, right, frames)`；stutter、cutter 与 delay 的周期全部由 `master_fx_bar_frames(sample_rate, bpm)` 与各自的 divisor 表从 Bar 推导，因此 FX 时值跟随整数 BPM transport anchor，而不是墙钟时间。`RealtimeEngine` 相应新增 `prepare_master_fx(bpm)`（控制线程、quiescent，一次性分配全部 FX 渲染存储）、`enqueue_fx_gesture`/`enqueue_master_fx_tempo(bpm)`、有界的 `MasterFxControlKind {gesture, tempo}` 控制通道、`FxEnqueueResult`（`accepted`、`invalid_fx`、`invalid_value`、`invalid_bpm`、`not_prepared`、`not_running`、`queue_full`）与 `master_fx_telemetry()`、`master_fx_processed_frames_`。既有实时不变量完全不变：实时回调仍不分配、不加锁、不修改 Project、不做量化、不做 journal I/O；FX 缓冲在准备阶段一次分配完毕，手势与 tempo 只经由有界控制通道到达。
## 3. 所有权与依赖
依赖 Foundation 与 Project Cooker；平台输出位于适配边界。
## 4. 架构与数据流
Runtime Snapshot + 可选 pending overlay → immutable Prepared Pattern slot → atomic32 slot-token mailbox claim → fixed SPSC control 与 Voice-state/Bar-boundary 队列 → Bar-boundary apply → master FX 链 → 输出 sink；preview、overlay、transport anchor 与 master FX 状态只属于 Runtime，不进入 Project Truth。FX 手势与 tempo 更新走同一条独立的有界 master FX 控制通道，与 trigger/control 通道同为单生产者单消费者；tempo 更新与手势保持顺序，并在下一个渲染量子边界生效。
## 5. API 与 Artifact 边界
消费不可变快照、resolved playback 与已准备样本，不在实时回调解析 Project/WAV、分配内存、加锁或调用 Host。`kRealtimeMaximumSampleFrames` 明确实时样本、playback 与 Voice-state 共用的无符号 32 位帧域；批准的 16,777,216 帧单 Pad 在 trim、loop、ramp 和事件回报中不发生中间收窄。master FX 只接受 trivially copyable 的 `FxGesture`（`kind` ∈ engage/move/release/hold_on/hold_off、`fx`、`value`），不接受 Project、Performance 或 Host 对象；`MasterFxTelemetry` 只回报 enqueued/dequeued/queued gesture、queue drop、processed frames、tempo 更新计数与 current BPM，不回报创作真相。
## 6. 状态、错误与并发
atomic32 claimed marker 管理 callback ownership，外部 authority 仍校验完整 generation、Pattern identity 与 activation frame。音频通过 RMW 的即时前值取得槽位；控制替换或取消与 claim 以原子转换决胜。已取消的 audio-owned 槽仍由音频本地 entry 保护，待音频释放后才能由控制线程回收，避免槽号复用造成 ABA。音频在 claim 前单方关闭控制写入 admission，完成交接后重开；控制只在非实时路径重新观察并重算 boundary，音频不等待控制确认。不同 BPM 的 claimed view 仍是后续 boundary 的 transport authority。固定 SPSC 队列和压力测试覆盖 control/Voice 并发，旧 Pattern slot 只由 control thread reclaim，callback 不析构 view，overflow fail closed，实时路径避免无界工作。`pending_publications` 显式计数 audio-owned A 与同时 queued B 两个不同 generation；每个 accepted Pattern publication 恰好落入 applied、superseded、canceled 或 pending。取消后的 audio-owned slot 后续被 callback 回收时不会重复计为 superseded；quiescent `stop()` 将 queued-only、audio-owned-only 或两者各计一次 canceled，且这些累计 counter 跨 `start()` 保留。deterministic race hooks 只存在于 private testable library；production archive/callback 无 hook symbol、marker、pointer atomic 或 branch。master FX 沿用同一纪律：控制线程是 FX 控制通道的唯一生产者，队列满时确定性返回 `queue_full` 而非阻塞或增长；`prepare_master_fx` 之前 enqueue 返回 `not_prepared`，未运行时返回 `not_running`。BPM 更新只改变周期推导的 rate，不在实时线程重新分配缓冲。
累计计数、帧位置与 epoch 保留 64 位。音频、控制各自发布固定三缓冲值快照；多个非实时遥测读者只在读者之间互斥，音频完全不接触该锁。调度使用独立的 control-only transport 读取通道，在原 callback 起始前沿与 Pattern origin 交接点发布，不被遥测读者占用。Pattern 遥测只读取值副本，以认领前沿和精确取消身份排除已应用／已取消的旧 pending 记录，不读取可回收槽。所有相关写操作静止并与读者正确同步后，最终统计精确，无需再来一次 callback；运行中跨域仍是 best effort。`start/stop` 沿用 callback 排空要求，不能只看 stopped；交接时正常发布新值，不重置读者可能仍持有的三缓冲槽。输入和 FX 占用以 32 位原子保留原先的预留／回滚顺序，上界包含队列 1024 项及各一项在途生产者、消费者，合计 1026。64-Pad mask 保持完整 64 位，由 Bank pending-zero 的 release/acquire 交接保护。

发布按 current/pending/retiring/reclaimable 状态转移：实时线程只读不可变 Bank，最后一个 Voice 结束后才允许控制线程回收。publication owner 按 reclaim → reserve → publish 顺序核算 live、pending、retiring bytes。准备阶段按剩余字节的较小约束判定失败，约束相等时稳定返回 Bank failure；Bank、generation 与 transient residency 三类失败不互相冒充。Web Audio 的每个有效 callback（包括 paused callback）以 lock-free `uint32` heartbeat 表示活性；Browser Main 在 `AudioContext.resume()` 后必须先观察 heartbeat 前进，才请求打开 realtime gate。激活只在 accepted generation 已成为 current 且无 pending publication 时开启 gate；激活前锁存的 generation 由首个 open-gate callback 精确确认，避免 stop/start 或 suspend/resume 把旧的非零 acknowledgement 当作当前 Bank。
Voice-state ring 内部使用自然对齐的紧凑 cell，入队／出队按字段复制，保留公开
`RuntimeVoiceStateEvent` 的成员顺序和完整 64-bit sequence/runtime frame、32-bit
source frame。默认容量仍为 10,240；SPSC 索引与内存序、满队列损坏状态、拒绝新
Voice 和 fail-closed drain 语义不变。当前队列存储在 Engine 构造时独立分配，
不是 render 中的动态扩容。`RealtimeEngine` 的 C++ 对象大小变化要求所有二进制消费者一致重编；
公开事件 ABI 不变不代表 Engine ABI 不变，后续 Package 分配须处理 MAJOR 影响。

## 7. 产品使用方
Native Host 与未来正式平台 Host 通过 Facade/适配层使用。

### 显式 Pattern transport 与 cutoff 回执（A1 source）

`enable_pattern_transport(generation)` 在 quiescent、`start()` 前选择显式模式；
runtime generation 在同一个 Engine 对象的 enable 调用间非零、严格递增；
耗尽时需要新 Engine，不要求不同 Project、进程或 Engine 之间全局排序。
默认调用方仍在 Engine start 后自动调度。
显式模式中 Engine running 与 Pattern playing 分离：start 后保持 Pattern stopped，
只有 `submit_pattern_transport` 的 start 在音频边界 F 生效后才开始调度。
该 start 设置 origin=F、cursor=0，无 count-in；既有 96-frame attack 保持不变。
stop 在 F 的调度前关闭 Pattern playing，并按既有 96-frame release 结束
Pattern-owned Voice。live Pad 与非 Pattern replay 保留各自 release 所有权；
replay 使用原 scheduled release。fence 保持 playing 和 origin。

串行控制 owner 提交 `PatternTransportCommand`，携带 runtime generation、epoch、
expected Pattern generation、start/stop/fence，以及可选精确 pending-switch authority。
首个 epoch 为 1，随后严格递增，耗尽拒绝。重复 start、stale identity 与非法 action
拒绝，不解释成 toggle。单个 outstanding command 与单个 retained receipt 使用
固定 SPSC cell；`PatternTransportCommandCell`/`PatternTransportReceiptCell` 均为 POD，
字符串与完整 authority 只在控制侧保留。保留期间 publication、cancel 与 reclaim
暂停，后续 command 返回 busy。inspect/acknowledge 也是串行控制方法，不是 observer API。

stop/fence 在首个能消费命令的非空 callback 边界 F、publication claim 前，由音频
owner 对命令命名的 switch 作出决定：实际应用 S&lt;F 保留，未应用（包含 S=F）取消。
已越过本 callback 消费点的命令取下一 callback 的实际 F；不会倒填 requested frame。
`inspect_pattern_transport_receipt(generation, epoch)` 返回不可变历史值：F、origin、
Pattern identity/generation/BPM、playing、完整 switch authority、cutoff decision，
以及已经应用时的实际 S。延迟读取不改写决定。

调用者须先保存完整回执，再 `acknowledge_pattern_transport_receipt` 释放 reservation。
该 API 只转移 RAM 保留责任，不提供 crash durability；录制 coordinator 必须先持久保留
未决 fence 结果。quiescent Engine stop 使 runtime generation 失效，下一次 start
清空旧命令通道并保持 Pattern stopped，接受新命令前必须重新 enable 新 generation。

A1/A2 尚不提供 Facade 六转换、journal durability、Runtime bridge 或 Creator
全局 opt-in。新增公开 API 与 Engine 内嵌存储改变 C++ 对象
布局：这是 staged ABI break，不能作为旧 ABI 二进制替换。按集成裁定，本 source slice
不改 manifest/Assembly；任何 package/team-test Build 分配前必须完成下一 Audio Runtime
MAJOR 身份分配、coherent 静态消费者重编和匹配的 Assembly 流程。

### 保相位替换与持续 Voice（A2 source）

串行控制 owner 调用
`publish_pattern_view_preserving_phase(PreparedPatternView&&, expected_generation)`，
要求非零 expected generation 精确匹配 current publication，并保持相同
Project、Pattern、BPM、PPQ 与 loop length；不匹配返回
`PatternPublishResult::phase_mismatch`。PreparedPatternView 的准备边界本身也拒绝
非 canonical PPQ。Project revision 和事件内容可以变化，支持 journal overlay
与提交后的 canonical replacement。既有 publication 方法与默认启动语义保留。

替换在音频实际取得 publication 后的首个有效渲染帧 F 应用，保留原 origin。
新事件 cursor 从该 origin 推导当前 loop phase，并定位到 F 尚未调度的首个事件：
恰在 F 的事件执行一次，已经过去的事件等下一 loop。返回的 activation frame 是
控制侧观察到的最早请求帧，并非回填的实际应用帧。显式 Pattern-stopped 状态下只更新
current view，不启用调度；后续显式 start 仍从新的 origin 开始。

旧 generation 的持续 Voice 保留其 slot、sample reference、播放 cursor、envelope
和绝对 scheduled release。旧 Pattern slot 进入 retiring，所有 Voice 结束且
publication/audio owner 已释放后才可由控制线程 reclaim；音频线程不析构 PCM。
固定四槽耗尽返回 `pattern_slots_full`，不抢占 Voice、不强制回收、不增长存储，
释放后调用者可重试。pending publication（含 switch）或 reserved transport
command/receipt 返回 `publication_pending`，不暗中重启或取代它们。

Pattern Stop 按既有 96-frame ramp 结束所有仍存活的 Pattern generation；真正的
Pattern switch 保留 origin 重启行为，并释放旧代 Pattern Voice。live Pad 与
独立 performance replay 仍保留各自 release 所有权。

组件证据覆盖独立引擎逐采样比较、非恒定 PCM 到 scheduled release、原 envelope、
overlay/canonical 边界事件、固定槽耗尽和重试、停止时替换，以及跨代 Stop/switch。
production stress 覆盖保相位 publication 与 render/reclaim/Stop 并发和显式拒绝，
render allocation guard 覆盖替换应用及旧音符结束。源码证明不代表真机听感验收。

### Cardputer 紧凑存储与只读 PCM Bank

[设计工作项 #1124](https://github.com/endaye/lmdj/issues/1124) 依据
[R1 负容量研究 #1127](https://github.com/endaye/lmdj/pull/1127)，分开实施队列与 PCM 改动。
当前 source 已实现按回执额度一次配置的控制/结果/Voice-state 存储（M1），
以及 live Pad 复用只读 PCM16（M2）。
默认桌面容量和既有 float Bank 路径保持不变，callback 不分配、不释放，原
publication ownership 与 quiescence 不变。M1/M2 是 staged source：Engine/Bank
布局变化须在后续身份分配时处理 Audio Runtime MAJOR，不代表已分配的 Product
Build，不能作为旧 ABI 的二进制替换。
设计或修复合并均不能替代同素材、同 reserve 的目标容量复测和完整 Host 验收。

`PreparedSampleBank::set_pcm_sample` 在控制侧持有 `shared_ptr<const PcmSample>`，
多个 Pad 可共享同一 PCM payload 并保留各自 playback。ESP32 窄 Runtime 使用此
只读 PCM16 路径，不生成完整 float 副本；上文桌面 per-Pad float 配额与
`set_sample/from_snapshot` 路径保留。旧 float setter 仍拒绝 occupied slot；新
PCM setter 支持 float → PCM 和 PCM → PCM 替换。校验失败完整保留旧样本、
playback、availability 与字节账本；成功替换释放整个旧 float allocation，
PCM payload 在 Bank 内按唯一 owner 对象计数，不因多个 Pad 重复收费。

发布后所有 mutable alias 都必须停止修改 PCM；const shared_ptr 本身不强制这一点。
窄 Facade 的 decoder 不向 Host 暴露 alias，能建立该条件。live Pad、preview 与
audition 通过 raw material view 使用与 Pattern 相同的 PCM16 转换函数；逐帧浮点
换算、混音和原 ramp/loop/release 语义不变，不是 fixed-point DSP 改写。
Voice 不复制 shared_ptr，旧 Bank 在最后一个 Voice 完成前保持 owner，只由
控制侧 reclamation 释放。Bank C++ 布局变化要求所有消费者一致重编；下一 Audio
Runtime MAJOR 及相关 identity allocation 仍留给 B1，不允许旧 ABI 二进制替换。

Runtime-only Facade 的 T3 source 使用 `PreparedPatternView::from_canonical_snapshot`：
严格拒绝重复或乱序 event key，保留全部 timing/material 验证，不建立桌面 overlay
merge 的 map workspace；既有 `from_snapshot` 和 overlay 规范化语义不变。
`consumed_controls_audio` 只允许音频消费者或 quiescent owner 读取，供 Facade 在
render 后发布精确消费序号，不是任意线程遥测，也不把消费次数当作已发声次数。
Facade 自有 OPEN/BUSY admission 屏障排空 Core render 后才调用 Engine stop/unload；
Engine 原来的 quiescence 前置条件没有弱化。该窄路径只准备 Pattern/Pad，不调用
Master FX prepare；嵌入 Engine 的固定 FX 对象仍计入固定成本。

### Voice-state 的回执有界存储

实时逐帧 release 与 mix 扫描使用音频线程独占的最高活跃槽加一作为上界；
不是活跃 Voice 数量。中间空洞保留，仍按槽号升序混音、按首个空槽准入，
128 Voice 容量不变。live 与 Pattern 启动扩展上界，完成或取消收缩尾部空槽，
静止 start/stop 重置；不增加 callback 分配、锁或跨线程共享状态。
这项 source 优化及其 Engine 布局变化与 M1/M2 一同等待后续身份分配和消费者
重编；减少扫描工作不证明 Cardputer CPU 余量已通过，仍需原 R2 目标复测。

默认 Engine 构造的控制/结果/Voice-state 容量保持 `1024/4096/10240`；旧无参数
`ReceiptBoundedVoiceStates` 构造保持 `1024/4096/2176`。新增显式额度 N 构造
选择 `N/N/(2 × N + 128)`，N 必须处于 1..1024，且构造后不能调整。
仅满足回执约束的调用方可采用该 profile：每条 accepted 命令从接收直到回执
取走一直占用 pending 名额；先 acquire render 消费位置，再 drain Voice states，
最后归还名额。每条命令至多两个状态事件，加上最多 128 个既有 Voice 的结束事件，
得到 `2 × N + 128` 的上界。
Pattern/replay/audition 不进入此状态流；release tail 不重复发布结束事件。

Runtime Facade 将 `maximum_pending_commands` 作为 N；桌面/Performance 默认不变。
三个队列都使用构造时一次分配的固定 SPSC cell block，期间不切换、不截断、不缩窄字段；
资源不足可以使构造抛出异常，Facade load 将其转为 allocation_failed 并保留 empty。
回调不分配、不释放、不加锁；析构仍要求 quiescence。预算必须同时计入 Engine
对象和三个独立 cell block，每块包含一个 sentinel cell；索引和 owner wrapper 已在
Engine 对象内计入。`receipt_bounded_storage_bytes(N)` 用溢出检查计算三个 block
的总 payload，非法 N 返回空值；构造器对非法 N 抛出 invalid_argument。
allocator overhead 另属平台 reserve。选用较小模式但违反回执
约束的 Core 调用方仍会触发原有 corrupted/fail-closed，不会静默覆盖事件。

单元测试锁定旧两个组合和 N=1/128/1024 的精确容量、全宽字段与 wrap；实际分配
账本检查 Engine 加三个 cell block，而非只比较 sizeof。组件测试分别覆盖 128 个
旧 Voice 结束加 N 次短音的恰好 `128 + 2 × N` 条未读状态、队列满重试和空/部分回执。
并发测试覆盖实际
存储分支以及 render 与满额命令/部分 poll 的交错。这些源码测试不代表真机音频验收。

### Capture 缓冲按需准备

当前 source 的 Capture ring 不再嵌入 Engine；未请求录制时没有 ring allocation。
`prepare_capture()` 在串行控制线程上幂等申请原有 4096-event 容量，不改变 Capture
状态；返回 false 表示内存不足。Native 在创建 Sequence 会话前执行该预检。
现有 `arm_capture()` 仍可直接调用并隐式准备；申请失败返回 `internal_error`，
message 为空、details 为 null，避免 `noexcept` 错误路径再次分配内存。
失败不改变 running/idle 状态，播放继续，后续可重试。

存储在 release 发布 `arm_pending` 前完整初始化；音频 acquire 状态后才能写入。
指针只初始化一次，不在运行期间替换。disarm/stop 保留未读事件与已申请存储；
quiescent start 沿用清空旧队列的语义，最终由 quiescent Engine 析构释放。
回调仍然不申请或释放内存。启用录制后的完整缓冲成本未减少；冷态节省不等于
ESP32 可用堆、整机适配或实时 deadline 通过。该 additive API 与 B2 T2/T3 一同
现已在本次 integration 分配匹配的 Module/Assembly 身份。

## 8. 测试与证据

## Audition reclaim accounting

The audition pool remains separate from Project Bank storage. Reclamation counts
all retired Banks, but `decoded_pcm_bytes` refunds Project Bank reservations only;
retired audition PCM must not reduce that balance. Exact audition-only and mixed
reclamation tests protect Web snapshot reload and close after replaced previews.
Pool sizes, voice lifetime, release ramps and Project byte limits are unchanged.
