## 创作能力

Project v4 Truth、命令处理、项目存取、portable Bundle 1.1、确定性 Cook 与 Sequence recording 已实现。Project v4 在 v3 之上新增 16 个 Pattern Slot 地址、Performance 与 Asset Lineage，并成为唯一当前写入真相；v3 与 v1/v2 一起只作为迁移输入被读取，writer 永远只发出 v4。Facade 相应提供 Pattern Slot 的 assign/clear/move。Creator Web 提供 Pattern create/select、Record/Stop、overdub、Quantize/Swing/BPM/bars、next-Bar switch、owner-loss recovery，以及既有 Sample Editor、Pad Capture 与 64-Pad Runtime surface。Crop 只修改未提交 capture；多素材浏览、自动 slicing、Undo 与非破坏音频处理仍待后续 Stage。

## 演奏能力

Runtime Snapshot、样本准备、离线渲染、实时引擎、Voice 状态与 Sample preview 具有自动化覆盖。Stage 10 加入固定八级 master FX 链（filter、delay、reverb、stutter、gate、reverse、crush、cutter，取值域 0..1000、周期由 Bar 推导）、master tap 采集、Performance 录制与保存、Cooker replay projection、resample 提交与 Performance recovery，同样只有自动化覆盖。实时不变量未变：实时线程不分配、不加锁、不修改 Project、不做 journal I/O。低延迟手感、MIDI/触控输入、设备生命周期与 Perform 演奏体验需要独立物理验收；Stage 10 的物理行仍是 deferred。

## 智能能力

Capability Contract、Registry、Attempt Store 与本地成功/失败 Proof Provider 已实现。生产模型、云服务、鉴权、计费和数据政策尚未实现。

## Host 与交付能力

当前 source 是 Product Build `1.0.45.0`：Creator Web Host `4.1.0` 与 Formal Web Runtime Host `4.1.0` 已装配，交付边界仍由 `web-hosts` 六资产 Release profile 定义；Native Host、CLI 与 MCP 同为 `3.2.0`，Web Hosts 共享 Web Runtime Platform `4.1.0` 和 Application Facade `3.2.0`。Authoring Domain 升到 `3.0.0`、Project I/O 升到 `3.0.0`、Foundation 升到 `0.4.0`；Audio Runtime 升到 `3.1.0`；Project Cooker `1.1.0` 与 Provider SDK `1.1.4` 不变。Contract 侧新增 `lmdj.soundset.v1 · 1.1.0` 与 `lmdj.soundset-catalog.v1 · 1.0.0`，并把 `lmdj.project-bundle.v1` 升到 `1.2.0`，使 Bundle 能命名本 Build 唯一写出的 `lmdj.project.v4`；`lmdj.project.v4` 保持 `4.1.0`，其余 Contract、两个本地 Proof Provider `1.0.5` 与 Provider policy 身份不变。本 Build 起，Sound Set 试听可发声：Facade 解析并把关后交回已重采样的 PCM，拥有引擎的两个 Host——Web Host 与 Native Host——各自把它发布进引擎保留的双槽 audition 池并起声，并在回包上带 `played` 说明这一次是否真的起了声；两者都不读 Set Store，跨边界的只有几何信息。两侧都有自动化检查观察到试听确实发声：原生侧一条 journey 把试听渲染到结束并断言 `played: true`，Web 侧在真实浏览器里对打包后的 Creator 断言 `played: true` 并确认 Host 在预览播完后仍然站着。停止只在 Web Host 上有对应操作：`soundset.audition.stop` 是幂等的 Host 操作，Facade 不服务它。Native Host 没有停止操作，因为它的试听是 `one_shot`、后一次试听按池的替换语义取代前一次，而确定性后端在写出响应之前就已把预览渲染完毕。试听对 Project Truth 是 query —— 不建 Asset、不动 Pad、不推进 revision。Sound Set 目录浏览、检查、映射预览与安装继续在全部五个 Host 可用；Catalog 只在 Workspace 本地或由 Host 供给字节，Core 不含网络代码。Project v4、Sequence journal/receipt/recovery、performance 会话与 draft 生命周期、整数音频 transport、统一输入 admission，以及 manifest 总量与 1 MiB chunk 解耦的有界长素材摄入继续构成同一能力闭环；Creator 分发清单保持六项资产，Diagnostic Host 保持十五项且不声明 `perform_master_tap_worklet`。
Product Build `1.0.42.0` 曾装配 Stage 10 Perform 能力：它引入 `lmdj.project.v4 · 4.0.0`，把 Authoring Domain 与 Project I/O 升至 `2.0.0`、Project Cooker 升至 `1.1.0`，Audio Runtime、Application Facade、Web Runtime Platform 与五个 Host 升至 `3.0.0`，并让 Creator 分发清单新增 `perform_master_tap_worklet` 一项资产共六项。
Product Build `1.0.25.0` 曾分配 G2 evidence-durability 级联，同样不新增公开产品能力。
Product Build `1.0.24.0` 曾分配 provider-sdk 修复级联：CLI `1.0.13`、MCP `1.1.10` 与 Native Test Host `1.0.11` 已装配；Creator Web Host `1.3.1` 与 Formal Web Runtime Host `1.2.10` 已装配，并共用 Web Runtime Platform `0.3.1`；本地成功/失败 Proof Provider 也同步升至 `1.0.3`。那次分配修复的是 Attempt reservation 回收与 temp sibling 命名冲突，不新增公开产品能力。

Web Runtime Lab 保持为独立实验工具，不属于 Product Assembly，也不替代正式 Host 或物理设备验收。Product Assembly 锁定确切组件身份，版本发布不由任意 Host 决定。
