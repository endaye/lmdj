## 目的
`lmdj.capability.v2` 描述 Provider 可提供的能力、端口和版本要求。
## 多端口边界
能力输入输出以 Artifact 端口表达，Provider 不获得 Project 内部可变对象。
SDK 允许不同输出端口引用同一完整 ArtifactRef；角色不会因相同 bytes 被合并。
同端口重复和同 digest 不同 media type / byte length 仍拒绝，所有 required 端口
及逐端口 Schema 必须通过后才发布一个成功 Candidate。该行为保持既有 v2 wire shape；
输入唯一性、逻辑输出总量与实际 staging 预算不变。
## 选择与 Attempt
Registry 解析能力；Workspace/Host 做选择；Attempt Store 管理调用状态和失败。
## 证据
Provider SDK conformance 与两个本地 Proof Provider 证明成功/失败路径。已注册的 Slice 参考 Provider 另验证 PCM16 输入、切片坐标、源绑定与确定性输出；注册不授予权限或创建 Host owner。

## Slice 消费方定义

Slice 消费方的正式定义已写入 source_paths 指向的文件。集成身份展示随 K4 的
Assembly 注册更新；当前页不从活跃源码直接导入版本，避免未来快照引用可变身份。

一个 required `source_audio` 输入对应一个 required `slice_points` 输出，各最多一个。
输入遵循 [PCM16 WAV profile](./artifact-audio.mdx)，输出遵循
[Slice Points Schema](./slice-points.mdx)。输入 bytes 由 SDK 校验 custody，消费方
拥有解码与输出上下文校验；输出验证发生在成功 terminal 发布之前。

SDK owned 字节接口、Slice 参考 Provider 和 Product Assembly 注册已实现。C++ descriptor 的测试平台与聚合字节
预算不写入闭合的 Capability JSON。Host 必须显式授予消费方要求的权限；本地
运行不代表自动授权。参考资源数值是待测起点，不能当成性能或原生平台验收结果。

## Stem 消费方定义

`stem.split.v1` 从一个 `source_audio` 输入生成一个 Candidate，包含四个 required 输出
`drums`、`bass`、`vocals`、`other`，各 max_count=1。参数仅允许空对象；Capability 为
nondeterministic。四路 WAV 与输入同采样率、声道和帧数，canonical PCM16 从第一帧开始。
浮点乘 32768 后 ties-to-even，非有限数和越界拒绝，不归一化、削波或移位。

[Stem SDK Proof](../providers/local-proof-stem.mdx) 展示清单派生的 Provider 与伴随
Contract 身份。逐端口校验在终态前完成，任一路缺失或无效都失败。纯代码 Proof 重放
输入，model_identity 为 null；它只验证字节与状态边界，不证明真实模型质量、声学对齐
或隔离执行。默认 Assembly 策略不授予 Stem 执行权限。
