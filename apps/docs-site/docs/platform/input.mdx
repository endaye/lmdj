## 状态

<StatusBadge status="partial" /> Product Build `1.0.41.0` 的 Creator Web Host `2.1.1` 与 Diagnostic Web Runtime Host `2.1.1` 通过 Web Runtime Platform `2.0.1` 使用 64-Pad Pointer、Keyboard 与 Web MIDI adapter。三种输入以同一 Audio Runtime frame clock 和单调 `input_sequence` 驱动 live trigger 与 Sequence recording；双 Host 交付控制面不改变输入语义，`partial` 仅表示仍缺少完整物理输入/延迟矩阵。

## 目标事件

Pointer、Keyboard、MIDI 汇入共享 Runtime Session 的 Sample inspect→`trigger(flatSlot, velocity, source)` admission，并保留归一化来源和 release/cancel identity。Project `{bank, pad}` 只在输入边界按 `bank * 16 + pad` 展平一次；adapter 不操作 Asset、Project Truth、Provider 或音频字节。

Creator 默认键盘 mapping 使用 `KeyboardEvent.code`，按实体键盘与视觉 Pad 的共同上下顺序分配：`Q W E R T Y U I` 对应当前 Bank 的 Pad 1–8，`A S D F G H J K` 对应 Pad 9–16。Pad 上的 `kbd` 提示与 accessible name 均从同一个导出 mapping 派生，不维护第二份 Creator 键表；切换 Bank 只改变稳定的 16-Slot offset。

Creator 在用户明确授权 Web MIDI 后监听每个可用 input，在 channels 1–16 上接受 Note On `36..51` 并保留 velocity；Note On velocity `0` 与对应 Note Off 释放 Pad，范围外 note 仍忽略。共享 Platform adapter 保留可选的单 channel filter，Creator 不启用该限制，也不按设备名称分支。

## 生命周期

普通输入只在 `running` admitted；拒绝输入不重放。Gate/Loop Gate release、Loop Toggle latch 与 Voice sequence 精确关联；blur/hidden/suspend/close 先禁 admission、清 preview、stop all，再暴露状态。恢复期只有 Context 与 generation 就绪后开启的一次真实用户 probe 例外；MIDI 断开清理状态，不合成 Trigger。

## 自动化证据

Node 回归覆盖 primary Pointer、Chromium 整数化 compatibility mouse coordinate suppression、Keyboard `code`/repeat/editable focus、MIDI channels 1–16、显式授权/velocity/disconnect/privacy，以及 admission/recovery。Creator 与 Diagnostic packaged Chromium journey 分别覆盖实际 DOM Pointer Pad、mapped Keyboard、sequence-addressed Trigger、lifecycle 与 recovery 路由；它们不替代物理设备测量。

## 非能力

当前不证明 MIDI Learn、Controller Profile、移动端触控质量或完整跨设备物理延迟矩阵已经交付。

### Cardputer ADV：I1 输入与状态投影

Cardputer 首版由正式 Host 的 TCA8418 扫描器将实体键盘事件转换为固定的 `PhysicalKeyEvent`，再进入容量为 16
的输入队列；只有序列化的 Runtime Host executor 调用 Facade。A/S/D/F 对应四个
One Shot Pad，Space 播放/停止，M 静音，减号/等号调节音量，Enter 确认接收，
Esc 取消接收。按下沿去重，自动重复和越序释放不产生额外命令；队列满或丢键时
清除本地按键状态并停止，避免猜测性补发。Runtime 返回 `queue_full` 时保留原
命令在队首，下一轮重试，不消耗新的本地状态。

TCA8418 的 KEY_EVENT_A 位 7 为 1 表示按下、0 表示释放，低 7 位是键号。
扫描器按这个方向转换，不能把松手当成首次触发。寄存器 FIFO 回归覆盖真实扫描器
到输入队列、Host 与 Core 的 A/S/D/F 按下／释放／重按以及 M 命令按下沿；
它验证非零 Core PCM 和处理回执，但不模拟电气扫描时延或扬声器输出。

显示读取 Host 的有界值副本，投影 `empty/ready/running/draining/stopped`、错误、
音量/静音和四个 Pad 的已确认按下状态；只有当前运行 epoch 的 `voice_started`
回执点亮对应 Pad，释放回执及停止/卸载清除反馈。命令刚入队时不会点亮，
该指示也不表示 One Shot 尾音长度或 Pattern 的全部发声数。
显示不从屏幕线程调用 Facade。LCD 适配层提供 ST7789 初始化及分条 DMA 文字输出，
使用 4320-byte 像素缓冲区，等待完成回调后才复用；一帧使用同一个状态副本。
文字视图包含接收进度、USB 会话、内容短身份与长度、Build/Host/source 身份、
恢复动作及 Enter 清除已装载内容的提示。这里的 USB 会话不等同于物理插线状态。
当前产品入口尚未接入该适配层；硬件配置接线、完整候选 Build 和实际屏幕验收
仍待后续集成，不能仅凭组件测试宣称设备屏幕可用。
当前自动化覆盖映射、重复/越序、空状态拒绝、接收确认/取消、overflow、队列重试
和 bounded display frame。Cardputer ADV 的逐键组合、输入延迟、同时音乐负载和
真实屏幕/按键体验仍必须在固定 Product Build 上由 A1 物理验收。
