## Contract
平台存储为 Project I/O 提供文件、目录 lease、原子发布与可丢弃 Workspace Cache 能力，不解释 Project 业务语义。
## 事务模型
Project/Asset 写入先进入 token 专属临时目录，完整校验后以一个 revision 发布；commit/abort/坏 offset/启动清理只删除整个目录，故障不得留下被误认作权威 Project 的半成品。Project duplicate 复用同一 staging 根：逐个校验被引用 Artifact 后写入 revision 0 副本，重载验证通过才发布到新 Project ID；目标已存在返回 `DUPLICATE_ID`，任何失败或取消都不留下目标目录。
## Journal
Sequence journal overlay、Project Store、flush receipt、owner-loss recovery artifact、Sample staging、waveform cache 与 Bundle publication journal 的生命周期分开。Sequence event acknowledgement 以前先 durable append canonical tail；flush record 消费相同 tail，只有 Project Store manifest replacement 是 Project Truth commit point。commit point 前失败的 flush 可由后续 canonical 累积 flush 覆盖；反向 completion 也按 identity 加 canonical key/value coverage resolve 已耐久等价 retry，并从非等价 batch 与当前 pending tail 提取未提交 residual，即使 tail 后尚未产生 later flush。journal 在 writer lease 内按 `command_id` 查重：immutable original canonical payload 决定完全相同的 replay 或 append 前 collision，completion 只能改变独立 recovery residual。owner-loss effective batch 先合并 incomplete flush residual、最后合并最新 durable tail，使同-key 最新 acknowledgement 胜出并供 status/list/apply 共同计数与写入。sealed v2 缺少任一字段或 residual 不是 original 的 exact subset 时 fail closed；旧 recovery-only snapshot 保持可恢复但不猜测 original。任一顺序下，已提交 event 都不能同时成为 recovery 输入，新增 key 与同-key 新值不丢失。partial/torn、checksum、tail sequence 与 canonical-order 损坏都保留原文件，并以 path/offset/prefix/length/stable reason/repair-or-discard remedy fail closed；恢复规则由 Project I/O/Facade 统一执行。
## Writer admission
Project writer lease 排斥其他进程或 platform owner；同一 Facade 内的短期 mutation 还由 Project-scoped Sequence admission critical section 排序。普通 authoring command 在 lease 内重读 active journal 后才验证 revision 和发布；active owner 使 mutation fail closed，孤儿 journal 必须先 seal 为 `owner_lost`。因此进程内共享 lease 不是 authority shortcut，也不能让无锁 session 预检查成为提交依据。Duplicate 在整个调用中持有源与目标 lease，任一方被其他 owner 持有时以 `project_busy` 拒绝，而不是复制一个可能正在变化的源。
## Portable transfer
`lmdj.project-bundle.v1 · 1.1.0` 只传输完整 Project 内容，并声明 Project v1/v2/v3 identity；新 writer 发出 v3。managed Bundle paths use the portable ASCII segment subset `[A-Za-z0-9._/-]`；Project payload text remains UTF-8。导入在临时 staging 中完成路径、大小、顺序与 hash 验证，再通过 publication journal 原子发布；Host 不解释或直接写入 Project internals。
## Complete-read
Native `read_complete` 对已存在完整文件的 `replace_complete` 竞态重试 open/lock/short-pread/revalidation 瞬时失败，读者只看到完整旧字节或完整新字节；缺失、符号链接与非普通文件仍失败。Web/OPFS 路径未改。
## Bounded raw range read

可选 `ProjectStorageRangeReader` 使用调用方的 `span<byte>`，以无符号 64-bit offset
读取最多一个 buffer。成功返回实际字节数；到达或超过 EOF 返回零，短尾不改写其余
buffer。空 buffer 仍执行文件和路径校验。错误保留平台原有 typed mapping，失败时已复制
的字节不得作为有效数据使用。能力不持有跨调用 descriptor、缓存、writer lease 或隐式
整文件 fallback；原有 complete-read 的行为不变。

Native 复用拒绝符号链接和特殊文件的安全打开、共享锁与 identity 复核，直接 `pread`
到 buffer，读后检查稳定 metadata；检测到文件变化即拒绝，没有 range 级自动重试。
OPFS 每次解析现有路径、取得 File snapshot，只执行请求窗口的 `slice(...).arrayBuffer()`，
然后复制到 suspension 结束后的当前 Wasm heap。内部 glue 用两个 unsigned 32-bit word
传递 offset，并在转成 JavaScript Number 前检查 EOF，防止高位截断。

此接口只提供原始输入，不保证多次读取是同一文件版本，也不证明完整 Artifact 的长度、
SHA-256 或 Project ownership。后续消费者仍须在既有 owner/lease 下解析已提交引用并
完整校验，才能发布录音元数据。Native contract 与 Node 边界测试覆盖窗口、canary、
高位 offset、fresh read 和失败；独立真实 OPFS journey 通过 C++/Wasm/Asyncify 读取，
实际关闭页面并重开两次，检查固定字节和没有新增 physical writer。它们不替代设备验收。

## 证据

Project I/O 的 `scan_performance_recording` 在一个 Project writer lease 内解析 committed
owner、预期 revision 与录音 binding，再以64KiB heap buffer读取和 SHA-256 校验完整
Artifact；前后长度和 expected EOF 均检查。history guard 先于 lease 取得，既有平台
writer admission/intent 语义保留。Store 不触发 authoring recovery 或 orphan scavenge，
不为此读取无关 Asset/Performance 音频。同步 consumer 的每个 span 只在回调期间有效，
全部状态在最终 receipt 成功前都是 provisional；失败必须丢弃。结束前再次读取 committed
owner/revision/binding，以拒绝重入修改后的陈旧回执。所有出口销毁本次逻辑 lease，平台
physical close 失败仍按既有规则保留 custody/debt；扫描回执不确认物理 close。没有整文件
fallback、额外 writer 或隐式重试。

独立 Native observer 使用真实文件/锁并拒绝整文件音频读取，覆盖精确 selector、revision、
跨窗口损坏/长度变化、短读、错误/重入后释放和大于64MiB的真实稀疏 PCM WAV。实际
C++/Wasm/OPFS 旅程再验证多窗口、固定 digest/bytes、关页重开两次、stale revision
拒绝及归还 physical writer。它们证明有界原始输入完整性，不解释 WAV frames、保存完整性
或 Performance elapsed。Project Cooker 的 `WavMetadataInspector` 可消费相同临时
窗口，以固定状态验证完整 RIFF/WAVE PCM16 并解释实际 data frames，不分配 PCM。
格式错误必须与扫描最终回执分开：完整 hash 成功后才报告元数据或 unsupported
encoding；尾部摘要错误即丢弃 parser 状态。组合 OPFS 旅程覆盖192124字节、48017帧
的零事件静音和 odd JUNK，以及不支持的编码与末字节损坏，各自实际重开两次。
Facade 的 typed `PerformanceRecordingMetadataReader` 可在独立 worker 消费上述输入。
它由 Application 工厂保留精确 shared platform，使用独立只读 Store/history，避免长
hash 锁住 Control 的 live AuthoringHistory；不会捕获可变 Application 或修改 writer
admission。并发提交改变 expected revision 时，扫描仍拒绝旧 selector。

完整 raw verification 的 receipt 与 audio Result 分开，已校验但不支持的 WAV 编码
保留身份；摘要错误丢弃 provisional 格式状态。cooperative stop token 在平台调用
返回后才可生效，取消请求本身不证明 worker、lease 或 physical custody 已结束。
真实 Native 屏障/TSan 和 OPFS worker 旅程分别覆盖并发 Control、取消退役与共享
root；后者还验证 Application 已销毁、worker 真正退出后 join、root 归还和实际重开。
Runtime/SDK/Host 的异步查询、stale-owner retirement 与 Take 展示仍待，保存完整性
与演出 elapsed 也不是这些只读层的结论。

Storage platform contract、Sample cleanup retry/age gate/cache corruption rebuild、Bundle round trip/publication、fault matrix、writer-lease admission、并发 begin-vs-authoring、durable tail、torn-tail refusal、真实 `SIGKILL` restart、project store 和 journal 测试覆盖 shared native/OPFS storage boundary；硬终止 subprocess gate 在 native component 层执行。
