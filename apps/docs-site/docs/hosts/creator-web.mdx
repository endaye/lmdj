## Graphite 控件与字体

Interaction UI 的普通触摸按钮（包括 Sequence）与左栏键帽统一使用随包
加载的 IBM Plex Mono Regular 9px／13px 行高。Space Grotesk 继续随包保留
给标题角色；对象身份、读数与顶屏仍有各自的排版规则。标题为 14px，关键
参数读数为 18px。字体随样式离线提供，不依赖外部字体服务。

普通触摸按钮在至少 44 设计单位的正常布局命中框内绘制 32 单位可见面，
可见面的圆角为 6。上下留白属于按钮本身；独立背景面不会扩大命中框或盖住
相邻按钮。主要操作用浅绿底，普通操作用 raised 底，选中项用面板底与浅绿
描边／文字；破坏性操作可显式采用 rose 文字，禁用项降低透明度并保留
原生禁用语义。键盘焦点仍有独立轮廓，选中不替代焦点。
Project 内容卡、Pattern 启动槽、Pad 颜色选择、Pad、网格、推子和波形手柄
保留各自的内容或编辑尺寸；长标签允许自然增高。面板内距 16、分组间距 8。

布局先根据视口选择能保留实际命中尺寸的形态，再按舞台居中。宽屏保留
880×592 的 Figma 控制台；如果原布局会缩小到 1 以下，则采用紧凑布局：
页眉／页脚各 24px，控制台高 544px、上下外边距各 4px，宽度不超过 880px
且左右各留至少 8px。实体栏宽 92px，按钮为 44px 命中框，32px 可见面，

左侧 Pad 区宽 260px，四个 59px Pad 加三个 8px 间隔，控件不隐藏或重叠。
能以原尺寸容纳控制台的窄竖屏保留逆时针 90° 旋转；768×1024 使用该形态。
矮横屏宽度至少 648px、高度 364–599px 时，页眉／页脚各 16px，控制台占满
剩余舞台高度，不再整体缩小。System、四旋钮与两行实体键组成上方 632×88px
输入栏；SHIFT 保留双格，键盘顺序不变。下方左侧是 244×244px Pad 矩阵，
每个 Pad 为 55px；右侧上屏保留 152px 高度，触摸区在其下方单独纵向滚动。
44px 命中框与 32px 可见面分别保持实际尺寸；不隐藏操作或引入横向滚动。

实际像素与点击命中由浏览器测量，仍不代替实体触控、MIDI 或听音验收。

四个旋钮统一呈现相对编码器，移除旧绝对位置指针与刻度。禁用、焦点、

Pattern（#1515），只有输入转换尚未结束的 admission 才以 `sequence_admission_unresolved` 拒绝并保留 journal，Discard 释放它。Host 不解析 Bundle、Project、journal、quantizer 或 fingerprint，Project Truth、revision、receipt 与 Runtime Boot 直接进入一个 Project：本机没有 Project 时自动新建（与 New Project 相同的默认值）并进入 Sample；否则重开本设备上次打开的 Project。该记录只保存在 Host 本地存储（IndexedDB，打开即提交，浏览器崩溃后重启仍回到最后打开的 Project；Chromium 延迟且限频提交 localStorage，曾使崩溃前约一分钟内的记录丢失，#1726），不是 Project Truth；记录缺失、不可读或指向已不存在的 Project 时，Creator 停在 Local Projects 由用户选择，重开失败照常显示错误。Project 页常驻单列本地列表：卡片、ENC1 与普通 ↑/↓ 共用选择，普通 ←/→ 未分配，只有所选卡片内 Open 打开；SHIFT + ←/→ 保持 Undo/Redo。顶部 New Project／Import 与底部 Duplicate／Sound Sets 仍可达，Duplicate 复制已打开工程。此行为按 [2026-10-13 批准决定](https://github.com/endaye/lmdj/blob/main/docs/prd/decisions/2026-10-13-creator-interaction-ui-baseline.md)取代旧 Open local／Back to Project 浏览入口；list/create/duplicate/import/open/reopen 属于同一串行 Project action 边界，后发 action 不得与旧 action 重叠或提交过期结果。ready Session 的 diagnostics 更新只同步 Runtime 呈现，不得重新进入 Project inventory/reopen；inventory 只随 Session、Runtime phase 或明确 list retry 变化。Suspend audio 进入显式 `suspending` 屏障：Runtime 发布 `audio-suspended` 只负责输入清理，Project actions 必须等 `session.suspendAudio()` 的 safety cleanup 与 transport response 全部 settle 后才重新开放；拒绝但 Runtime 仍 running 时恢复 running surface。旧 Runtime generation 的 import 被 replacement 取消时，过期 action 不能提交 Project 结果，但它拥有的 transfer UI 必须独立回到 `idle`，避免新 Session 已 ready 而 Creator 永久显示 `importing`。persisted `pagehide` retains the shared Runtime 并进入受控恢复契约；non-persisted terminal `pagehide` performs close。新 Runtime generation 只能在旧 generation 的资源清理完成后接管，Project 会自动 reopen，但 Audio 必须保持 inactive，直到用户再次敲击 Pad 或点击录音，以同一次真实手势唤醒音频。

### 模式相关的只读顶屏

Interaction UI 上屏分为顶部对象／全局 Pattern transport、中部模式事实、底部四个 encoder 读数。四个读数来自当前真实 binding，未分配或不可读时显示 `—`；上屏没有操作控件。没有打开的 Project 时不虚构位置或内容。只读布局不会更改当前 Pad、下屏编辑目标或任何 transport intent。

- **Project** 标题绑定实际打开的 Project，选中另一张卡片不会提前换标题。没有名称投影时显示短 ID。中部是本地保存／内容、Audio、MIDI 三栏，保留 BPM、Bank、Pad／Pattern 数、实际音频 phase、设备监听百分比与权限状态。`LOCAL AUTOSAVE` 表达本地自动保存策略，不是所有独立草稿的保存回执；可观察的 Sample 更新、错误、未提交草稿以及“已保存但 audio pending”会覆盖该提示，不虚构保存时间。
- **Sample** 标题是当前 Pad 地址；波形上方显示真实类别，缺少类别但已分配时为 `SAMPLE`，空槽有 `EMPTY PAD / No audio assigned`；未获得 inspect 的已分配 Pad 显示加载／错误上下文，不当作空槽。格式、总时长和有效裁剪范围叠在完整波形下缘。切换 Pad 时不沿用上一 Pad 的 inspect。后台更新明确标出实际操作的 Pad；错误提示为 `CHECK LAST ACTION`，表示上一笔 Sample 操作，不能误认为当前 Pad 的错误。Asset ID、源格式／帧数和 revision 收进 **Pad → Sample details**，编辑控件仍保留本地参数值与必要 Pad 上下文。
- **Sequence** 停止时标题为选中 Pattern 序号，播放中绑定实际正在播放的 Pattern；排队目标在 GROOVE 标题显示，生效前不提前改当前标题。八条轨道和标题绑定同一正在播放的 Pattern；这不改变下屏编辑选择。排队目标在上屏独立显示，不覆盖播放身份；错误／publication pending 仍保留。轨道显示地址与真实类别／空态，沿用 Project 投影颜色与当前 Pad 高亮。没有素材名称字段时不臆造 KICK／SNARE 等名称。
- **Perform** 中部四栏为 `PATTERN PLAYING`、`PATTERN QUEUED`、`PATTERN POSITION` 与 Bank／Quantize；前三栏只读同一个全局 Pattern transport，保留实际 bar／beat、进度、Performance 录制 phase 与已分配槽数。Playing 只取全局 transport 的当前 Pattern，Queued 只取它的 pending switch；未分配槽的 Pattern 显示序号，不能以历史 launch 回执猜测正在播放。独立 launch cue 另行同时显示 `ACKNOWLEDGED SLOT` 和 `QUEUED SLOT`，分别来自同一个 Perform controller 的 `lastLaunchAck` 与 `pendingLaunch`；待切换不会覆盖已确认槽位。没有演奏 launch 排队时，`QUEUED SLOT` 改为命名 transport 待切换目标所在的槽；未分配到槽的目标显示 `QUEUED PATTERN NN`（[#1958](https://github.com/endaye/lmdj/issues/1958)）。Performance pending launch 不覆盖 `PATTERN QUEUED`；同屏两个目标分别标明不同来源。确认是 Runtime 回执，不是持续播放或听感验收。全局 Pattern 的 bar／beat／进度仍来自独立的 Pattern transport，长度取正在播放的 Pattern，停止时取所选 Pattern，不能把它当作 Performance 录音时钟。触摸区保留启动键及分组的就地 Queued／Playing 高亮，重复的页首 cue 和录制 authority 中的 last-launch 段落移除。

- **Sound Sets／Slice** 显示已打开 Project／保存状态与各自操作摘要。Sound Sets 的 catalog／install 状态、Slice 的实际 source／candidate 结果仍由触摸工作区拥有；上屏不把当前 Sample Pad 当作 Slice 来源，不显示示例切片数。完整来源／结果投影属于 U03b 后续接线。
- **System** 标题和中部都切换为独立 Project／Audio／MIDI 概览，不再挂出底层 Sample／Sequence／Perform 内容；全局 transport 仍更新。关闭后恢复原模式上屏和绑定，不能因此停止播放或修改工程。

所有顶屏保持只读；Sample 裁剪和触摸 Tempo／Swing 的连续草稿已同步到顶屏，取消后恢复已提交值，详见下文草稿投影说明。BPM 旋钮的读数预览仍不代表可听即时变速。加载、错误和缺失字段明确降级，完整错误与恢复动作仍在触摸区。未实现的电平表与滤波类型没有被图示代替。

## 演奏边界

Creator 使用共享 Runtime Session 进入同一 Wasm Core、OPFS 与 AudioWorklet 路径。Pointer、Keyboard 与 MIDI 使用统一输入 adapter。默认实体键盘按四排空间布局映射：`1 2 3 4` 对应当前 Bank 的 Pad 13–16，`Q W E R` 对应 Pad 9–12，`A S D F` 对应 Pad 5–8，`Z X C V` 对应 Pad 1–4；每个 Pad 从同一共享 mapping truth 派生并显示键帽提示。用户明确授权 Web MIDI 后，Creator 在 channels 1–16 上接受 Note `36..51` 并映射到当前 Bank；Platform 的可选单 channel filter 不由 Creator 启用。每个 Sample press 以串行 inspect→trigger admission 确定 Runtime-effective playback，release/cancel/stop 与 ordered Voice state 共同维护视觉和真实声音。播放头只消费已快照的 Voice render bounds 与 session-local 观察时间，不写 Project Truth、Runtime Snapshot 或音频线程；并发/retrigger 时最新开始的选中-Pad Voice 获得显示所有权。saved Project revision 与 Runtime revision 分开显示，Cook 失败只重试 prepare、不重放 mutation。恢复期间只有 Platform diagnostics 证明唯一 recovery probe window 已 armed 时才开放一个真实 Trigger；Probe 后立即重新封闭输入，直到 Runtime 报告 `running`。未完成的物理设备/延迟验收不会被 UI 可用性或 Playwright 结果替代。

C1（2026-10-11 起）把 Perform 的实时控制接到 W1 的 typed producer：八段 FX 与 HOLD 在 Core epoch 可用时改走 `applyPerformanceLiveControl`（fx_parameter/fx_release 意图按 Core receipt 的 runtime generation 配对，过期或伪造的 generation 由 Core 远端拒绝，Host 不自行编造），producer 不可用（headless 或旧 Core）时原样保留上述 legacy 手势路径。Filter 从此成为独立参数组：LP/HP/BP 类型、20 Hz–20 kHz 对数 Cutoff（滑杆为 0..1000 对数位置，端点精确）、0–100% Resonance，初值 OFF/LP/20 kHz/0% 且只从 `queryPerformanceLiveStatus` 的 Core 读回取得，绝不从旧百分比反推 Hz；读回区分 core/pending/unavailable 与 frozen。主组首推子保持 Filter 槽位与可访问名，读数改为 Hz；FILTER 按钮打开 FILTER 面板（type 三段 + Cutoff + Resonance），进入该组是纯 UI 状态、不调用任何 producer；旋钮组相应扩为 main/more/filter 三枚（主组 ENC1 Cutoff，FILTER 组 ENC1 type、ENC2 同一 Cutoff、ENC3 Resonance，ENC4 仍是 #2000 的监听）。旋钮停转与切组不 release（D04 批准语义），触摸的 pointer-up/cancel/blur 保持既有 release 语义，HOLD 下的 release 由 Core 冻结并经读回显示 frozen。录制改用 headered begin：先取 live status 的 epoch，begin 返回 Core 的 gesture mapping 后直接配对后续 move/release，不再补记 synthetic engage 起点（旧 profile 的 seed 分支原样保留）；begin 的 Core fence 与 capture started ACK 两道 ready 门之前首个 Pad 被 gated。录音中的 release 之后同样以 Core 读回显示 frozen。控制 ACK 只证明接收，界面在实际 applied 状态读回前保持 pending，旧 epoch 的回执和晚到查询不能覆盖新操作。Host 共用有界 FIFO（一个执行中、一个普通等待项），begin 期间的控制等待 Core mapping 与 capture started ACK，再按实际绑定执行；溢出在修改本地手势前明确报错，最多 64 个 Pad 保留到 matching release 完成；Stop 取消尚未送达 Core 的普通等待输入并明确拒绝，已接收手势的 release 先完成。


Pattern launch strip 呈现 16 个 Pattern Slot（Project 的可发射地址空间），槽位状态为 `idle` / `pending` / `acknowledged`：Creator 发出 `requestPerformancePatternLaunch` 后进入 pending，然后轮询 `performance.record.status`，直到该 `requestId` 出现在 authority 的 `lastLaunchAck` 才标记为已确认；空槽被确认时显式显示 silent gap。没有演奏录制时，Launch 不再整体禁用（[#1958](https://github.com/endaye/lmdj/issues/1958)）：transport 播放且未录音、未在结算时，按下槽位经全局选择路径预约 `pattern.transport.switch`（槽位照 `pendingSwitch`／`currentPatternId` 显示 Queued／Playing），停止时按下槽位直接走 `snapshot.reload` 选中；空槽两种情况都不做任何事，transport 录音（S3 之前）或结算中槽位保持禁用。Pattern 的 assign/clear/move 只在录制 `idle` 时开放。状态输出中的 open Pad 手势数、open FX 手势数、HOLD 与最后一次 acknowledged launch 全部取自 Facade authority，不做本地预测。

录制阶段机为 `idle → starting → recording → flushing → stopping → stopped → saving | discarding`。录制面板提供 Record / Flush / Stop / Performance 名称 / Save / Discard / Export Performance WAV，并在 `bindingStatus === "retry"` 时额外提供 Retry WAV bind。WAV 绑定词汇是 `unbound | binding | retry | bound`；bind 或随后的 Project truth 刷新失败会回到 `stopped` 并保留 retry，不丢弃已落盘的 WAV 前缀。master tap 以每批最多 4,800 帧喂入流式 WAV writer，背压、写入失败、tap 投递失败与 30 分钟上限都以明确原因封存，durable WAV 前缀仍可保存。

回放面板列出已保存的 Performance，可对其一发起 replay，并显示 `replay.state`、解析出的 revision 与 `neutral` 标记。回放期间可以照常编辑（网格、Pad、BPM）：编辑写入 Truth，回放仍按开始时的 revision 播放、不被打断，回放结束后选中的 Pattern 按 Truth 恢复（#1789）。内部回放内录通过选择 Internal playback 并按住空 Pad 完成：松手后将实际采集的 master 输出保存到该 Pad；中断或达到时长上限的素材由用户显式 Save 或 Discard。回放面板保留 Performance recovery 候选的 Apply recovery / Discard recovery。

Pattern transport 的 Play/Stop、Record，以及创建或打开 Project，都会先通过回放自身的 Stop 停止正在播放的 Performance，再照常执行（[#1801 决策](https://github.com/endaye/lmdj/blob/main/docs/prd/decisions/2026-10-07-performance-replay-command-handoff.md)）。transport 接手选中 Pattern 的当前 Truth，包括回放期间提交的编辑；回到原 Project 不会复活已停止的回放。用户正在听的回放会被打断；真实停止失败或超时会阻止后续操作。

Host 只渲染 Facade 返回的 authority：录制状态、pending/acknowledged launch、replay 状态与 recovery 候选都来自 Core 查询结果。演奏输入本身不改写 Project Truth；只有显式的 Save、Discard 与 WAV bind 会带 `expected_revision` 经 Facade 提交 Project mutation，Creator 随后重读 Project truth，不自行推断 revision。

## Continue in another tab

A Project has one writer at a time: the tab holding it owns an exclusive OPFS
writer lease that no other tab can take away. When another tab opens the same
Project and is refused as busy, the refusal offers **Continue here** next to
Retry. Continue here asks the holding tab, over a same-origin Creator channel,
to hand the Project over. The exchange belongs to the Creator Host. It changes
no Host operation, Facade capability, lease semantics or Contract.

The holding tab treats the request as a Project change. It applies the same
guard as opening another Project, and also requires capture and Pattern
transport to be idle. While it is playing, recording, capturing, saving or running
another Project action, it refuses, and the requesting tab explains why. When it
accepts, it closes its Runtime through the same barrier as closing the page:
pending Performance saves finish, then `host.close` commits and releases the writer.
It then shows that the Project is open in another tab, with its own Continue
here to take it back; its controls stay unavailable until then.

The requesting tab waits a bounded time for an answer and for the release, and
can cancel the wait. A holder that is gone, frozen or does not answer counts as
unanswered. After a release, an unanswered request or a release that did not
finish, the requesting tab opens the Project once in the ordinary way. If it is
still busy, the refusal returns with a note naming that outcome. The new holder
reads only committed Project Truth and starts with an empty Undo/Redo history.
The previous holder cannot undo afterwards.
Automation covers the hand-over, refusal, take-back and reopen with two pages
sharing one browser context. It is not real multi-window, frozen-tab or device
lifecycle acceptance, and no listening acceptance is claimed.

## Error messages

Creator keeps one message catalogue (`state/error_messages.ts`). It maps each
public error code to what happened, in the user's terms, and to what to do
next. Storage problems are matched by their storage condition: a full device
says how to free space, and other storage failures say that saved work stays
on this device. Audio engine stops say that the Project is saved and not
affected, and point to Retry runtime. A code Creator does not know gets the
general message, never the code itself.

The error panel, the Duplicate refusal and Sequence and transport errors use the
catalogue. The Project overview shows only that something needs attention.
Codes, storage conditions and resource tokens never appear in that text. They
are recorded in Developer diagnostics, together with Runtime boot and Host
terminal errors. Button names are unchanged.

Sample errors use the same catalogue, worded for the Pad and sound being edited,
with a next step under the message. Long-source import failures read as two
plain sentences, such as "This sound is longer than Creator can import. Shorten
it in your audio app, then import it again." They carry no resource tokens or
counts. A microphone that cannot start names what to do, for example allowing
access, connecting a microphone or closing the other app, and never names the
browser exception. Each Pad change, import, room check and recording start
that fails is recorded in Developer diagnostics with its code and details.
Recovery More options／Open Sequence／Open Perform 通过同一导航入口离开 System；拒绝恢复的 take 仍保留，导航不额外 apply 或 discard。

### Measured stereo output level

Perform's read-only upper display has separate L/R rails and dBFS readouts.
They consume the SDK's synchronous `outputMeter()` measurement: actual sample
peaks after FX, before the shared ENC4/MASTER monitor gain, excluding the separate
metronome/cue output. Capture does not need to be recording. Changing monitoring
volume changes neither the measured work level nor its captured PCM.

Nonzero values use amplitude dBFS over -60..0; digital zero reads **−∞**.
Each channel's thin peak marker holds for one second of the same AudioContext
clock, from its actual peak frame. Equal/higher peaks refresh to their measured
frame; repeated getter reads cannot extend the hold. Lower levels draw directly
from measured windows, without decorative decay or transport-derived animation.
The existing current/queued Pattern, counter, progress and launch receipt remain.

Missing/stale/failed measurements say **UNAVAILABLE**, with no numeric meter or
held marker. Session, Project, owner/rate replacement and suspension clear held
state; a replacement never borrows the old readout. Only the visible, eligible
Perform meter owns a cancel-safe animation-frame reader. It issues no command,
adds no audio/gain node, and writes no Project, history or device preference.
Browser/PCM verification is distinct from physical-device and acoustic acceptance.

Ordinary Sequence touch buttons share the common 44 px target, 32 px
painted face and 6 px face radius. Grid cells, note gestures and continuous
editors retain their own editing geometry. Choices use the existing touch
controls instead of introducing browser-native dropdowns or checkboxes.

Sixteen rows are the active Bank's sixteen Pads, so the grid follows the Bank
keys. The horizontal axis is the whole Pattern, one, two, four or eight bars,
with 1/16 as the default snap. Each note renders as a
rectangle whose position and length are its exact
`onset_tick`/`duration_tick` from Project Truth; velocity reads as shade.

One gesture is one `pattern.events.edit`, sent at gesture end through the
Runtime Session with flat Pad slots (0–63), and one undo record: a pen tap on
an empty cell adds a note (one snap step long — 1/16 with snap off — at the
last velocity the grid set, starting at 100); a tap on a note removes it;
dragging a note's body moves it and dragging its end resizes it; a vertical
drag in VEL mode sets velocity from the pointer's height in the row; and a
drag on empty space box-selects, after which the selection deletes or moves as
one batch command. A gesture that ends where it started sends nothing. Moves
and lengths snap to the selected grid, lengths clamp to the loop seam, and a
move onto an occupied key replaces that note by the key rule.

While the transport records, editing is disabled and the grid says so. While
the transport only plays, an edit of the playing Pattern commits and swaps
its Runtime view in place at once: the play position is unchanged, sounding
voices are not interrupted, and new notes after the playhead are heard in the
current loop — there is no next-bar wait. A stopped edit of the current
Pattern also swaps immediately, so a later Play is never blocked by a pending
publication; an edit of a non-current Pattern changes Project Truth only.
When every engine Pattern slot is held by a sounding retiring view the edit
still commits (`deferred`) and the Runtime swaps in place by itself once a
slot frees — it is committed Truth like any other edit, so the grid shows no
separate deferred state. A `pattern_transport_busy` or
`pattern_publication_pending` refusal happens before the commit, and Creator
retries it instead of showing a conflict, re-reading the current revision
before every attempt because the busy window can land an intervening commit.
The retry is bounded: 32 attempts 250 ms apart cover a bar boundary at the
slowest tempo (6 s at 40 BPM). A longer wait, or a revision that cannot be
re-read, shows the refusal itself ("can't be done right now"), never a
stale-revision conflict. While the projection re-reads Truth after a commit no gesture
starts; a box selection hit-tests the notes Truth holds when it is released,
so it never names a key that no longer exists. Keys that an Undo or Redo, a
transport settle or another surface's edit removes leave the selection. Any
other conflict or refusal restores the projection from Truth and shows the
reason; a committed edit whose swap fails surfaces the typed snapshot error
honestly. Undo and Redo are the existing stop-only history controls.

Grid edits, Pattern structure changes and Pad colour changes share a serialized
authoring queue. Each successful commit advances the Project revision before
refreshing its projection with that committed revision, so consecutive changes
remain visible even when the preceding refresh has not rendered yet. Project,
Pattern and refresh-token identity checks still reject stale projections.

### Perform 关闭的应用结算边界

Perform 的公开 Stop／Leave／Save 可以继续通过 UI 报告操作失败，但原实例
关闭仍须保留真实未结算的捕获、WAV 和持久化责任。缓存的 controller.close
向已注册关闭屏障传播原操作失败；SDK 的正向释放结果不能替代这些应用
结算，替代实例不得越过失败屏障。未知 begin／写入结果、停止画面或空资源
引用不证明 owner 已释放；只有真实匹配回执与实际清理才能结清对应责任。
已知无 owner 且实际清理成功的失败操作仍可正常关闭，不以任意 UI 错误
永久锁住会话。真实物理设备上的关闭与恢复尚未验收。
