## 创作边界

当前 UI 提供 browser-local Project discovery/open、New Project（经共享 Runtime Session 在本机创建空 Project：120 BPM、1 Bar 初始 Pattern，创建后列入 Local Projects 并进入 Sample）、Duplicate Project（自动保存下取代 Save As：Host 以新身份复制当前 Project 的 Project Truth 与 Asset，原 Project、它的 writer 与 Runtime 不受影响，随后 Creator 打开副本——副本 revision 为 0，并成为本设备记住的 Project；音频运行或其他 Project action 进行中时不可用；复制被拒绝（另一标签页占用、未完成录音、播放或 Sample 导入进行中）时原 Project 保持打开，拒绝原因内联显示在 Project 页；副本已存但打开失败时照常报告打开错误，并把副本列入 Local Projects）、portable Project Bundle import、64 个稳定 Pad Slot、Sample Surface 与 Sequence Surface。长素材在读内容前检查 100 MiB source ceiling，可判定的声道/时长在 decode 前拒绝，decode 后再精确验证最多 2 声道和 43,200,000 帧；取消、替换、提交成功、Project 切换和后台恢复都会释放完整源缓冲。Capture 与导入选区都使用 `sample.quota` 返回的 target-exclusive effective headroom，不再有固定单 Pad 帧数上限；冲突或配额拒绝保留源与选区。Pointer、Keyboard、MIDI 经同一 Input Controller 同时进入 live trigger 和全局 Pattern transport 的 post-enqueue admission：candidate 由 Facade 持有的 coordinator 在 acknowledged admission/cutoff 区间内 durable 保留，Record-off 按 exact fence 结算提交，播放保持；Stop 先停调度再结算。实体 Play/Stop 与 Record 键在任何 mode 下都驱动同一 transport projection 与命令身份——Play/Stop 是 Pattern 播放/停止，Record 是当前 Pattern 的 overdub，绝不表示 Sample capture 或 master recording；普通 mode 导航不再停止 transport。Creator 只提交 intent 并渲染 projection：busy、refused、committed-but-not-published 与 recoverable 均如实显示，重试是 inspect/reconcile 同一命令身份，绝不发出新的反向 toggle。播放中的 engagement 诚实拒绝跨身份 Pattern reload；停止态 reload 注销 engagement，由下一条命令按当前 Pattern 重新 vend。Capture、空 Pad 录音与 Pattern／Performance 录音互斥，Pattern 播放仍可继续。敲击 armed Pad 只停采并进入 trim overlay；裁剪/保存由 Host 独立显示，无需 Pattern recording journal。armed 期间其他 Pad 仍可演奏，但不能改写 Capture 所拥有的 Sample selection。已有 transport journal 时，Core 的 Sample 提交 busy 守卫仍保持有效；take 保留，录音结算后可重试提交。Capture 提交的失败或取消仍由 Core 在 writer lease 下判定 exact receipt/Project Truth，冲突 fail closed。Sequence recovery 只允许 fingerprint 匹配的原 Pattern、用户明确选择的有效新 Pattern或 discard；owner-lost 的 transport admission 在列出时被 reconcile 密封为 owner_lost 候选；Apply 把演奏者听到的 take（按下在 attack tail 后结束）回放进目标 Pattern（#1515），只有输入转换尚未结束的 admission 才以 `sequence_admission_unresolved` 拒绝并保留 journal，Discard 释放它。Host 不解析 Bundle、Project、journal、quantizer 或 fingerprint，Project Truth、revision、receipt 与 Runtime publication 均由 Core 决定。

Boot 直接进入一个 Project：本机没有 Project 时自动新建（与 New Project 相同的默认值）并进入 Sample；否则重开本设备上次打开的 Project。该记录只保存在 Host 本地存储（IndexedDB，打开即提交，浏览器崩溃后重启仍回到最后打开的 Project；Chromium 延迟且限频提交 localStorage，曾使崩溃前约一分钟内的记录丢失，#1726），不是 Project Truth；记录缺失、不可读或指向已不存在的 Project 时，Creator 停在 Local Projects 由用户选择，重开失败照常显示错误。Open local 在已有 Project 时仍保持可达；list/create/duplicate/import/open/reopen 属于同一串行 Project action 边界，后发 action 不得与旧 action 重叠或提交过期结果。ready Session 的 diagnostics 更新只同步 Runtime 呈现，不得重新进入 Project inventory/reopen；inventory 只随 Session、Runtime phase 或明确 list retry 变化。Suspend audio 进入显式 `suspending` 屏障：Runtime 发布 `audio-suspended` 只负责输入清理，Project actions 必须等 `session.suspendAudio()` 的 safety cleanup 与 transport response 全部 settle 后才重新开放；拒绝但 Runtime 仍 running 时恢复 running surface。旧 Runtime generation 的 import 被 replacement 取消时，过期 action 不能提交 Project 结果，但它拥有的 transfer UI 必须独立回到 `idle`，避免新 Session 已 ready 而 Creator 永久显示 `importing`。persisted `pagehide` retains the shared Runtime 并进入受控恢复契约；non-persisted terminal `pagehide` performs close。新 Runtime generation 只能在旧 generation 的资源清理完成后接管，Project 会自动 reopen，但 Audio 必须保持 inactive，直到用户再次敲击 Pad 或点击录音，以同一次真实手势唤醒音频。

状态栏显示由生成的 Product Assembly identity 派生的 build 身份（Product Build、Host、Platform 与 protocol 版本），启动时同一身份写入浏览器 console 并暴露为只读的 `window.__LMDJ_CREATOR_BUILD__`；该显示只做呈现，不替代 Runtime Session 对部署 manifest 的验证。状态栏同时显示 Project revision 与 MIDI 授权/输入数；Project Surface 显示 import 传输进度，Local Projects 列表可返回已打开的 Project；Runtime `ready` 时的 advisory 错误可被 Dismiss，`restart-required`、`unsupported`、`failed` 与 `closed` 的 Runtime 错误则保留到 Runtime 自身改变 phase。

Sample 触摸工作区只保留编辑与采集；Bank 导航和可演奏 Pad 网格统一在左侧实体栏／
Pad 区。该 Pad 区在 Sample mode 同时提供选中态、空槽选样、拖入／替换，以及原有
pointer／keyboard press、release 和 cancel。Sound Set 的 **Install target Bank**
是独立安装目标，初始取进入该工作区时的 active Bank；修改它不切换演奏 Bank，之后
切换实体 Bank 也不会悄悄改写该安装目标。

开发诊断折叠面板在各模式的触摸工作区中保留当前 Workspace 最近 100 条错误。
Sequence/transport 的恢复、丢弃、设置、切换与命令失败，以及 Project 与 Sample
preparation 的 shell 错误，都经同一 helper 追加操作名、UTC 时间、code、message
与 details；可直接读取 `sequence_admission_unresolved` 和 `journal_retained`。
切换模式不清空记录，刷新页面会清空；不写存储、不上传，也不收集请求、Project
内容或 stack。现有 alert 与恢复行为不变。此面板是开发辅助，最终用户可见性尚未决定。

## 首次音乐手势

Creator 不再提供专门的 Activate audio 门禁。可演奏 Pad 的 pointer／keyboard press、
实体 Record／Play 与 Capture Record 点击会在原生可信事件中调用共享 Runtime 的音频唤醒。
第一次 Pad 敲击等待唤醒完成后只提交一次；已松手的 one-shot 仍可演奏，提前松手的
Gate／Loop Gate、取消、后台与 Session 替换会阻止迟到的发声。拒绝唤醒恢复原状态，
下一次真实手势可重试。MIDI Note 不伪造浏览器用户手势；Enable MIDI 的明确点击可唤醒。
恢复探针仍由 Runtime 的 armed window 决定，未完成的真实 Safari／触控听感验收不由
组件测试替代。

## 演奏边界

Creator 使用共享 Runtime Session 进入同一 Wasm Core、OPFS 与 AudioWorklet 路径。Pointer、Keyboard 与 MIDI 使用统一输入 adapter。默认实体键盘按空间顺序映射：上方 `Q W E R T Y U I` 对应当前 Bank 的 Pad 1–8，下方 `A S D F G H J K` 对应 Pad 9–16；每个 Pad 从同一共享 mapping truth 派生并显示键帽提示。用户明确授权 Web MIDI 后，Creator 在 channels 1–16 上接受 Note `36..51` 并映射到当前 Bank；Platform 的可选单 channel filter 不由 Creator 启用。每个 Sample press 以串行 inspect→trigger admission 确定 Runtime-effective playback，release/cancel/stop 与 ordered Voice state 共同维护视觉和真实声音。播放头只消费已快照的 Voice render bounds 与 session-local 观察时间，不写 Project Truth、Runtime Snapshot 或音频线程；并发/retrigger 时最新开始的选中-Pad Voice 获得显示所有权。saved Project revision 与 Runtime revision 分开显示，Cook 失败只重试 prepare、不重放 mutation。恢复期间只有 Platform diagnostics 证明唯一 recovery probe window 已 armed 时才开放一个真实 Trigger；Probe 后立即重新封闭输入，直到 Runtime 报告 `running`。未完成的物理设备/延迟验收不会被 UI 可用性或 Playwright 结果替代。

Sample 控件在 Volume 之外新增 Pitch（±24 半音，0.1 半音步进，读数如 `+3.5 st`）与 Pan（`L100`–`C`–`R100`），三者共用一个 `ParameterSlider` 手势：拖动经 `sample.preview.set` 试听，松手（pointer up、方向键抬起或窗口级 pointerup）且值变化时只提交一次，Escape 或 pointercancel 取消并清除试听。Reverse 是 `aria-pressed` 开关；Loop 打开时出现 Forward / Ping-pong 分段，选 Ping-pong 会同时清除 crossfade，因为它没有可叠化的接缝。波形编辑器在 Loop 下画出循环点手柄与 crossfade 区，并提供 Loop start（秒）与 Crossfade（毫秒，仅 Forward）读数卡；读数卡聚焦即开始手势、失焦提交、Escape 取消。Reverse 时整个 trim 区间连同循环点一起镜像，循环点手柄、Loop start 读数与 crossfade 区都画在镜像位置，也就是之后各遍回卷处；未设循环点时手柄落在 End。播放头模型与内核一致：按 pitch 速率推进，forward 循环每遍从循环点之后 crossfade 帧继续，ping-pong 在两端反射，reverse 镜像源帧。Reset 恢复全部回放对齐参数的缺省值。

Stage 10 在 mode rail 上新增 Perform 入口（`project` / `sample` / `sequence` / `perform`）：它只在 Project 可演奏、audio `running` 且 capture 存储可用时启用，否则保持 disabled 并以 aria-label 说明缺少的前置条件。Perform surface 由 Pattern launch strip、FX slider bank、HOLD、Pad surface、录制面板与回放面板组成。

FX 使用固定的八段链路顺序 `filter → delay → reverb → stutter → gate → reverse → crush → cutter`，与 Audio Runtime 的 `kFxChainOrder` 同一份真相；每个 slider 是 `0..1000` 整数范围、中性起点 `500`。FX 随时可用（#1674）：滑杆按下即经 `performance.fx.gesture` 实时作用于 master bus，与演奏录音互不构成前置；录音进行中同一手势再经 `performance.record.event` 记入 journal，录音开始时已为开启状态的 FX 与 HOLD 会补记 engage/hold_on，录音停止不释放仍按住的 FX。折叠 FX / MORE 或卸载时强制释放未闭合手势。HOLD 是链路级开关，同样随时可切换。

Pattern launch strip 呈现 16 个 Pattern Slot（Project 的可发射地址空间），槽位状态为 `idle` / `pending` / `acknowledged`：Creator 发出 `requestPerformancePatternLaunch` 后进入 pending，然后轮询 `performance.record.status`，直到该 `requestId` 出现在 authority 的 `lastLaunchAck` 才标记为已确认；空槽被确认时显式显示 silent gap。Pattern 的 assign/clear/move 只在录制 `idle` 时开放。状态输出中的 open Pad 手势数、open FX 手势数、HOLD 与最后一次 acknowledged launch 全部取自 Facade authority，不做本地预测。

录制阶段机为 `idle → starting → recording → flushing → stopping → stopped → saving | discarding`。录制面板提供 Record / Flush / Stop / Performance 名称 / Save / Discard / Export Performance WAV，并在 `bindingStatus === "retry"` 时额外提供 Retry WAV bind。WAV 绑定词汇是 `unbound | binding | retry | bound`；bind 或随后的 Project truth 刷新失败会回到 `stopped` 并保留 retry，不丢弃已落盘的 WAV 前缀。master tap 以每批最多 4,800 帧喂入流式 WAV writer，背压、写入失败、tap 投递失败与 30 分钟上限都以明确原因封存，durable WAV 前缀仍可保存。

回放面板列出已保存的 Performance，可对其一发起 replay，并显示 `replay.state`、解析出的 revision 与 `neutral` 标记；同一面板提供 start frame / end frame / 目标 Pad Slot（`0..63`）的 resample commit，以及 Performance recovery 候选的 Apply recovery / Discard recovery。

Host 只渲染 Facade 返回的 authority：录制状态、pending/acknowledged launch、replay 状态与 recovery 候选都来自 Core 查询结果。演奏输入本身不改写 Project Truth；只有显式的 Save、Discard 与 WAV bind 会带 `expected_revision` 经 Facade 提交 Project mutation，Creator 随后重读 Project truth，不自行推断 revision。

## 分发与身份

`scripts/creator-web.sh package` 生成内容哈希资产和 canonical Creator distribution manifest；manifest 绑定 Product Build、Host、Platform、协议、固定 Emscripten 身份、heap 与资源上限，并显式声明兼容的诊断 Host 身份。共享 native manifest gate 只接受 Product Assembly 注入的精确 Host/contract/version 组合。该同构建 manifest ownership 协议不是公开跨版本 Contract。

`1.0.44.0` 的 Creator 同构建 distribution manifest 声明六个 expected asset：`host_main`（`assets/main.*.js`）、`runtime_script`（`assets/runtime.*.js`）、`runtime_wasm`（`assets/runtime.*.wasm`）、`host_style`（`assets/styles.*.css`）、`capture_worklet`（`assets/capture-worklet.*.js`），以及新增的 `perform_master_tap_worklet`（`assets/perform-master-tap.*.js`）；兼容的诊断 Host 身份为 `web-runtime-host 4.0.0`。`apps/creator-web/tools/package.py` 定位 Vite 产出的 master tap processor，按内容哈希为 `assets/perform-master-tap.<sha256>.js`，改写主 bundle 中唯一一处引用，并在匹配为零或多于一个时拒绝打包。共享 native manifest gate 对声明 `compatible_hosts` 的 Creator manifest 要求恰好一个 tap 资产（诊断 Host 为零个），并校验十三项资源上限——既有九项之外，本 Build 新增四项 Sound Set Set Store 上限 `maximum_soundset_manifest_bytes` 1 MiB、`maximum_soundset_blob_bytes` 65 MiB、`maximum_soundset_unique_bytes` 256 MiB 与 `maximum_soundset_staging_bytes` 512 MiB，每一项都必须是正 safe integer 并逐值比对。清单形状改变是 Creator Host 本次取 MAJOR 的依据。多余默认值、重复 role、缺失或错误的前后缀、digest 不匹配，以及无法解析到精确哈希资产的主 bundle URL 都 fail closed。更早的不可变包保持各自的精确身份，不被追溯要求携带 Stage 10 字段。私有协议版本仍为 `1`。

## Cloudflare operator workflow

The stable `scripts/cloudflare-host.sh` entry point provides signed candidate
upload, exact-version HTTP verification, promotion, recovery and explicit
reconciliation. Operations are requested by an operator; these Hosts do not
automatically deploy on main pushes. The shared runbook at
`docs/deploy/cloudflare-hosts.md` records command inputs, the common private
journal directory, credential isolation and unknown-outcome handling.

Promotion rechecks candidate and prior signed bytes. Recovery selects the exact
retained prior version, while first publication failure disables its stable
route. Reconciliation checks current live state and closes the pending local
operation without a cloud write. Local locks require one coordinated operator
host and do not lock dashboard changes. These HTTP checks do not establish
browser, audio, storage migration or manual acceptance.

## Project Undo and Redo

The global history controls are shared by Sample, Sequence and Perform. They
live on the rail as a shifted chord, not as a software toolbar: the full-width
SHIFT key above the record/play row engages the modifier, ← / → step back and
forward through the session, and each direction key's lamp lights while its
direction is available instead of showing a greyed button pair. Desktop parity
adds Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z, leaving native text undo to editable
fields. The chord explains disabled states, including unfinished recording,
import, recovery and Pattern playback. One drag commits at its existing
gesture boundary.
The rail requests Facade history; it keeps no Project snapshot or audio copy.
A failed request retains its exact identity for an explicit retry, and successful
restoration refreshes the current Project, Pattern and Sample projections.

Navigation and committed saves retain history. Closing, refreshing, reopening,
switching Project or losing ownership starts a fresh history; saved Truth remains.
New edits clear Redo, while refused, failed, cancelled and no-op operations preserve
it. Precommit CaptureBuffer crop remains outside Project Undo. Upcoming hold-record,
Pad-management and grid-editing interactions remain in their own implementation Tasks.
Automation verifies state and persistence only; no physical-device listening or
lifecycle acceptance is claimed by this change.

## 首次触屏唤醒

首次触屏启动播放音频遵循浏览器用户激活事件：音频尚未启动时，touch／pen Pad 按下保留本次输入，在同一指针的真实 pointerup 中唤醒；在 Pad 外松手也沿用原手势身份。取消、失焦或销毁不唤醒、不迟发输入。一个合法主指针仍按住时，不阻塞另一种指针（如 pen）先松手的 Pad；非主指针不准入。首个 one-shot 松手后仍只演奏一次，已松手的 gate／loop gate 不迟发；音频已经运行时，触屏仍按下即演奏。该源路径和自动化验证不替代 iPad／Safari 实机听感验收。

## Continue in another tab

A Project has one writer at a time: the tab holding it owns an exclusive OPFS
writer lease that no other tab can take away. When another tab opens the same
Project and is refused as busy, the refusal offers **Continue here** next to
Retry. Continue here asks the holding tab, over a same-origin Creator channel,
to hand the Project over. The exchange belongs to the Creator Host. It changes
no Host operation, Facade capability, lease semantics or Contract.

The holding tab treats the request as a Project change. It applies the same
guard as opening another Project, and also requires capture and Pattern
transport to be idle. While it is playing, recording, capturing, saving or running
another Project action, it refuses, and the requesting tab explains why. When it
accepts, it closes its Runtime through the same barrier as closing the page:
pending Performance saves finish, then `host.close` commits and releases the writer.
It then shows that the Project is open in another tab, with its own Continue
here to take it back; its controls stay unavailable until then.

The requesting tab waits a bounded time for an answer and for the release, and
can cancel the wait. A holder that is gone, frozen or does not answer counts as
unanswered. After a release, an unanswered request or a release that did not
finish, the requesting tab opens the Project once in the ordinary way. If it is
still busy, the refusal returns with a note naming that outcome. The new holder
reads only committed Project Truth and starts with an empty Undo/Redo history.
The previous holder cannot undo afterwards.
Automation covers the hand-over, refusal, take-back and reopen with two pages
sharing one browser context. It is not real multi-window, frozen-tab or device
lifecycle acceptance, and no listening acceptance is claimed.

## Interrupted recordings on reopen

When a Project opens in a Runtime Session and it holds recordings an earlier
owner left unfinished, Creator asks once. The trigger is boot, a library open,
a take-back, a reload or a Runtime replacement. Creator reads the Sequence and
Performance recovery lists, then shows an **Interrupted recording** region.
It names how many recordings there are and where each was made. A revision
change within the same open never asks again. A recording interrupted while
the Project stays open appears only in its existing list.

**Keep recording** is the primary action. It restores each recording to its
original destination through the existing recovery commands: Sequence apply
to the original Pattern, and Performance apply through the Perform controller.
A recording the Core refuses, such as an unresolved admission, stays in its
list. The region then names it and offers **Open Sequence** or **Open
Perform**. **Discard…** needs a second confirmation, because a discarded
recording cannot be restored. **More options** opens the list where the
recordings are, and **Decide later** closes the region. Neither changes
anything. The region is not an alert, and it takes no focus, because Enter and
Space also play Pads.

In the Sequence recovery list, restoring into another Pattern now sits behind a
**More** disclosure. Recover original Pattern and Discard stay visible.
Automation covers the prompt in component tests and in a packaged owner-loss
journey. That journey keeps the take, then reloads with the same persisted Truth
and no prompt. Real crash and device-lifecycle acceptance is not claimed.

## Error messages

Creator keeps one message catalogue (`state/error_messages.ts`). It maps each
public error code to what happened, in the user's terms, and to what to do
next. Storage problems are matched by their storage condition: a full device
says how to free space, and other storage failures say that saved work stays
on this device. Audio engine stops say that the Project is saved and not
affected, and point to Retry runtime. A code Creator does not know gets the
general message, never the code itself.

The error panel, the Duplicate refusal and Sequence and transport errors use the
catalogue. The Project overview shows only that something needs attention.
Codes, storage conditions and resource tokens never appear in that text. They
are recorded in Developer diagnostics, together with Runtime boot and Host
terminal errors. Button names are unchanged.

Sample errors use the same catalogue, worded for the Pad and sound being edited,
with a next step under the message. Long-source import failures read as two
plain sentences, such as "This sound is longer than Creator can import. Shorten
it in your audio app, then import it again." They carry no resource tokens or
counts. A microphone that cannot start names what to do, for example allowing
access, connecting a microphone or closing the other app, and never names the
browser exception. Each Pad change, import, room check and recording start
that fails is recorded in Developer diagnostics with its code and details.
Creator keeps a single set of accepted public codes, so a code accepted at one
boundary is never rejected at the next. Candidate, Sound Set, Perform and Undo
history messages move to the catalogue in the last step of #1680.
