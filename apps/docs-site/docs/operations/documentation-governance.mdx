## 单一来源
门户源码位于 `apps/docs-site`，事实来自 active manifests；独立手工 HTML 不再是正常发布源。
## 过程文档位置
设计与配套参考素材位于 `docs/design/`，实施计划位于 `docs/plans/`，跨会话交接位于 `docs/handoffs/`，完成报告与验证记录位于 `docs/quality/`。目录索引由 `docs/README.md` 维护；生成工具不决定文档归属。路径迁移更新 current 引用，已冻结版本页和来源证明保留原路径并通过其 Git revision 审计。

## 页面 Contract
每页声明 area、status、owners 与 source paths；构建拒绝缺失来源、非法状态和 current/history 边界泄漏。
## 版本更新规则
任何改变产品能力、Module/Host/Provider/Contract/Assembly/平台/发布流程的版本 Task，都必须同步对应页面和图；Product Build 或 Assembly 变化不能声明文档无影响。
## 快照规则
本地构建、普通 CI 和 PR Preview 只校验 current 页面，不创建永久快照。任何已分配并交付团队测试的 `canary`、`dev`、`beta` Product Build，以及 `stable` 发布，都必须冻结匹配的不可变快照；current main 始终标明非正式快照。
schema-2 快照把 37 页 current source、versioned sidebar、十张图的 20 个 HTML/SVG 资产和自认证 Git/source projection 元数据作为一个生成边界。版本页的卡片按 active doc ID 解析，图表按版本资产根解析；缺失、重复、越界、符号链接或哈希漂移都 fail closed。已有 schema-1 快照保持只读兼容，不回写为 schema 2。若 squash introducing tree 还包含冻结后的 mutable current/non-projection 更新，必须用 `scripts/docs-site.sh witness PRODUCT_BUILD INTRODUCING_REVISION` 生成反向差异；验证器只在临时 Git index 精确重建 raw source commit 已认证的 tree/commit 后才接受，不能重建、身份不匹配或被篡改的 witness 继续 fail closed，且不能改写不可变快照。
## 发布规则
正式入口为 [产品说明书](https://docs.lmdj.workers.dev)。页面 canonical、Open Graph
地址及 sitemap 使用该固定入口；版本 Preview 仍引用正式 canonical。此变更不修改
自有域名；旧 Netlify 入口已退役删除，冻结快照的源码和来源记录保持原样。
Git 合入 main 触发 Cloudflare 构建；先通过完整 Portal check，再验证同一 Git SHA 的版本 Preview，发布同一个 version ID 并验证生产 smoke。手工本地上传不能替代 Git 生产流程。

## CI 影响检查
Pull Request 必须声明 `Documentation impact: required` 或 `none`。需要更新时，changed files 必须包含 current 门户页；只改 Product 身份再生成文件并冻结当前 Product Build 快照的纯候选 cut 除外，因为 current 页面身份全部由 manifest 派生；无需更新时必须给出具体理由且不能制造空文档 churn。完整检查还要求当前 Product Build 的快照与 source revision、source-rebuilt Product/Assembly facts、37 页清单、sidebar、版本图表、Channel、freeze time 和 introducing commit 一致；来源关系只接受 direct-parent、byte-identical squash projection，或能精确重建已认证 source tree/commit 的显式 squash witness。

## Cloudflare PR Preview

PR Preview 使用隔离构建和独立可信发布两个 workflow。构建绑定 PR head，
不接收部署凭据；发布端从 GitHub API 核实 run、artifact 和当前 head，验证
静态归档后生成固定配置，只上传到 `portal-preview` 的版本地址，并在页面、
响应头和文件摘要检查通过后回写 `Cloudflare Portal Preview` 状态。

Preview 默认关闭。广泛激活需要三个仓库变量同时显式设置：
`CLOUDFLARE_PREVIEW_ENABLED=1`、批准的月度托管分钟预算
`CLOUDFLARE_PREVIEW_BUDGET_MINUTES`、以及接收阈值告警的运维 Issue
`CLOUDFLARE_PREVIEW_BUDGET_ISSUE`。构建触发经依赖完整的路径过滤
（权威集合见 `scripts/ci/cloudflare_preview_paths.json`，与
`cloudflare-preview-build.yml` 的 `paths:` 由测试锁定一致）：不触及门户构建
输入的 PR 不产生 Preview run，零托管成本。每次构建先执行只读的月度预算门：
当月已完成 run 的实际时长加未完成 run 的全额预留达到预算 90% 时，新构建以
why/remedy 失败关闭；每日 `Cloudflare Preview Budget` workflow 在 50/75/90%
阈值各发一条去重告警到运维 Issue。未知用量或缺失预算变量同样失败关闭。

2026-10-09 批准的持续月度额度为 2,000 GitHub-hosted Linux 分钟：依据试点
实测约 3.6 分钟/次与 2026-09 相关 PR 需求约 1,340 分钟/月（需求约占 67%）。
撤销 `CLOUDFLARE_PREVIEW_ENABLED` 可立即停用全部 Preview；调整预算属于新的
预算决策，须先记录再修改变量。外部 fork PR 始终不参与 Preview。

2026-09-08 的 60 分钟单 PR 监督试点已完成并拆除（实测三次构建共 652 秒）；
原 `CLOUDFLARE_PREVIEW_PILOT_BRANCH` 变量机制已被上述广泛激活模型取代。
稳定观察期为验收通过后的连续七天。2026-09-08 用户追加授权删除旧站点和托管
数据，替代此前旧部署保留 30 天及保留 Creator 旧 origin 的决定。私有恢复证据
仍按原期限保存，不能依赖仅保留七天的构建 artifact。删除远端站点不会清除用户
浏览器的 IndexedDB/OPFS；本次没有读取或删除浏览器本地 Project，也不声称完成
跨 origin 数据迁移。正式 Project 导出/导入仍由 #961 设计。
